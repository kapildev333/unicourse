## Method
- Orchestrator launches lanes, verifies every landing (re-run gates, then real Postgres / HTTP / browser), maintains this file.
- One directory = one owner at a time. Hot spots are single-lane: `apps/api/internal/httpx/routes.go`, `apps/api/cmd/api/main.go`, `apps/api/migrations/`, `apps/api/openapi.json`, `.github/workflows/ci.yml`.
- One integration suite at a time, orchestrator included, until runs get an ephemeral database (single local Postgres from `apps/api/docker-compose.yml`).
- Test-driven: every worker step is failing test → implementation → pass → commit, as written in the implementation plan. Reviewer re-runs gates; orchestrator re-runs them again before the PR.
- Order per lane: designer (kind D) → worker → reviewer → orchestrator verification → PR → green `ci` → squash-merge.
- Agents escalate only decisions that belong in the table above.

Notes P1-L1a: `auth.Authenticate`, `auth.NewToken`, `auth.NormalizeEmail` (rejects > 254 bytes) are the shared entry points. Go `ToLower` and Postgres `lower()` agree for every letter, so the lowercase email check cannot fire.

Notes P2-L2b: `GET …/staff` is paginated in creation order; "instructors first" applies to the staff embedded in a section. An instructor adding someone who already has a pending higher-role invitation sees that invitation in the 202 body (accepted).

## Backlog
- Spec §4 "the platform CLI uses a separate role for `universities` administration": not built; CLI uses `UNICOURSE_DATABASE_URL`. Add a dedicated role when a non-engineer runs the CLI (raised by orchestrator).
- Whoever consumes `?next=` on sign-in must accept same-origin paths only (raised by P0-L3 review).
- Per-IP magic-link limit is in memory and per process; move to Postgres when more than one API process runs (raised by P1-L1).
- Before production: split the database roles so the API role does not own the tables (an owner can disable RLS); migrations run as a separate owner role, e.g. through `unicourse-admin migrate` (raised by P0-L2 review; changes D4 - owner's call).
- Magic-link send is synchronous: an SMTP failure or the extra latency is visible only for allowed emails (timing and failure oracle). Fix together with the outbox item (raised by P1-L1a review).
- The per-IP magic-link limit keys on the connection's remote address; behind a reverse proxy every client shares one bucket. Choose the trusted forwarded header when the deployment topology is known (raised by P1-L1c review; owner's call).
- `encoding/json` matches JSON keys case-insensitively, so `{"NAME":…}` is accepted although the contract forbids extra properties (raised by P1-L2b review).
- Dependabot PRs #24 (web dev-dependencies group), #25 and #26 (react / react-dom) are open and untouched: the spec pins React 18, so a major bump is the owner's call.
- A department admin can learn from invitation 409 messages whether an email is already a member or has a pending invitation in their own university (as designed; raised by P1-L2c review).
- Before real SMTP onboarding: send invitation mail after commit through an outbox; today mail is sent inside the request transaction, which a 50k-row roster import would hold open (raised by P1-L2 and P2-L2 designs).
- A dedicated endpoint to cancel one pending staff assignment, if admins ask (raised by P2-L3 design).
- Department picker, term select and course picker read one page of 200; add search when a university exceeds that (raised by P1-L4 and P2-L3 designs).
- Enable branch protection with required checks `api`, `web` once the repo plan allows (CLAUDE.md).
