# Spec 4: Grading, scores and GPA

Status: decided by the orchestrator under D8 delegation, owner to confirm · Date: 2026-10-07 · Builds on Specs 1 and 2; visual rules from Spec 3

## 1. Intent

An instructor grades a section in UniCourse instead of a spreadsheet: assessments with weights, scores per student, a running grade, a final letter computed on the university's grade scale, and a transcript view with term and cumulative GPA for every student. The model follows the common North American practice: percentage scores, a letter scale with grade points on a 4.0 basis, course credits, GPA as the credit-weighted mean of grade points.

**Success criterion.** An instructor creates two weighted assessments on a section (a 40% midterm and a 60% final), enters scores for the roster (by hand and by CSV), publishes them, and finalizes the section: each student gets a letter and grade points from the university's scale. A student signs in and sees, per term, their sections with final letters, the term GPA and the cumulative GPA, and the published scores behind each section. A second section in the same term with a different credit weight changes the GPA as expected. An automated end-to-end test asserts it.

**References.** Default scale: the plus/minus 4.0 scale used by most US universities (A 93+ 4.0, A- 90 3.7, B+ 87 3.3, B 83 3.0, B- 80 2.7, C+ 77 2.3, C 73 2.0, C- 70 1.7, D+ 67 1.3, D 63 1.0, D- 60 0.7, F below 60 0.0). Second preset: the 4.0 scale with A+ used by Canadian universities such as the University of Toronto (A+ 90 4.0, A 85 4.0, A- 80 3.7, B+ 77 3.3, B 73 3.0, B- 70 2.7, C+ 67 2.3, C 63 2.0, C- 60 1.7, D+ 57 1.3, D 53 1.0, D- 50 0.7, F below 50 0.0). GPA = Σ(grade points × credits) / Σ credits over graded courses, as both compute it.

## 2. Out of scope

Rubrics, per-question grading, late penalties, drop-lowest rules, curves · grade appeals workflow · transcripts as PDF · transfer credit, repeats and academic standing rules · percentage-only scales (UBC style) beyond what the editable scale allows · LMS grade sync · notifications on grade release.

## 3. Domain model

All new tables are tenant-scoped with RLS, composite tenant FKs (D19), `created_at`/`updated_at` (D20).

| Entity | Fields | Rules |
|---|---|---|
| `courses` (existing) | + `credits numeric(3,1) not null default 3.0` | 0 to 20; editable on create/patch and an optional `credits` column in the courses CSV import |
| `grade_scales` | `university_id`, `letter text`, `min_percent numeric(5,2)`, `points numeric(3,2)` | one row per letter; unique `(university_id, letter)` and `(university_id, min_percent)`; a university always has at least one row; the migration seeds the US preset for every existing university and `create-university` seeds it for new ones |
| `assessments` | `university_id`, `section_id`, `name` (≤100), `max_points numeric(7,2) > 0`, `weight numeric(5,2) ≥ 0` (percent of the section grade), `due_on date` nullable, `published boolean default false`, `position integer` | unique `(section_id, name)`; a section's weights may sum to anything while drafting; finalizing requires them to sum to 100.00 |
| `scores` | `university_id`, `assessment_id`, `user_id`, `points numeric(7,2) ≥ 0`, `graded_by uuid`, `graded_at` | unique `(assessment_id, user_id)`; the user must be enrolled in the section (checked by the handler); `points` may exceed `max_points` (bonus) up to 2× |
| `final_grades` | `university_id`, `section_id`, `user_id`, `status` (`graded`, `incomplete`, `withdrawn`), `percent numeric(5,2)` nullable, `letter text` nullable, `points numeric(3,2)` nullable, `override_reason text` nullable, `finalized_by uuid`, `finalized_at` | unique `(section_id, user_id)`; `graded` rows carry percent, letter and points; `incomplete` and `withdrawn` carry none and are excluded from GPA; a snapshot: later scale edits never change it |

Derived, never stored: a student's running percent in a section = Σ(weight × points/max_points) / Σ weight over the assessments that have a score for that student (missing scores do not count until finalization, when a missing score counts as 0). Letter = the scale row with the greatest `min_percent` ≤ percent. Term GPA = Σ(points × credits)/Σ credits over `graded` final grades of that term; cumulative GPA over all terms. Percent and GPA are rounded half up to 2 decimals for storage and display; the letter is decided on the unrounded percent.

## 4. Authorization

| Who | Can |
|---|---|
| admin | read everything; edit the grade scale (`PUT`); finalize and override like an instructor |
| dept_admin (own departments) | read gradebooks and final grades; finalize and override |
| instructor of the section | create, edit, reorder, publish, delete assessments; enter scores; finalize; override a letter with a reason; reopen (delete the final grades) |
| TA of the section | enter scores and read the gradebook; nothing else |
| enrolled student | read own scores on published assessments, own running percent when every scored assessment is published, own final grades, own GPA |

Writes after finalization: scores stay editable (the snapshot does not move); reopening deletes the section's `final_grades` and is audited. Everything is audited: `assessment.create/update/delete`, `score.set` (one row per bulk request, `after` lists the user ids), `final_grade.finalize` (one row per section, `after` lists per-user letters), `final_grade.override`, `final_grade.reopen`, `grade_scale.update`.

## 5. API

Contract widenings and new routes under `/universities/{slug}`; conventions D16; lists paginate as before where noted.

| Route | Who | Notes |
|---|---|---|
| `Course.credits` on `Course`, `CourseCreate`, `CourseUpdate`; `credits` column in the courses CSV import | existing roles | optional on write, default 3.0 |
| `GET,PUT /grade-scale` | member read, admin write | `{ rows: [{ letter, minPercent, points }] }`, PUT replaces the whole scale (validation: letters unique, min percents unique, at least one row, one row at 0.00) |
| `GET,POST /sections/{id}/assessments`, `PATCH,DELETE /sections/{id}/assessments/{assessmentId}` | instructor, admin, dept_admin write; TA and students read (students see published only) | `Assessment = { id, sectionId, name, maxPoints, weight, dueOn?, published, position }`; delete cascades scores; `PATCH` may set `published` |
| `PUT /sections/{id}/assessments/{assessmentId}/scores` | instructor, TA, admin, dept_admin | body `{ scores: [{ userId, points }] }` (≤ 500 rows), upsert in one transaction; a `userId` not enrolled → `validation_failed` at `scores[i].userId`; returns the assessment's score list |
| `GET /sections/{id}/gradebook` | instructor, TA, admin, dept_admin | `{ assessments, students: [{ userId, email, displayName, scores: {assessmentId: points}, percent?, letter?, final? }], stats: { mean?, median?, letters: {A: n, …} } }`; with `Accept: text/csv` the same as CSV (one row per student, one column per assessment, percent, letter) |
| `POST /sections/{id}/assessments/{assessmentId}/scores/import/preview`, `…/import` | instructor, TA, admin, dept_admin | CSV columns `email`, `points`; preview/commit with checksum like the other imports; rows: `add`, `update` (score changes), `error` (unknown email, not enrolled, bad points) |
| `POST /sections/{id}/final-grades` | instructor, admin, dept_admin | finalizes every enrolled student: weights must sum to 100.00 (else `validation_failed` on `weights`), every assessment is marked published, missing scores count as 0; body may carry `overrides: [{ userId, status?, letter?, reason }]` applied in the same transaction; 409 `conflict` if already finalized (reopen first) |
| `GET /sections/{id}/final-grades` | instructor, TA, admin, dept_admin | list |
| `PATCH /sections/{id}/final-grades/{userId}` | instructor, admin, dept_admin | override `{ status?, letter?, reason }` (letter must exist on the scale; points follow the scale row; `reason` required) |
| `DELETE /sections/{id}/final-grades` | instructor, admin, dept_admin | reopen (deletes all final grades of the section) |
| `GET /me/grades` | member | `{ terms: [{ term, gpa?, credits, sections: [{ section, course, credits, final?: {status, letter, points, percent}, running?: {percent, letter}, assessments: [{ id, name, weight, maxPoints, dueOn?, points? }] }] }], cumulativeGpa?, cumulativeCredits }` — published assessments only; `running` only when every scored assessment is published |

Errors follow the existing envelope; `validation_failed` lists every bad field (`scores[3].points`, `rows[2].minPercent`).
