# P21-L1 design: Stay on top (Upcoming, notifications, calendar feed, campus time)

Source: roadmap `docs/specs/2026-10-09-feature-roadmap.md` §2 R1-R4 ("Spec 13 by reference", D158) with the §6 defaults Q8, Q9 and Q12. Plan: `docs/plans/2026-10-09-feature-roadmap.md` Tasks 2-6 and the review focus. The conventions of P18-L1 and P19-L1 still apply (D16 no `null`, D19 composite FKs, D20 triggers, D27/D32 logging, D30 database clock). Where this document and the code disagree on a convention, the code wins. On behaviour, this document wins.

## 0. Decisions taken here

| # | Decision | Why |
|---|---|---|
| 1 | Notifications store **no text**. A row holds `kind` plus typed source columns: `section_id`, plus `announcement_id` or `assessment_id`. Each source column has a cascading composite FK. The list joins the source to get the live title. | Deleting an announcement or assessment removes its notifications, so no stale or moderated text survives. Edits show up. The web composes the copy (no template keys in the database) |
| 2 | Four `kind` values cover the spec's three items: `announcement`, `assessment_created`, `scores_published` and `grades_finalized` | Each grade release has a different source (an assessment or a section) and a different link |
| 3 | `notifications.user_id` and `calendar_feeds.user_id` reference `memberships (university_id, user_id) on delete cascade` | Removing a member revokes their feed and clears their notifications with no extra code (review focus 3) |
| 4 | The opt-out is a column `memberships.announcement_mail boolean not null default true`, served by `GET/PATCH /universities/{slug}/me/notification-settings` in `internal/notification` | It is the smallest diff, per university as Q8 says. `/me` belongs to `auth`, which is Task 3's file and is cross-university |
| 5 | Recipients are computed only when the item is created. Lists do not re-check access later. | The count stays one indexed query. Ceiling: §10 |
| 6 | `scores_published` fires only when `published` goes false→true in `updateAssessment`, at most once per (user, assessment). A `not exists` check is enough because the assessment row is already locked `for update`. Finalizing sends one `grades_finalized` per final-grade holder. It sends no `scores_published` for the assessments it publishes. Re-finalizing after a reopen notifies again. | No spam from publish toggling, and a changed final grade is news |
| 7 | **`GET /me/upcoming` and the feed live in a new `internal/calendar`, not in `internal/grade`.** `quiz` imports `grade`, so `grade` cannot use `quiz.deadlineSQL` (it would be an import cycle). `quiz/deadline.go` gains the one-line exported alias `const DeadlineSQL = deadlineSQL`. | This reuses the D153 constant. Upcoming and the feed's deadlines share one query (§3) |
| 8 | The feed URL carries the slug: `GET /api/v1/universities/{slug}/calendar-feeds/{token}`, where the path value is `<token>.ics`. It is not wrapped by `tenant.Wrap`: slug → university (platform tx), then `pg.WithTx(university)` looks up the token hash under the normal tenant RLS | There is no by-token RLS policy and no new `app.*` setting. The logged pattern is `/api/v1/universities/{slug}/calendar-feeds/{token}` (D27) |
| 9 | Tokens are `auth.NewToken()` values (256 bits), stored as `sha256` like sessions and magic links. The URL is shown **once**, when it is created or rotated. | A database leak gives no working URL. Q9 asks for rotation, not for re-display |
| 10 | Meetings are expanded into **one VEVENT per occurrence with UTC `DTSTART…Z`**, and Postgres does the expansion: `(date + starts_at) at time zone universities.timezone`. There is no RRULE, TZID or VTIMEZONE. | RFC 5545 §3.2.19 requires a VTIMEZONE for every TZID, and building one means parsing tzdata transitions. Expanded UTC events are valid in every client and DST-correct (checked on the local Postgres: a 09:00 Europe/Berlin Monday class is 07:00Z on 2026-10-19 and 08:00Z on 2026-10-26). This **deviates from the plan's "RRULE … TZID"**: E1 |
| 11 | The feed window is campus today −30 days … +180 days, intersected with each term. Its deadlines are the Upcoming query with a 180-day horizon. | The feed size stays bounded whatever the term data holds |
| 12 | Web formatters keep their signatures. `lib/format.ts` holds a module-level campus (`setCampus`), which `routes/$slug/route.tsx` sets while it renders. | About 20 call sites keep working untouched. Ceiling: one university at a time per tab, which is already true |
| 13 | The Calendar feed dialog opens from a **My sections header action** "Calendar feed" | Its data is the user's sections; the account menu stays name and mail preference |

## 2. Notifications (Task 2): `internal/notification`

### 2.1 Producers: one `insert … select` in the producer's transaction

Exported from `notification/produce.go`, all with `(ctx context.Context, tx *sql.Tx, universityID, actorID, sectionID, sourceID string) error` (`GradesFinalized` ignores `sourceID`, pass ""). Every recipient set is `memberships m where m.status = 'active' and m.user_id <> $actor`, intersected with:

| Function | `kind`, source column | Recipients (`m.user_id in …`) | Called in | When |
|---|---|---|---|---|
| `Announcement` | `announcement`, `announcement_id` | `select user_id from enrollments where section_id = $s union select user_id from section_staff where section_id = $s` | `content/announcement.go` `createAnnouncement` | after the insert, before `outbox.Enqueue`, whatever `email` says |
| `AssessmentCreated` | `assessment_created`, `assessment_id` | `select user_id from enrollments where section_id = $s` | `grade/assessment.go` `createAssessment` | after the insert when `a.Kind` is `quiz` or `assignment` |
| `ScoresPublished` | `scores_published`, `assessment_id` | enrollments as above `and not exists (select 1 from notifications n where n.assessment_id = $src and n.kind = 'scores_published' and n.user_id = m.user_id)` | `grade/assessment.go` `updateAssessment` | after the update when `!before.Published && after.Published` |
| `GradesFinalized` | `grades_finalized`, no source | `select user_id from final_grades where section_id = $s` | `grade/final.go` `finalize` | after the `final_grades` insert (when `n > 0`) |

Shape (Announcement):
```sql
insert into notifications (university_id, user_id, kind, section_id, announcement_id)
select $1, m.user_id, 'announcement', $3, $4 from memberships m
where m.status = 'active' and m.user_id <> $2
  and m.user_id in (select user_id from enrollments where section_id = $3 union select user_id from section_staff where section_id = $3)
```
Admins and department admins who are not on the section are not recipients: "members who can read the source" means the roster and staff. Students are only ever notified about grades by publish or finalize, so an unpublished grade never reaches them (review focus 1). The functions take no lock of their own and run inside the caller's transaction, with no goroutines.

**Mail opt-out (`content/mail.go`).** In `announcementMails`, the membership predicate becomes `exists (select 1 from memberships m where m.user_id = u.id and m.status = 'active' and m.announcement_mail)`. RLS keeps it to this university. `emailed` stays `len(mails) > 0`, so it is false when every recipient has opted out.

### 2.2 Routes (`notification/handler.go`, all `tenant.Wrap`, any active member, own rows only)

Base `/api/v1/universities/{slug}`:

| Route | Body | Answer |
|---|---|---|
| `GET /me/notifications?limit&cursor` | — | 200 `List[Notification]` newest first, keyset `(created_at, id)` via `tenant.Page`, like `listAnnouncements` |
| `GET /me/notifications/unread-count` | — | 200 `{"count": 3}` from `select count(*) from notifications where user_id = $1 and read_at is null` |
| `PATCH /me/notifications/{id}` | `{"read": true}` (or `false`) | 200 `Notification`. `true` sets `read_at = coalesce(read_at, now())`, `false` sets it to null. A bad uuid, another user's row or a missing row is 404 `notification`. `read` missing gives `NoFields()` and `null` gives 400 "must not be null" |
| `PATCH /me/notifications` | `{"read": true}` | 204. `update … set read_at = now() where user_id = $1 and read_at is null`. `false` is 400 `read` "must be true" |
| `GET /me/notification-settings` | — | 200 `{"announcementMail": true}` |
| `PATCH /me/notification-settings` | `{"announcementMail": false}` | 200 same shape. `null` is 400, and an empty body gives `NoFields()`. It locks the membership row `for update` and writes audit `membership.update` with entity `membership` and before/after `{"announcementMail": …}`, but only when the value changes |

## 3. Upcoming (Task 3): `GET /universities/{slug}/me/upcoming`

`calendar/upcoming.go` holds `func work(ctx context.Context, tx *sql.Tx, userID, horizon string) ([]Upcoming, error)`, with `horizon` an interval literal parameter (`'14 days'` here, `'180 days'` for the feed):

```sql
with mine as (
  select section_id, role from section_staff where user_id = $1
  union all
  select e.section_id, 'student' from enrollments e where e.user_id = $1
    and not exists (select 1 from section_staff ss where ss.section_id = e.section_id and ss.user_id = $1))
select q.id, q.kind, q.name, s.id, s.number, c.code, c.title, mine.role, q.opens_at,
  <DUE> as due_at, q.late_until, q.time_limit_minutes, a.started_at is not null,
  case when mine.role <> 'student' then (select count(*) from enrollments e where e.section_id = s.id) end,
  case when mine.role <> 'student' then case when q.kind = 'quiz'
    then (select count(*) from attempts x join enrollments e on e.section_id = s.id and e.user_id = x.user_id where x.assessment_id = q.id and x.submitted_at is not null)
    else (select count(*) from submissions x join enrollments e on e.section_id = s.id and e.user_id = x.user_id where x.assessment_id = q.id) end end
from mine join sections s on s.id = mine.section_id join courses c on c.id = s.course_id
join assessments q on q.section_id = s.id and q.kind in ('quiz', 'assignment')
left join attempts a on a.assessment_id = q.id and a.user_id = $1 and mine.role = 'student'
where (mine.role <> 'student' or (a.submitted_at is null
       and not exists (select 1 from submissions x where x.assessment_id = q.id and x.user_id = $1)))
  and <END> > now()
  and (q.opens_at <= now() or <DUE> <= now() + $2::interval)
order by due_at, q.id
```
- `<DUE>` is `quiz.DeadlineSQL`, i.e. `least(a.started_at + make_interval(mins => q.time_limit_minutes), q.closes_at)`. It equals `closes_at` for assignments, for staff (no attempt is joined) and for a quiz that has not been started.
- `<END>` is `case when q.kind = 'assignment' and mine.role = 'student' then coalesce(q.late_until, q.closes_at) else <DUE> end`. An assignment inside its late window stays listed.
- The query is bounded by the caller's own sections. Its joins use `enrollments(user_id)`, `section_staff(user_id)`, `assessments` per section and `attempts (university_id, assessment_id, user_id)`, so there is no new index and no pagination.

```json
{ "items": [ { "assessmentId": "uuid", "kind": "quiz", "name": "Quiz 1",
  "section": { "id": "uuid", "number": "001" }, "course": { "code": "CS101", "title": "Intro to CS" },
  "myRole": "student",                 // student | instructor | ta
  "opensAt": "…Z", "dueAt": "…Z",
  "lateUntil": "…Z",                   // assignments with a late window only
  "timeLimitMinutes": 30,              // timed quizzes only
  "started": false,                    // always present; true = the caller's quiz attempt is running
  "submittedCount": 12, "enrolledCount": 30 } ] }   // both only when myRole is instructor or ta
```
The response carries no keys, scores or other students' identities (review focus 2). Admins see only sections they staff.

## 4. Calendar feed (Task 3): `internal/calendar`

### 4.1 Token routes (`calendar/token.go`, `tenant.Wrap`, any active member)

| Route | Answer |
|---|---|
| `GET /universities/{slug}/me/calendar-feed` | 200 `{"createdAt": "…Z"}`, or 404 `calendar feed` when there is none |
| `POST /universities/{slug}/me/calendar-feed` | 201 `{"url": "<BaseURL>/api/v1/universities/<slug>/calendar-feeds/<token>.ics", "createdAt": "…Z"}`. The previous row is deleted, then a new one is inserted in the same transaction, so rotation invalidates the old URL. Audit `calendar_feed.create` (entity `calendar_feed`, after `{"userId": …}`, never the token or its hash) |
| `DELETE /universities/{slug}/me/calendar-feed` | 204, or 404 when there is none. Audit `calendar_feed.delete` |

`Register(r, d tenant.Deps)` builds the URL from `d.BaseURL` (`strings.TrimRight(…, "/")`), the path slug and `auth.NewToken()`. The POST handler returns a `tenant.After` that sets `Cache-Control: no-store` and then calls `httpx.WriteJSON(w, 201, body)`, so the URL is never cached.

### 4.2 Feed route (`calendar/feed.go`, outside `tenant.Wrap`)

`r.Handle("GET", "/api/v1/universities/{slug}/calendar-feeds/{token}", d.feed)`. Every failure is `httpx.NotFound("calendar feed")`, with no distinction between cases:
1. `t, ok := strings.CutSuffix(r.PathValue("token"), ".ics")`. Fail when the suffix is missing or `t` is not 43 base64url characters that decode to 32 bytes (the same shape check as `auth.validToken`, copied in 4 lines). No query runs for a malformed token.
2. `pg.WithPlatformTx`: `select id, name, timezone from universities where slug = $1`, then `httpx.WithUniversityID(ctx, id)`.
3. `pg.WithTx(ctx, db, uni, …)` with `select f.user_id from calendar_feeds f join memberships m on m.university_id = f.university_id and m.user_id = f.user_id and m.status = 'active' where f.token_hash = $1`, where `$1` is `sha256(t)`. The same transaction then runs `work(…, '180 days')`, the meetings query below and `select now()` (DTSTAMP).
4. Write status 200 with headers `Content-Type: text/calendar; charset=utf-8`, `Cache-Control: no-store` and `Referrer-Policy: no-referrer`.

The route is not rate-limited, because the token has 256 bits. The request log shows only the pattern, since `Router.ServeHTTP` already sets it (D27).

Meetings, with `$2` = the university timezone:
```sql
with mine as (select section_id from section_staff where user_id = $1 union select section_id from enrollments where user_id = $1),
today as (select (now() at time zone $2)::date as d)
select m.id, d::date, c.code, s.number, c.title, m.location,
  (d::date + m.starts_at) at time zone $2, (d::date + m.ends_at) at time zone $2
from mine join sections s on s.id = mine.section_id join courses c on c.id = s.course_id join terms t on t.id = s.term_id
join section_meetings m on m.section_id = s.id, today,
  generate_series(greatest(t.starts_on, today.d - 30), least(t.ends_on, today.d + 180), interval '1 day') d
where extract(isodow from d) = m.weekday
order by 7, m.id
```

### 4.3 ICS text (`calendar/ics.go`, pure functions, no dependency)

```
BEGIN:VCALENDAR
VERSION:2.0
PRODID:-//UniCourse//Calendar feed//EN
CALSCALE:GREGORIAN
METHOD:PUBLISH
X-WR-CALNAME:UniCourse: <university name>
REFRESH-INTERVAL;VALUE=DURATION:PT6H
X-PUBLISHED-TTL:PT6H
BEGIN:VEVENT                                   (one per meeting occurrence)
UID:meeting-<meetingId>-<YYYYMMDD>@unicourse
DTSTAMP:<now>Z
DTSTART:20261026T080000Z
DTEND:20261026T093000Z
SUMMARY:CS101-001 Intro to CS
LOCATION:<location>                            (omitted when empty)
END:VEVENT
BEGIN:VEVENT                                   (one per work item)
UID:assessment-<assessmentId>@unicourse
DTSTAMP:<now>Z
DTSTART:<dueAt>Z
DTEND:<dueAt>Z
SUMMARY:CS101-001 Quiz closes: Quiz 1         ("Assignment due: …" for assignments)
DESCRIPTION:<BaseURL>/<slug>/sections/<sectionId>/quizzes/<id>   (…/assignments/<id>)
TRANSP:TRANSPARENT
END:VEVENT
END:VCALENDAR
```
- Times use `t.UTC().Format("20060102T150405Z")`.
- `escape(s)` turns `\` into `\\`, `;` into `\;`, `,` into `\,` and a newline into `\n`, and drops `\r`.
- `fold(line)` emits at most 75 octets per physical line. Each continuation line starts with one space (which counts in the 75). It never splits a UTF-8 sequence: back off while the byte at the cut is `0b10xxxxxx`.
- Every line ends in `\r\n`, including the last.
- A student sees only work they have not submitted (review focus 2). Staff see their sections' work, without counts.

### 6.2 Task 5: campus time, Upcoming, Calendar feed

**`lib/format.ts`**:
```ts
let campus: { timeZone?: string; locale?: string } = {}
export function setCampus(u?: { timezone: string; locale: string }) { campus = u ? { timeZone: u.timezone, locale: u.locale } : {} }
export const browserZone = () => Intl.DateTimeFormat().resolvedOptions().timeZone
export const campusZone = () => campus.timeZone ?? browserZone()
```
- `formatDate`: a `YYYY-MM-DD` value is formatted with `timeZone: 'UTC'` from `Date.UTC(y, m-1, d)`, because a calendar date has no zone. An instant is formatted in `campus.timeZone`. The locale is `campus.locale` (undefined means the browser's, as today).
- `formatDateTime`: `dateStyle: 'medium', timeStyle: 'short'` in the campus zone and locale. When `campus.timeZone` is set and differs from `browserZone()`, it appends `' ' + zoneName(iso)`. `zoneName` is the `timeZoneName` part of `new Intl.DateTimeFormat(locale, { timeZone, timeZoneName: 'short' }).formatToParts`. It cannot be one formatter: `dateStyle` together with `timeZoneName` throws, which was checked in Node. Output looks like "Oct 26, 2026, 8:00 AM UTC".
- `campusClock(d = new Date()): { date: string; weekday: number; minutes: number }` comes from `formatToParts` with `hourCycle: 'h23'` in `campusZone()`. `weekday` is ISO 1-7.
- `toZonedInput(iso)` and `fromZonedInput(v)` handle `datetime-local` in the campus zone. "From" is a guess `Date.UTC(fields)`, minus the zone offset at the guess, then corrected once with the offset at the result. A time in a DST gap moves forward, and a time in a DST fold takes the later instant. This was checked in Node for Europe/Berlin on 2026-03-29 and 2026-10-25.

## 10. Risks and ceilings

- **No pruning** (plan): growth is about recipients × events. The `(user_id, created_at desc, id desc)` index keeps the list and count fast. Add a CLI prune when the table grows.
- **Fan-out size:** one insert of about 500 rows inside the announcement or finalize transaction, which is milliseconds. That transaction also holds the outbox rows (D90).
- **Slug in the feed URL:** if slugs ever become editable (roadmap R5), existing feed URLs break. Add the slug change to R5's design.
- **Campus module state:** `setCampus` runs during render. With two universities in two tabs each tab is separate, so it is fine. A render outside `/$slug` (sign-in, invite) uses the browser zone, which shows no times today.
- **Residual browser-local clocks:** `courses/queries.ts` `todayIso` (catalog and courses default term) and the `admin/audit-log.tsx` day filter stay in browser time. They are off by at most a day near midnight. Fix them when those files are next touched.
- **Zone aliases:** `formatDateTime` names the zone when the campus and browser zone strings differ, so an alias pair (`Asia/Calcutta` and `Asia/Kolkata`) shows a redundant label.
- **Calendar clients** poll every few hours or more (Google up to 24 h). Rotation stops the old URL at once, but a client may keep showing cached events until its next fetch.
