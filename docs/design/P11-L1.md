# P11-L1 design: `unicourse-admin seed-demo`

Designer lane P11-L1, 2026-10-07. Implements Spec 7 (`docs/specs/2026-10-07-demo-seed-and-readme.md`) §3 to §6, §8, §9, §10 under D104 to D108. Worker scope: `apps/api/internal/seed/**`, `apps/api/cmd/unicourse-admin/**`, one new section in `apps/api/README.md`. No migration, no contract change, no new module, no edit to `internal/app`, `internal/blob` or any handler.

Everything below is a ruling. Where the spec's wording and the code disagree, §11 says which way this design went and why.

## 1. Shape in one paragraph

`seed.Load` turns the embedded `demo.json` into a validated `seed.Fixture` (placeholders substituted, every reference resolved, no I/O). `seed.Run` checks migrations, handles the slug (exists: `ErrExists`, or with `Reset`, delete and remove files), writes the few rows no handler can write (university, users, memberships, department admins, the pending invitation, sessions) as the owner role, then makes every other write by calling `app.NewRouter` in process with a persona's session cookie, one `httptest.NewRecorder` per request (no listener, no port). It deletes the sessions it minted on the way out, success or failure, and returns a `seed.Report` that `unicourse-admin` prints.

The three material files are copied into `internal/seed/files/` (`cp apps/web/e2e/fixtures/* apps/api/internal/seed/files/`) and embedded. The CLI must not depend on the web tree at run time and `go:embed` cannot reach outside the package directory. Duplication ceiling: the e2e copies and the seed copies can drift. That is harmless, because both are only 143 to 436 byte placeholders.

## 3. Fixture schema

One JSON object. Every object is decoded with `DisallowUnknownFields`, and a second JSON value after the first is an error. Keys are camelCase. Where a fixture object has the same shape as an API request body, the Go type is that body: the seed marshals it as is, so the API returns its own field error when a value breaks one of its rules.

### 3.1 Placeholders

Substituted on the raw bytes before the strict decode, with `strings.NewReplacer("<year+1>", Y+1, "<year>", Y, "<domain>", slug+".edu")`:

| Placeholder | Value |
|---|---|
| `<year>` | `year` argument of `Load` (`unicourse-admin` passes `time.Now().Year()`) |
| `<year+1>` | `year + 1` |
| `<domain>` | `<effective slug>.edu`. The effective slug is the `slug` argument, or `university.slug` from the fixture when that is `""` |

The fixture's slug is read with a first lenient `json.Unmarshal` into `struct{ University struct{ Slug string } }`. Then come the substitution and the strict decode, and `Fixture.University.Slug` is set to the effective slug. No other text in the file is special.

`<domain>` is a ruling beyond the spec's `<year>` rule. It follows from spec §4 (allowed domain is `<slug>.edu`): with `--slug acme`, every email becomes `@acme.edu`. Two demo universities therefore never share user rows, and every persona's email is inside the university's domain.

Request bodies that differ from the fixture shape are local struct literals in `seed.go`, tagged exactly as the OpenAPI schema (`httpx.DecodeJSON` rejects unknown and mis-cased keys):

- course: `{departmentId, code, title, credits,omitempty}`
- section: `{courseId, termId, number, meetings}` (`meetings` is `[]Meeting`, always sent, `[]` when empty)
- assessment: `{name, maxPoints, weight, published}`
- scores: `{scores: [{userId, points}]}`
- finalize: `{overrides: [{userId, status,omitempty, letter,omitempty, reason}]}` (`overrides` is always sent, `[]` when none)
- description: `{description}`
- announcement: `{title, body, email}` (`email` is always `false`)
- week: `{title, notes}`

### 3.4 Validation in `Load` (before any I/O)

`Load` returns the first problem as `fmt.Errorf("demo.json: %s: %s", path, msg)`, with paths like `courses[0].sections[1].roster[3]`. It checks only shape and references. Value rules the API owns (lengths, code patterns, time format, weights, points, dates) are not re-checked: the API's 400 `validation_failed` reports them at write time (§6).

1. Decode errors: unknown key, wrong type, trailing value. Return the `encoding/json` error prefixed with `demo.json: `.
2. `university.name`, `slug`, `timezone` and `locale` are non-empty. The format of the effective slug is checked in `unicourse-admin` (§7), where `slugRE` and `reserved` live.
3. `departments[].code` unique. `terms[].name` unique (after substitution).
4. `people[].email`: `auth.NormalizeEmail` succeeds and the result is unique. Store the normalised form back into the fixture so every later lookup uses it. `displayName` non-empty. `role` is one of `admin`, `dept_admin`, `member`. `departments` is non-empty and every code is known when `role` is `dept_admin`, and empty otherwise.
5. Exactly one person with `role: "admin"` and `invited: false`: the acting admin.
6. Every email the fixture references elsewhere (`courses[].as`, `staff[].email`, `roster[]`, `scores[].student`, `overrides[].student`, `announcements[].as`) normalises to a `people` entry. `as`, `roster`, `scores` and `overrides` must point at a person with `invited: false`. Only `staff` may name an invited person (that becomes a pending staff row, §4 step 7).
7. `courses[].departmentCode` is a known department. `courses[].code` is unique. `sections[].term` is a known term name. `(code, term, number)` is unique.
8. `roster` has no duplicates. Every `scores[].student` and `overrides[].student` is in that section's `roster`. A student appears at most once per assessment's `scores` and once per `overrides`.
9. A section with `assessments` or `finalize` has an active (not invited) `instructor` in `staff`. The first such instructor is the grading persona.
10. Every `materials[].file` exists in the embedded `files/` directory (`fs.Stat(files, "files/"+name)`), and the name has no `/`.

`Load` does not check that the persona has permission for a write. Per spec §8, a fixture that asks a persona to do what their role cannot fails with the API's 403 at write time.

## 4. `Run`: order of writes and who makes each

`Run(ctx, db, f, o)`. `db` is the owner pool (`UNICOURSE_OWNER_DATABASE_URL`, D48). The owner role is `NOBYPASSRLS` under forced row level security, so every tenant read and write goes through `pg.WithTx(uni)` and every platform one through `pg.WithPlatformTx`, exactly like `testdb` and `prune-files`. The in-process handlers get the same pool. They behave as for the API role, because the policies are the same and the owner holds every privilege.

The writer holds: the router `h := httpx.RequestIDMiddleware(httpx.Recover(app.NewRouter(app.Deps{Auth: auth.Deps{DB: db, Sessions: store}, BaseURL: o.BaseURL, Files: o.Files})))` with `store := &auth.SessionStore{DB: db}`, plus maps from email to user id, department code to id, term name to id, and email to session token.

One request helper is used for every call:

```go
// call makes one request as the persona with that email (session minted on first use) and decodes a 2xx JSON body into out (nil: ignore).
func (w *writer) call(what, as, method, path, contentType string, body io.Reader, out any) error
```

It builds `httptest.NewRequestWithContext(ctx, method, "/api/v1/universities/"+slug+path, body)`, sets `Content-Type`, adds the cookie `auth.SessionCookie`, serves `h` into `httptest.NewRecorder()` and returns `apiError` (§6) on any status ≥ 300. JSON bodies are made by a thin `post(what, as, method, path, v, out)` that marshals `v`.

Steps, in this order. "SQL" means a direct owner write; every other step goes through a handler as the named persona.

| # | Step | Made by | Writes |
|---|---|---|---|
| 0 | `pg.CheckMigrated(ctx, db)` | none | nothing. Its error (`database is missing migrations ...: run unicourse-admin migrate`) is returned as is |
| 1 | slug check and reset (§5) | SQL | maybe one delete |
| 2 | university: one `WithPlatformTx` that inserts `universities (name, slug, allowed_email_domains, timezone, locale)` with domains `{<slug>.edu}`, then `pg.SetUniversity`, then `select seed_us_grade_scale($1)`, the same three statements as `create-university`. Unique violation (`pg.MapError` gives `pg.ErrConflict`) returns `ErrExists`, for a concurrent seed | SQL | universities 1, grade_scales 12 |
| 3 | users and memberships for every person with `invited: false`. Users go in one `WithPlatformTx` with `insert into users (email, display_name) values ($1, $2) on conflict (email) do update set display_name = excluded.display_name returning id` (the upsert is needed because `--reset` deletes the university but not the platform-wide user rows). Memberships go in one `WithTx(uni)` with `insert into memberships (university_id, user_id, role, status) values ($1, $2, $3, 'active')` | SQL | users 13, memberships 13 |
| 4 | departments: `POST /departments` per entry, in order; record code to id | admin | departments 4 |
| 5 | terms: `POST /terms` per entry; record name to id | admin | terms 2 |
| 6 | one `WithTx(uni)`: `insert into department_admins (university_id, department_id, user_id)` for every `dept_admin` code; then, for each invited person, `tenant.CreateInvitation(ctx, tx, tenant.NewInvitation{UniversityID: uni, ActorUserID: adminID, Email, Role: authz.Role(p.Role), DepartmentIDs: ids of p.Departments}, noMail, o.BaseURL)` with `noMail := func(context.Context, *sql.Tx, ...outbox.Mail) error { return nil }` (the `create-university` pattern, D28: no outbox row), followed by `update invitations set display_name = $2 where id = $1` | SQL | department_admins 1, invitations 1, its `invitation.create` audit row by the admin |
| 7 | for each course, in order (actor `A` = `course.as` or the admin): `POST /courses`; then for each section: `POST /sections` with meetings; `POST /sections/{id}/staff` per staff entry in order (an invited email returns 202 and leaves a `pending_section_staff` row; nothing is mailed because the invitation exists); roster: build the CSV `email,displayName\n` plus one `email,displayName` line per roster email (fields quoted with `encoding/csv`), multipart part `file` (filename `roster.csv`, type `text/csv`) to `.../enrollments/import/preview`, read `checksum`, then the same bytes plus part `checksum` to `.../enrollments/import` | `A` | courses, sections, section_meetings, section_staff, pending_section_staff, enrollments and their audit rows |
| 8 | same section, grading (actor `I` = the section's first active instructor): per assessment, `POST /assessments`, then `PUT /assessments/{aid}/scores` when it has scores; then `POST /final-grades` when `finalize` is present | `I` | assessments, scores, final_grades |
| 9 | same section, content (actor `C` = `I` if the section has an active instructor, else `A`): `PUT /description` when non-empty; announcements in order as `announcement.as` or `C`, with `email: false`; weeks in order (`POST /weeks`, record id), each followed by its materials in order (multipart upload) | `C` (announcement `as` overrides) | sections.description, announcements, weeks, materials and blobs |

## 5. `--reset`, duplicate slug, failure

Slug step (step 1), in one `WithPlatformTx`: `select id from universities where slug = $1`.

- Not found: continue. `Reset` on a missing slug is not an error.
- Found and `!o.Reset`: return `ErrExists`. Nothing is written.
- Found and `o.Reset`: `delete from universities where id = $1` in that same transaction, which commits before anything else. The delete cascades to every tenant table; the composite `on delete restrict` keys do not block it, because the whole tree goes in one statement (probed on the real schema in a rolled-back transaction). Users, their sessions and magic links are platform rows and stay. After the commit, remove the old university's files with the blob API only (`internal/blob` is the only code that touches the directory):

```go
var ids []string
_ = o.Files.Walk(func(u, id string, _ time.Time) error { if u == old { ids = append(ids, id) }; return nil })
for _, id := range ids { if err := o.Files.Remove(old, id); err != nil { /* collect */ } }
```

  A Walk or Remove error does not abort: the row is gone, so the files are orphans that `prune-files --delete` removes later. `Run` records the problem in `Report.Warnings`, and `unicourse-admin` prints each one to stderr as `seed-demo: warning: <text>`. Ceiling: the empty `<files>/<old id>/` directory and its `.tmp/` stay behind. A `blob.Dir.RemoveUniversity` would close that gap (§12).

The id deleted is the one read by slug in the same transaction, so `--reset` cannot touch another university's row or files.

Failure after step 2: `Run` stops at the first failing step and returns `fmt.Errorf("%w; %s is partly seeded, rerun with --reset", err, slug)`. What is left: the university and every write before the failing one, including uploaded files. The sessions are always revoked (deferred). Nothing is mailed: no step enqueues, because the announcements send `email: false`, the invitation uses `noMail`, and the roster import only adds active members. A failure before step 2 (migrations, `ErrExists`) leaves nothing behind and carries no hint.

## 6. Error text

`apiError` is the error from `call` for a non-2xx answer:

```go
type apiError struct { What, As string; Status int; Body []byte }
// Error(): "<what> as <as>: HTTP <status> <code>: <message>[ (<field>: <message>; <field>: <message>)]"
```

`Error()` parses `Body` as the error envelope (`{"error":{"code","message","details":[{"field","message"}]}}`). If the body is not an envelope, it is printed raw instead (trimmed to 500 bytes). `what` names the write in fixture terms:

| Call | `what` |
|---|---|
| department | `department CS` |
| term | `term "Academic Year 2026"` |
| course | `course CS101` |
| section | `section CS101 001` |
| staff | `staff elena.marsh@northfield.edu on CS101 001` |
| roster preview / commit | `roster preview of CS101 001` / `roster import of CS101 001` |
| assessment | `assessment "Midterm Exam" of CS101 001` |
| scores | `scores of "Midterm Exam" in CS101 001` |
| finalize | `final grades of CS101 001` |
| description | `description of CS101 001` |
| announcement | `announcement "Welcome to CS101" in CS101 001` |
| week | `week "Week 1: Welcome and setup" in CS101 001` |
| material | `material syllabus.pdf in CS101 001` |

Example of the final stderr line:

```
seed-demo: assessment "Midterm Exam" of CS101 001 as elena.marsh@northfield.edu: HTTP 400 validation_failed: 1 field is invalid (weight: must be ...); northfield is partly seeded, rerun with --reset
```

Direct SQL errors are wrapped as `fmt.Errorf("<step>: %w", err)` with `<step>` one of `university`, `users`, `memberships`, `department admins`, `invitation ingrid.larsen@...`, `sessions`.

## 7. Package API and the CLI

```go
package seed

var Demo []byte                 // embedded demo.json
var ErrExists = errors.New("university already exists")

// Load substitutes the placeholders (slug "" = the fixture's slug; year is <year>) and validates (§3.4).
func Load(raw []byte, slug string, year int) (Fixture, error)

type Options struct {
	Reset   bool
	BaseURL string   // UNICOURSE_BASE_URL, required: the router's invitation URLs (in mail that is never queued)
	Files   blob.Dir // UNICOURSE_FILES_DIR, from blob.New
}

// Run seeds f into db (the owner pool). ErrExists when the slug exists and !o.Reset.
func Run(ctx context.Context, db *sql.DB, f Fixture, o Options) (Report, error)

type Report struct {
	UniversityID, Name, Slug string
	Personas                 []Persona // one per people entry, fixture order
	Warnings                 []string  // §5 file removal problems
}
type Persona struct{ Role, Name, Email, Sees string }
```

The plan sketched `Run(ctx, db, files, baseURL, Fixture, Options)`. The design folds `files` and `baseURL` into `Options`; nothing else changes.

### 7.1 Persona lines (derived in `Run`, never stored in the fixture, so they cannot drift)

`Role`, first match wins: `invited` → `invited`; `admin` → `admin`; `dept_admin` → `department admin`; an `instructor` staff entry anywhere → `instructor`; a `ta` staff entry → `TA`; a roster entry → `student`; otherwise `member`.

`Sees` is the parts below in this order, joined with `"; "`. A section label is the course code only. Ceiling: two sections of one course in the same list read the same; add the number when a persona gets one.

- admin: `admin of <university name>`
- dept_admin: `department admin of <codes joined ", ">`
- instructor rows: `instructor of <labels joined ", ">`
- ta rows: `TA on <labels>`
- roster entries: `student in <labels>`
- invited: `invitation pending, never signed in` first. Its staff rows then read `TA on CS210 at first sign-in` (pattern: `<role word> on|of <labels> at first sign-in`, using `instructor of` or `TA on`).
- nothing else applies: `member, no sections`

### 7.2 `unicourse-admin seed-demo`

Usage gains one line under `commands:` and the environment line names the command:

```
  seed-demo [--slug s] [--reset]  load the demo university (see seed-demo -h)
```

`seedDemo(ctx, args, env, open, stdout, stderr) int`, in this order. Every exit-2 path returns before `open()`.

1. `flag.NewFlagSet("seed-demo", ContinueOnError)` with `--slug` (string, default `""`) and `--reset` (bool), and `fs.Usage` printing `seedHelp`. A parse error exits 2. A stray argument exits 2 with `seed-demo: unexpected argument %q`.
2. `f, err := seed.Load(seed.Demo, *slug, time.Now().Year())`. An error exits 2 with `seed-demo: <err>`.
3. `f.University.Slug` must match `slugRE` and not be in `reserved`, with the same messages as `create-university` but the prefix `seed-demo: --slug ...`. Otherwise exit 2.
4. `UNICOURSE_BASE_URL` (trim the trailing `/`): empty exits 2 with `seed-demo: UNICOURSE_BASE_URL is not set`.
5. `UNICOURSE_FILES_DIR`: empty exits 2 with `seed-demo: UNICOURSE_FILES_DIR is not set`. A `blob.New` error exits 1 with `seed-demo: <err>` (the `prune-files` precedent).
6. `open()`: an error exits 1 with `database: <err>`.
7. `seed.Run`. `errors.Is(err, seed.ErrExists)` exits 2 with `seed-demo: university <slug> already exists; rerun with --reset to replace it`. Any other error exits 1 with `seed-demo: <err>`. Warnings go to stderr. Success exits 0 and prints the report.

`UNICOURSE_WEB_ORIGIN` (optional, existing variable) chooses the URL printed for the sign-in page, the same rule the API uses for browser redirects (`WebBase`): the origin if set, else the base URL.

## 10. Simplifications and their ceilings

- No transaction around the whole seed (handlers commit their own). Ceiling: a failure leaves a partial university; the message says to rerun with `--reset`.
- Section labels are course codes only (§7.1).
- `--reset` leaves the empty old files directory (§5).
- The pending invitation expires after 14 days (§7.3).
- Users are upserted by email: `seed-demo` overwrites the display name of an existing user with a demo email. That only matters on a shared database, and the seed is for local ones.
- `time.Now().Year()` in the server's local time: in the first hours of January 1 the "current" term can be a year off until the next `--reset`.

## 11. Rulings on spec wording

- Spec §5 says the students "enter through the roster import so `pending_enrollments` and the roster paths are exercised". If students entered as unknown emails, the import would create invitations and queue one mail each (`tenant.CreateInvitations` enqueues). That breaks §4 ("no mail is queued"), and students without a user row cannot be scored. **Ruling:** students are users with active memberships (step 3) and enter through the import's add path, so `enrollment.create` audit rows and the import code run. `pending_enrollments` stays 0. The pending path that is exercised is `pending_section_staff`: Ingrid is invited (no mail), then added as TA on CS210 by Owen, so she becomes TA on CS210 at her first sign-in. Escalated as E1.
- Spec §5 says the grade scale is "written through `PUT /grade-scale` only when the new university has no rows". **Ruling:** the university is created exactly as `create-university` creates one, including `seed_us_grade_scale`, so it always has the US scale and the condition never fires. The fixture carries no scale. Ceiling: a custom scale needs a `gradeScale` key and a `PUT /grade-scale` step (add with `--fixture`).
- Spec §5 lists the "two weekly meetings ... of the capture seed" and one announcement and week for "the other sections". **Ruling:** CS101 002 (Spring) gets a description, one announcement and one week too, written by Owen (it has no instructor). It has no meetings, staff or roster.
- `<domain>` placeholder (§3.1): an addition required by `--slug` (spec §4).

## 12. Escalations (owner's call; the design proceeds with the default)

- **E1, pending enrollment.** Spec §5 wants `pending_enrollments` exercised. The default (above) keeps it at 0 and exercises pending staff instead. Alternative: add Ingrid to the BIO150 roster too, which needs no mail because her invitation already exists, and gives one pending enrollment. Recommended: keep the default; Ingrid is a staff hire in the capture seed's story.
- **E2, files directory leftovers on `--reset`.** The default uses the blob API only and leaves an empty `<files>/<old id>/`. Alternative: a one-method `blob.Dir.RemoveUniversity(id)` (`os.RemoveAll` after the uuid check), which is outside this lane's scope. Recommended: backlog it with the trigger "someone resets often enough to notice".
- **E3, the URL printed for sign-in.** The report uses `UNICOURSE_WEB_ORIGIN` when set (Vite on 5173 in development), else `UNICOURSE_BASE_URL`. No new variable. P11-L2's quick-start block should export `UNICOURSE_WEB_ORIGIN=http://localhost:5173` so the printed URL is the one the reader opens.
