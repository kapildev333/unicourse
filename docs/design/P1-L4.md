# P1-L4 design: web `auth` and `admin` features, and the shared web layer

Builds against: contract `docs/design/P0-L4.md` (§3 shapes win over the plan), auth `docs/design/P1-L1.md` §2/§6/§8, orchestrator ruling D11 (magic-link GET renders an API page; the web has no route for it), web skeleton on `main` (`a95026c`).
Hard limits: no new dependencies; no hand-written `fetch` outside `src/api/`; never `window.confirm()`; `next` accepted only as a same-origin path.

## 0. Deviations from plan Task 8 (deliberate)

1. `/` redirect lives in a new `src/routes/index.tsx`, not in `__root.tsx` (root stays the provider + skip link + 401 listener; an index route is how TanStack expresses "the `/` page").
2. New layout route `src/routes/$slug/route.tsx` (the app shell). It owns "is the user a member of this slug", so `useUniversity()` can return a non-optional membership instead of throwing redirects from a component (TanStack throws `redirect` only from `beforeLoad`/loaders).
3. Feature pages take `slug` (and `role` where needed) as **props**; route files read params and pass them. Pages therefore render in tests without a router (only a `QueryClientProvider`).
4. `useFieldErrors(error, copy?)` takes an optional client copy map keyed `<code>:<field>` (brief: UI copy keyed on code + field, never on server text). `FormErrors({ error, copy? })` likewise.
5. Extra files beyond the plan list: `src/features/auth/safe-next.ts`, `src/features/admin/department-picker.tsx`, shared components in §1.3, `src/test-utils.tsx`, `src/lib/use-cursor-list.ts`, `src/lib/format.ts`. Each is used by at least two screens or by Task 11.
6. dept_admin gets an Admin area with the Invitations tab only (spec §5: dept_admin may invite `member`s; there is no other place to do it).

Tailwind 4 turns each `--color-*` into utilities (`bg-canvas`, `text-ink-muted`, `border-line`, `outline-focus`, ...). Workers use only these colour names plus `white`; no `blue-700`, `gray-*`, `red-*` anywhere.
Ceiling: light theme only; dark mode = a second token block under `@media (prefers-color-scheme: dark)` later, no component changes (that is why components use roles, not hues).

**Type scale** (Tailwind defaults, used only as listed): page title `text-xl font-semibold tracking-tight text-ink`; section/dialog title `text-base font-semibold text-ink`; body and tables `text-sm`; meta/help/labels-in-tables `text-xs text-ink-muted`; product wordmark `text-sm font-semibold tracking-tight`.
**Spacing rhythm**: multiples of 4px; page padding `px-8 py-6`; between header and content `mb-6`; between form fields `gap-4` (FormField has no margin of its own, the form is `flex flex-col gap-4`); dialog padding `p-6`; dialog action row `mt-6 flex justify-end gap-2`.
**Radius**: controls `rounded-md` (6px); surfaces (table wrapper, dialog, banners) `rounded-lg` (8px); badges `rounded-full`.
**Density**: rows `py-3` (≈44px with text-sm), comfortable for staff scanning long lists; row actions are `size="sm"` ghost buttons.
**Max width**: content column `max-w-6xl`; sign-in card `max-w-sm`.
**Focus**: every interactive element `focus-visible:outline-2 focus-visible:outline-offset-2 focus-visible:outline-focus` (inputs use `outline-offset-1`). Never `outline-none` without this replacement.

### 1.2 Existing components — new recipes

**`Button`** (`src/components/button.tsx`): add props `variant?: 'primary' | 'secondary' | 'danger' | 'ghost'` (default `primary`), `size?: 'md' | 'sm'` (default `md`); keep `type='button'` default and `className` passthrough.
- base: `inline-flex items-center justify-center gap-2 rounded-md font-medium whitespace-nowrap transition-colors focus-visible:outline-2 focus-visible:outline-offset-2 focus-visible:outline-focus disabled:cursor-not-allowed disabled:opacity-60`
- md: `h-9 px-4 text-sm` · sm: `h-8 px-3 text-sm`
- primary: `bg-accent text-white hover:bg-accent-hover`
- secondary: `border border-line-strong bg-surface text-ink hover:bg-canvas`
- danger: `bg-danger text-white hover:bg-danger-hover`
- ghost: `text-accent hover:bg-accent-soft` (row actions: "Edit", "Change role", "Revoke"; destructive ghost uses `className="text-danger hover:bg-danger-soft"`)
- Busy state: callers pass `disabled` and change the label ("Saving…", "Deleting…"); no spinner.

**`Table`** (`src/components/table.tsx`): keep `caption` (sr-only). Render `<div className="overflow-x-auto rounded-lg border border-line bg-surface"><table className={`ui-table ${className}`} …>`. Callers write plain `<thead><tr><th scope="col">`, `<td>`, and put row actions in `<td className="actions">`.

**`Dialog`** (`src/components/dialog.tsx`): keep API `{ open, onClose, title, children }`, add optional `description?: string` (rendered under the title as `text-sm text-ink-muted`, wired with `aria-describedby`). Classes: dialog `w-full max-w-md rounded-lg border border-line bg-surface p-6 text-ink shadow-xl backdrop:bg-ink/40`; title `text-base font-semibold`; content `mt-4`. Children end with the action row `<div className="mt-6 flex justify-end gap-2">` holding **Cancel (secondary, first in DOM)** then the confirm button. Escape closes (native). Opening focuses the first focusable element (native): for forms that is the first input, for delete confirmations it is Cancel (safe default). On close the browser returns focus to the opener.

**`FormField`** (`src/components/form-field.tsx`): keep API, add optional `hint?: string` (rendered `text-xs text-ink-muted` with its own id, merged into `aria-describedby` before the error id). Layout `flex flex-col gap-1.5`, no outer margin. Label `text-sm font-medium text-ink`. Error `<p id role="alert" className="text-sm text-danger">` prefixed with the visually hidden text `Error: ` (`<span className="sr-only">Error: </span>`), so colour is not the only signal and the red border is redundant. Export `export const inputClass = 'h-9 w-full rounded-md border border-line-strong bg-surface px-3 text-sm text-ink placeholder:text-ink-muted focus-visible:outline-2 focus-visible:outline-offset-1 focus-visible:outline-focus aria-[invalid=true]:border-danger'` — used verbatim on every `<input>` and `<select>`.

## 3. Screens

Common to every admin list page:
- **Loading** (`isPending`): `PageHeader` (action disabled) + `<Loading/>`.
- **Error**: `PageHeader` + `ErrorBanner` (message = `errorMessage(error)`, `onRetry={refetch}`).
- **Empty**: `PageHeader` + `EmptyState` with the page's create action repeated inside.
- **Success**: `PageHeader` + `StatusMessage` + `Table` + `LoadMore`.
- Lists use `useCursorList` (§4.2), page size 50, order as the API returns (created asc; audit newest first).
- Create and edit share one dialog component per page with `mode`. Dialog forms: `<form noValidate onSubmit className="flex flex-col gap-4">` (noValidate: the server is the validator; the client only trims). Submit disabled while pending ("Saving…"). On success: close dialog, `setNotice(...)`, invalidate (§4.1). On error: keep dialog open, show `<FormErrors>` as first child of the form, field errors under fields, run `useFocusFirstError`.
- Delete confirmations: `Dialog` titled "Delete department?" etc., description naming the object, buttons Cancel (secondary) / Delete (danger). A 409 shows `ErrorBanner` inside the dialog with the page copy below and the Delete button stays enabled.

### 3.1 Sign-in (`src/features/auth/sign-in-page.tsx`, `SignInPage({ next?, error?, email? })`)
Layout: `<main id="main" tabIndex={-1} className="flex min-h-screen items-start justify-center bg-canvas px-4 pt-24">` → card `w-full max-w-sm rounded-lg border border-line bg-surface p-8 shadow-sm`. Wordmark "UniCourse" `text-sm font-semibold text-accent`, then `h1` "Sign in" `mt-6 text-xl font-semibold tracking-tight`, then `p` "Use your university account." `mt-1 text-sm text-ink-muted`.

`next` is passed through `safeNext()` once at the top (`src/features/auth/safe-next.ts`: returns `s` iff `typeof s === 'string' && s.startsWith('/') && !s.startsWith('//') && !s.startsWith('/\\') && !/[\r\n\t]/.test(s) && s.length <= 512`, else `undefined`). Only the safe value is ever sent to the API.

Callback error (`?error=`): `ErrorBanner` above the forms (no title, body only), copy:
| code | copy |
|---|---|
| `unauthenticated` | Sign-in didn't complete. Please try again. |
| `forbidden` | This email can't sign in to UniCourse. Ask your university administrator to invite you. |
| `validation_failed` | That sign-in link has expired or was already used. Request a new one below. |
| `rate_limited` | Too many sign-in attempts. Wait a minute, then try again. |
| `no_membership` | You're signed in, but your account isn't a member of any university yet. Ask your administrator for an invitation. |
| anything else | Something went wrong while signing in. Please try again. |

**Form A, provider sign-in** (`<form aria-labelledby="provider-heading">`, visually: no heading text shown; use `aria-label="Sign in with your university account"`):
- `FormField` label "University email or university ID", name `identifier`, hint "For example alice@example.edu or example", `<input type="text" autoComplete="email" inputMode="email" autoCapitalize="none" spellCheck={false}>`; initial value = `email` search param ?? ''.
- Two full-width secondary buttons stacked (`w-full`): "Continue with Google", "Continue with Microsoft", both `type="button"`.
- Click: `v = identifier.trim()`; body = `v.includes('@') ? { email: v } : { slug: v.toLowerCase() }`, plus `next` if safe. `const { url } = await unwrap(api.POST('/auth/oidc/{provider}/start', { params: { path: { provider } }, body }))`; `window.location.assign(url)`. While pending both buttons disabled and the clicked one reads "Redirecting…".
- Empty identifier: client-side field error "Enter your university email or university ID." on `identifier`, focus it, no request.
- Errors: 400 → field `slug` or `email` mapped to `identifier` (copy `validation_failed:slug` → "Enter your university email or university ID.", `validation_failed:email` → "Enter a valid email address."); 404 → banner "We couldn't find a university for “{v}”, or this sign-in option isn't available for it. Check the spelling or use an email link below."; 429 → envelope message; other → `errorMessage`.

Divider: `<div className="my-6 flex items-center gap-3 text-xs text-ink-muted"><span className="h-px flex-1 bg-line"/>or<span className="h-px flex-1 bg-line"/></div>` (both spans `aria-hidden`).

**Form B, magic link** (`<form aria-label="Email me a sign-in link">`):
- `FormField` label "Email", name `email`, `<input type="email" autoComplete="email">`; initial value = `email` param, else identifier if it contains `@` at first render.
- Primary full-width submit "Email me a sign-in link" ("Sending…" while pending).
- Submit: `await unwrap(api.POST('/auth/magic-link', { body: { email: v.trim(), next } }))` → 202 → render **MagicLinkSent** in place of the card body.
- Errors: 400 field `email` → "Enter a valid email address." (focus field); 429 → `FormErrors` shows the envelope message; other → `errorMessage`.

**MagicLinkSent** (`magic-link-sent.tsx`, `MagicLinkSent({ email, onBack })`): heading (`h1`, receives focus via ref + `tabIndex={-1}` on mount) "Check your email"; body "If {email} can sign in to UniCourse, we've sent it a link. The link works once and expires in 15 minutes."; secondary text "Didn't get it? Check spam, or" + ghost Button "use a different email" → `onBack()` (returns to the forms with the email kept). Same copy for allowed and not-allowed emails (the API does not reveal which).

### 4.3 Errors in forms — `src/components/form-errors.tsx`

```ts
export type FieldCopy = Record<string, string>   // keys '<code>' (banner) or '<code>:<field>' (field), e.g. 'conflict:code'
export function errorMessage(error: unknown, copy?: FieldCopy): string
export function useFieldErrors(error: unknown, copy?: FieldCopy): Record<string, string>
export function FormErrors(props: { error: unknown; copy?: FieldCopy }): JSX.Element | null
export function useFocusFirstError(formRef: React.RefObject<HTMLElement>, error: unknown, bannerRef?: React.RefObject<HTMLElement>): void
```
- `useFieldErrors` (pure; a hook by name for the plan interface, implemented as `useMemo`): not an `ApiError` → `{}`. For each `details[i]` with non-empty `field`: `out[field] = copy[`${code}:${field}`] ?? sentence(details[i].message)` (`sentence` capitalises the first letter and adds a final period). If `details` is empty: for each copy key `${code}:<field>` → `out[field] = copy[key]` (this is how a detail-less 409 lands on `code` / `email` / `role`). First message per field wins.
- `errorMessage`: `ApiError` → `copy[code]` ?? (`validation_failed` with details → "Please fix the highlighted fields.") ?? `defaults[code]` ?? `error.message`; non-ApiError → "Something went wrong. Check your connection and try again.". `defaults`: `forbidden` "You don't have permission to do this.", `not_found` "This item no longer exists. Reload the page.", `internal` "Something went wrong on our side. Try again in a moment." For `rate_limited` there is no default: the envelope message is shown (plan test). When `error.requestId` is set, append " Reference: {requestId}." (support can grep the log).
- `FormErrors`: `null` when no error; else `ErrorBanner` with `errorMessage(...)`, plus a `<ul>` of the details whose field is `''` or `'body'` (the banner does not know which fields the form renders; any other unknown field is a bug to report, not to display).
- `useFocusFirstError`: `useEffect` on `error` change: if error is set, `const el = formRef.current?.querySelector<HTMLElement>('[aria-invalid="true"]')`; `(el ?? bannerRef?.current)?.focus()`. DOM order defines "first". Field names in forms equal the contract's JSON field names (`name`, `code`, `startsOn`, `endsOn`, `role`, `departmentIds`, `email`), so `details[].field` maps 1:1; the only alias is sign-in (`slug`/`email` → `identifier`, done in SignInPage).
- Client-side errors (sign-in empty identifier) are local state merged over `useFieldErrors` output.

### 4.4 Formatting — `src/lib/format.ts`
`formatDate('2026-09-01')` → parse the parts as a **local** date (`new Date(y, m - 1, d)`; never `new Date('YYYY-MM-DD')`, which is UTC and shifts a day west of Greenwich) → `Intl.DateTimeFormat(undefined, { dateStyle: 'medium' })` → "Sep 1, 2026". For date-times (`expiresAt`), `formatDate` accepts an ISO date-time too (`new Date(iso)`). `formatDateTime(iso)` → `{ dateStyle: 'medium', timeStyle: 'short' }`. Browser locale and timezone (ceiling: university timezone arrives with the spec that adds `University.timezone`).

## 9. Alignment with P1-L2 (tenant API design, read at finish)

- Every 409 from tenant routes is `httpx.Conflict(message)` with `details: []`; the UI therefore keys field placement on `conflict:<field>` copy (§4.3), never on the server sentence. Server 409 texts seen: "department code already exists", "department is still in use", "term name already exists", "university must keep one admin", "user is already a member", "invitation already pending for this email", "invitation already accepted".
- Names are capped at 100 characters server-side (400 field `name`); the copy above says so. No `maxLength` attribute on inputs (the server is the validator; a silent truncation would hide the rule).
- dept_admin may list (member invitations only), create (`role: member`) and revoke member invitations — matches the Invitations-only admin area in §2.3.
- Department and term lists are readable by every member, so `useAllDepartments` works for dept_admin pickers too.
