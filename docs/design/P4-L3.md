# P4-L3 - Trusted-proxy client address; rate limit on OIDC start

Brief: PLAN.md Phase 4 P4-L3, backlog "per-IP magic-link limit keys on the remote address", D13, ruling D47 (owner to confirm). Spec 1 §6 (`rate_limited` on "magic-link and sign-in endpoints"), §9 (request log line).

## 1. Problem, in the code

- `auth.Deps.requestMagicLink` keys the IP bucket on `net.SplitHostPort(r.RemoteAddr)` (`internal/auth/handler.go` ~243). Behind a reverse proxy every client is the proxy, so one bucket of 300/h serves everyone.
- `auth.Deps.oidcStart` has no limit. The contract already lists `429 RateLimited` on `POST /auth/oidc/{provider}/start` (`openapi.json`), so the code is behind the contract.
- The request log line (`httpx.LogMiddleware`) has no client address.

## 2. Shape

One new middleware resolves the client address once per request and stores it in the context; one reader returns it. Both live in `httpx`.

```go
// internal/httpx/clientip.go (new)
func ClientIPMiddleware(trusted []netip.Prefix, next http.Handler) http.Handler
func ClientIP(r *http.Request) string
```

- `ClientIPMiddleware` computes `clientIP(r.RemoteAddr, r.Header.Values("X-Forwarded-For"), trusted)` and puts the string into the context under a new `ctxKey` constant `clientIPKey` (add to the existing `iota` block in `middleware.go`).
- `ClientIP(r)` returns the context value; when absent (handler built without the middleware: unit tests, contract test) it returns `clientIP(r.RemoteAddr, nil, nil)`, i.e. the connection address. It never fails.
- Why a middleware and not a pure `ClientIP(r)`: the trusted list is configuration; a package-level variable would be global mutable state shared by parallel tests. Same pattern as `RequestIDMiddleware`/`RequestID`.
- `r.RemoteAddr` is not rewritten (it stays the truthful socket peer).

Chain in `cmd/api/main.go` `newHandler`, outermost so the log middleware sees it:

```go
return httpx.ClientIPMiddleware(trusted, httpx.RequestIDMiddleware(httpx.LogMiddleware(logger, httpx.Recover(mux))))
```

`newHandler` gains a parameter `trusted []netip.Prefix` (after `logger`); `main` passes `cfg.TrustedProxies`; the four `main_test.go` call sites pass `nil`.

## 3. Algorithm

Load-bearing; implement as written (the designer ran this code against every row of the §9 table: all pass).

```go
// parseIP accepts 1.2.3.4, 1.2.3.4:80, ::1, [::1], [::1]:80, fe80::1%eth0. It unmaps
// IPv4-mapped IPv6 and drops the zone, so one host has one canonical key and
// netip.Prefix.Contains works (Contains is false for any address with a zone).
func parseIP(s string) (netip.Addr, bool) {
	s = strings.TrimSpace(s)
	if ap, err := netip.ParseAddrPort(s); err == nil {
		return ap.Addr().Unmap().WithZone(""), true
	}
	if len(s) > 2 && s[0] == '[' && s[len(s)-1] == ']' {
		s = s[1 : len(s)-1]
	}
	a, err := netip.ParseAddr(s)
	if err != nil {
		return netip.Addr{}, false
	}
	return a.Unmap().WithZone(""), true
}

func trustedAddr(a netip.Addr, trusted []netip.Prefix) bool {
	for _, p := range trusted {
		if p.Contains(a) {
			return true
		}
	}
	return false
}

// clientIP: the connection address unless it is a trusted proxy; then the rightmost
// X-Forwarded-For hop that is not itself trusted (a client can only prepend entries,
// so it cannot choose that hop). All hops trusted: the leftmost hop. Malformed hop
// reached during the walk: the connection address. Never fails.
func clientIP(remoteAddr string, xff []string, trusted []netip.Prefix) string {
	remote, ok := parseIP(remoteAddr)
	if !ok {
		return remoteAddr // unix socket or test oddity: same as today
	}
	if !trustedAddr(remote, trusted) {
		return remote.String()
	}
	hops := strings.Split(strings.Join(xff, ","), ",")
	client := remote
	for i := len(hops) - 1; i >= 0; i-- {
		if strings.TrimSpace(hops[i]) == "" {
			continue
		}
		a, ok := parseIP(hops[i])
		if !ok {
			return remote.String()
		}
		client = a
		if !trustedAddr(a, trusted) {
			break
		}
	}
	return client.String()
}
```

Notes the worker must keep:

- Several `X-Forwarded-For` header lines are joined with `,` in order (RFC 9110 field combination); `r.Header.Values` gives them in order.
- Empty hops (`", ,"`, trailing comma) are skipped, not malformed.
- Output is `netip.Addr.String()`: lowercase, compressed IPv6, no port, no brackets, no zone. `2001:DB8::7` and `2001:db8::7` share a bucket.
- Spoof resistance: the walk stops at the first untrusted hop from the right, so entries a client wrote (always to the left of the hop its first trusted proxy appended) are never read. A malformed hop is only reached if every hop right of it was trusted, i.e. a trusted proxy wrote it; falling back to the proxy's address is then safe (shared bucket, never 500).
- "All hops trusted" returns the leftmost hop, not `RemoteAddr`: that is a client inside a trusted range, vouched for by the proxy chain (nginx `real_ip_recursive` behaves the same). It gives internal clients separate buckets. Ruling D47 says "otherwise RemoteAddr" only for untrusted connections, so this does not contradict it.

## 4. Configuration

`internal/config/config.go`:

- `Config` gains `TrustedProxies []netip.Prefix`.
- Env var `UNICOURSE_TRUSTED_PROXIES`, optional, default empty (trust nobody: behaviour equals today's).
- Parse after the existing checks with a new unexported `parseProxies(s string) ([]netip.Prefix, error)`:
  - split on `,`, `strings.TrimSpace` each, skip empty items;
  - item contains `/`: `netip.ParsePrefix`, then `.Masked()` (so `10.0.0.1/8` becomes `10.0.0.0/8`);
  - otherwise `netip.ParseAddr`, reject a zone, then `netip.PrefixFrom(a.Unmap(), a.Unmap().BitLen())` (one host);
  - reject `Bits() == 0` (`0.0.0.0/0`, `::/0`): trusting every address lets any client choose its own key.
- Error text, first bad item only (`Load` returns it, `main` already logs and exits 1):
  - `UNICOURSE_TRUSTED_PROXIES: "nope" is not a CIDR or IP address`
  - `UNICOURSE_TRUSTED_PROXIES: 0.0.0.0/0 trusts every address; list only the proxies' addresses`

## 5. Log field

`LogMiddleware` always appends `"clientIp", ClientIP(r)` to `attrs` (after `requestId`). camelCase like `requestId`, `userId`. It is present on every line, including when no proxy is trusted (then it is the connection address).

## 6. Limiter

`internal/auth/handler.go`:

- `requestMagicLink`: replace the `SplitHostPort` block with `d.IPLimit.Allow("ip:"+httpx.ClientIP(r))`; order unchanged (after body validation, IP before email). Drop the `net` import if nothing else uses it (today nothing does).
- `oidcStart`: after `NormalizeEmail` succeeds and before `p.begin`, add
  ```go
  if !d.IPLimit.Allow("oidc-ip:" + httpx.ClientIP(r)) {
  	return httpx.RateLimited()
  }
  ```
  Unknown provider (404) and invalid bodies (400) are answered first and do not spend a hit, the same as the magic link.
- `Deps` comment: `IPLimit guards POST /auth/magic-link and POST /auth/oidc/{provider}/start (300 per client address per hour, a separate bucket per endpoint); EmailLimit guards the magic link (5 per email per hour).`
- `cmd/api/main.go` wiring of the limiters is unchanged (`NewLimiter(300, time.Hour)`).

**Deviation from D47: separate bucket per endpoint, not one shared bucket.** Same `Limiter` instance, same 300/h, different key prefix (`ip:` and `oidc-ip:`). Reason: D13 set 300 because a campus shares one NAT address, and the magic-link bucket protects mail sending. An OIDC start costs one random read and one HMAC (`Provider.begin`: no database, no mail). Sharing would let SSO sign-ins on a campus NAT use up that campus's magic-link budget, and the reverse, with no security gain. If the orchestrator keeps the shared bucket, the change is one token (`"oidc-ip:"` becomes `"ip:"`) and the test in §9 that checks the magic link still gets 202 flips to 429.

**429 response on start.** `start` is a JSON `POST` (it returns `{"url"}`), not a browser navigation, so D16's "callbacks answer 302" does not apply. It answers the standard envelope `429 {"code":"rate_limited",...}` from `httpx.RateLimited()` and sets no `oidc` cookie (the check runs before `setOIDCCookie`). The web sign-in page already handles it: `sign-in-page.tsx` catches the error from `unwrap` and `client.ts` maps 429 to `rate_limited`, which has its own copy. No web change.

## 10. Simplifications and their ceilings

| Simplification | Ceiling | Upgrade |
|---|---|---|
| Limiter in memory, per process (D13, unchanged) | N API processes allow N x 300/h per client | Backlog: Postgres-backed buckets when more than one process runs |
| Only `X-Forwarded-For`; not RFC 7239 `Forwarded`, `CF-Connecting-IP`, `Fly-Client-IP` | A proxy that sets only `Forwarded` gives no client address (all clients share the proxy's bucket again) | Configure the proxy to append `X-Forwarded-For` (nginx, Caddy, ALB, Cloudflare and Fly all do by default); add another header when a deployment needs it |
| IPv6 keyed per address, not per /64 | A client with a /64 can rotate through many buckets; the per-email limit (5/h) still caps mail per mailbox | Mask IPv6 keys to /64 in `auth` (escalated, §11) |
| Clients inside a trusted range can set their own key and logged address | Only matters if someone lists client networks | README row says to list proxy addresses only |
| Fixed-window limiter (unchanged) | 2x burst across a window edge | Sliding window if abuse shows up |
| Unparseable `RemoteAddr` (unix socket) is used as is and never trusted | All unix-socket clients share one bucket | Not needed: the API listens on TCP |

## 11. Escalated (owner or orchestrator)

1. Separate per-endpoint buckets instead of D47's shared bucket (§6). The design implements separate buckets; reverting is one token.
2. `clientIp` in every request log line is personal data (GDPR). Spec 1 §9 lists the log fields without it; D47 adds it. Owner to confirm, and to set log retention when logs leave the box.
3. 300 starts/h per address on OIDC start: a lecture hall signing in through one IPv4 NAT at the start of term could hit it (sessions are long-lived, so this is a first-day risk). Raise it or exempt start if it shows up.
4. IPv6 /64 masking (§10). Not done: it trades bypass resistance against campus networks sharing one /64 per Wi-Fi VLAN.
5. Web copy for `rate_limited` says "Wait a minute" while the window is an hour. Out of scope here (web).
