# P4-L2 design: database role split (owner migrates, API cannot disable RLS)

PLAN.md: Phase 4 P4-L2, backlog "split the database roles", D4 (superseded), D48 (ruling this designs against). Spec 1 §4: "The platform CLI uses a separate role for `universities` administration."
Base: `main` **after PR #43 (mail outbox, `0003_mail_outbox.sql`, table `outbox_mails`) has merged**. The worker branches from that main, not from `1bfbd2a`: `cmd/api/main.go`, `cmd/unicourse-admin/main{,_test}.go` and `pg/migrate_test.go` all change in #43. P4-L3 (trusted proxy, `lane/P4-L3-trusted-proxy`) edits the same `newHandler(...)` call in `cmd/api/main.go` (adds a `trusted` argument): a one-line conflict; whichever lands second rebases, keeping both changes.

Every path below is under `apps/api/` unless it starts with `.github/` or `apps/web/`.

## 0. Decisions, deviations and simplifications

| # | Decision | Why / ceiling |
|---|---|---|
| 1 | Two LOGIN roles, both `NOSUPERUSER NOBYPASSRLS NOCREATEDB`: `unicourse_owner` owns the databases, schema contents and every table; `unicourse` owns nothing and gets `select, insert, update, delete` on every table (only `select` on `schema_migrations`), `usage` on schema `public`, and `usage, select` on future sequences. No `truncate`, `references`, `trigger`, no `create`. | D48. `truncate` is withheld on purpose: TRUNCATE ignores row level security. |
| 2 | **All grants live in migration `0004_role_split.sql`**, not in `initdb.sql` and not in a one-off. initdb only creates roles and databases. | Deviation from the ruling's "default privileges executed once as the owner". Verified on PG16: `drop schema public cascade` (TestMigrate does it) deletes the schema's `pg_default_acl` rows, and the recreated `public` has no `usage` for anyone but its owner. Grants in a migration are replayed on every fresh schema and also land in production through the normal `migrate`. |
| 3 | Role names `unicourse` and `unicourse_owner` are hard-coded in `0004`. | Ceiling: a deployment must use these two names (a managed host that forces other login names can create `unicourse` as a NOLOGIN group and `grant unicourse to <login>`; `pg_has_role` checks below still work). Renaming means a new migration. |
| 4 | Every table gets the same four privileges, `universities` included. | Restricting `universities` to read-only for the API is not possible as-is: `tenant/membership.go:104` locks it with `for no key update`, which needs UPDATE. Escalated (report), not designed. |
| 5 | `pg.Migrate` stays in package `pg` (unchanged); only its call in `cmd/api/main.go` goes. Callers: `unicourse-admin migrate` and `testdb`. | testdb needs it; moving the function into `cmd/` would duplicate it. |
| 6 | The CLI uses **only** `UNICOURSE_OWNER_DATABASE_URL`, for every command (`migrate` and `create-university`). No fallback to `UNICOURSE_DATABASE_URL`. | Spec 1 §4 "separate role". A fallback would silently run migrations as the API role (they would fail anyway, see 8). Ceiling: the operator holds the owner credential for daily university creation; a third, non-owning platform role is the upgrade if that matters. |
| 7 | API startup: `pg.CheckAPIRole` then `pg.CheckMigrated`; either failing logs one clear line and exits 1. `/readyz` = `pg.CheckMigrated` (which also proves the connection, replacing `db.PingContext`). | Ruling. Ceiling of the `/readyz` half: it only changes anything if the database is restored to an older state under a running process; cost is one indexed read of a ~4-row table per probe. Drop it if anyone objects; startup is what matters. |
| 8 | `CheckMigrated` fails only when an **embedded** migration has no `schema_migrations` row (database behind the binary). Rows the binary does not know (database ahead) are fine. | Rolling deploy order is "migrate, then roll binaries"; old processes must stay ready. Ceiling: every migration must be compatible with the previous binary (expand, then contract in a later migration). Write it in the README. |
| 9 | `CheckAPIRole` refuses: superuser, BYPASSRLS, member of the owner of schema `public`, member of the owner of any relation in `public`. `MEMBER` (not `USAGE`) so a `NOINHERIT` grant to the owner still counts. | Being the database owner implies membership in `pg_database_owner`, the PG15+ owner of `public`, so "API URL points at the owner" fails even on an empty database. |
| 10 | testdb takes two URLs: `UNICOURSE_TEST_DATABASE_URL` (API role, unchanged name) and `UNICOURSE_TEST_OWNER_DATABASE_URL` (new). Unset API URL still skips; API URL set but owner URL unset is `t.Fatal` (not skip, so CI cannot go silently green). Migrate and truncate run on the owner pool; the returned pool is the API pool, checked with `pg.CheckAPIRole`. | The API pool has no TRUNCATE (decision 1). Ceiling: two pools per test instead of one (one extra connect + ping per `testdb.Open`, a few ms). |
| 11 | `testdb.Seed` is unchanged (writes through whatever pool it is given; the API role may write `universities`, decision 4). | Smallest diff. |
| 12 | No new `internal/config` field. The API keeps `UNICOURSE_DATABASE_URL`; the CLI reads its variable with `os.Getenv` as today. | The CLI never used `config.Load`. |
| 13 | Migrate does not check which role runs it. | Running it as the API role already fails loudly (`permission denied for schema public`, verified, and asserted by a CLI test). Running it as a superuser would make `postgres` own new tables and skip the default privileges, so the API breaks with `permission denied` on the new table, loudly, not insecurely. |
| 14 | The API role keeps PG's default `TEMP` and `CONNECT` on the database (via PUBLIC). | Temp tables are session-private and harmless. Revoke when a hardening pass wants it. |
| 15 | `0004` also runs `revoke create on schema public from public`. | No-op on PG15+ (already the default); closes the hole if production runs PG14 or older. |
| 16 | One worker lane, not two (§9). | The API calls `pg.Migrate` at startup and the CLI reads the owner URL; with only half landed, e2e breaks. |

## 1. SQL

### 1.1 `migrations/0004_role_split.sql` (new)

```sql
-- D48: the API connects as role unicourse, which owns nothing and so cannot disable row level
-- security, drop policies, truncate (TRUNCATE ignores RLS) or create tables. unicourse_owner owns
-- everything and runs migrations (unicourse-admin migrate). The grants live here, not in a one-off,
-- because dropping and recreating schema public (tests) drops its default privileges too.
-- Fails, on purpose, when run as any role that is not, or is not a member of, unicourse_owner.
revoke create on schema public from public;
grant usage on schema public to unicourse;
grant select, insert, update, delete on all tables in schema public to unicourse;
revoke insert, update, delete on schema_migrations from unicourse;
alter default privileges for role unicourse_owner in schema public
  grant select, insert, update, delete on tables to unicourse;
alter default privileges for role unicourse_owner in schema public
  grant usage, select on sequences to unicourse;
```

No sequences exist today (all ids are `gen_random_uuid()`); the sequence default costs one line and covers a future identity column. Functions need nothing: `set_updated_at()` is `security invoker` and PUBLIC has EXECUTE by default. Foreign-key checks run as the table owner, so no `references` grant.

Rule for every later migration (put it in the README §6 and as the comment above): run as `unicourse_owner`; tables and sequences are granted automatically by the default privileges; anything else the API needs (a new schema, a function with revoked EXECUTE) is granted in that migration.

### 1.2 `docker/initdb.sql` (replace)

```sql
CREATE ROLE unicourse_owner LOGIN PASSWORD 'unicourse_owner' NOSUPERUSER NOBYPASSRLS NOCREATEDB;
CREATE ROLE unicourse LOGIN PASSWORD 'unicourse' NOSUPERUSER NOBYPASSRLS NOCREATEDB;
CREATE DATABASE unicourse OWNER unicourse_owner;
CREATE DATABASE unicourse_test OWNER unicourse_owner;
CREATE DATABASE unicourse_e2e OWNER unicourse_owner;
```

Runs on a fresh compose volume and in both CI jobs (already wired: `psql -f apps/api/docker/initdb.sql`).

### 1.3 Production one-off (README §6, documented, not a file)

Nothing deploys yet, so production is the same as a fresh volume, run once by the database administrator (superuser, or a `CREATEROLE` admin that is granted membership in `unicourse_owner` on managed Postgres, which PG16 needs to create a database owned by another role):

```sql
create role unicourse_owner login password '<secret>' nosuperuser nobypassrls nocreatedb;
create role unicourse login password '<secret>' nosuperuser nobypassrls nocreatedb;
create database unicourse owner unicourse_owner;
```

then `UNICOURSE_OWNER_DATABASE_URL=... unicourse-admin migrate`. The API process gets only `UNICOURSE_DATABASE_URL` (role `unicourse`); the owner credential is never in its environment.

### 1.4 Existing local volumes (README §6, and the orchestrator's cut-over, §8)

Either `docker compose down -v && docker compose up -d` (loses local data), or keep data, as `postgres`:

```sql
create role unicourse_owner login password 'unicourse_owner' nosuperuser nobypassrls nocreatedb;
\c unicourse
reassign owned by unicourse to unicourse_owner;
\c unicourse_test
reassign owned by unicourse to unicourse_owner;
\c unicourse_e2e
reassign owned by unicourse to unicourse_owner;
```

(`reassign owned` moves the in-database objects of the database it runs in, plus the databases themselves, so it runs once per database.) Then `unicourse-admin migrate` with the owner URL against each of the three databases, which applies `0004`.
Command form: `docker compose exec -T postgres psql -U postgres -v ON_ERROR_STOP=1 <<'SQL' ... SQL`.

## 3. Package `pg`: `internal/pg/check.go` (new)

```go
// CheckAPIRole fails when the connected role could switch row level security off or bypass it:
// a superuser, a BYPASSRLS role, or a member of the role owning schema public or any relation in it.
func CheckAPIRole(ctx context.Context, db *sql.DB) error

// CheckMigrated fails when a migration embedded in this binary has no schema_migrations row.
// Rows for migrations the binary does not know are fine (a newer binary migrated first).
func CheckMigrated(ctx context.Context, db *sql.DB) error
```

`CheckAPIRole` query (verified on PG16: `f` for the API role, `t` for the owner, also on a database with no tables):

```sql
select current_user, rolsuper or rolbypassrls
    or pg_has_role(current_user, (select nspowner from pg_namespace where nspname = 'public'), 'MEMBER')
    or exists (select 1 from pg_class where relnamespace = 'public'::regnamespace and pg_has_role(current_user, relowner, 'MEMBER'))
from pg_roles where rolname = current_user
```

Error when true, exact text: `fmt.Errorf("database role %q is a superuser, bypasses row level security or owns the schema: UNICOURSE_DATABASE_URL must use the API role (unicourse), not the owner", role)`. Query error: `fmt.Errorf("check database role: %w", err)`.

`CheckMigrated`: `fs.Glob(migrations.FS, "*.sql")`; `select name from schema_migrations`; a `*pgconn.PgError` with code `42P01` (table missing: never migrated) counts as zero rows applied; any other error returns `fmt.Errorf("check migrations: %w", err)`. Missing = embedded names without a row, in name order. When non-empty, exact text: `fmt.Errorf("database is missing migrations %s: run unicourse-admin migrate", strings.Join(missing, ", "))`.

Package doc line in `open.go` stays true (pg still applies migrations, through the CLI).

## 5. `internal/testdb/testdb.go`

```go
// Open is OpenWithOwner without the owner pool; nearly every test wants only the API pool.
func Open(t *testing.T) *sql.DB

// OpenWithOwner connects twice to the same _test database: as the owner (UNICOURSE_TEST_OWNER_DATABASE_URL),
// which migrates and truncates, and as the API role (UNICOURSE_TEST_DATABASE_URL), which the tests
// use like the API does. Skips when UNICOURSE_TEST_DATABASE_URL is unset.
func OpenWithOwner(t *testing.T) (api, owner *sql.DB)
```

Order inside `OpenWithOwner` (keeps today's structure; the advisory lock moves to the owner pool):

1. API URL unset: `t.Skip` (as today). Owner URL unset: `t.Fatal("UNICOURSE_TEST_OWNER_DATABASE_URL not set: testdb migrates and truncates as the owner role (unicourse_owner)")`.
2. Open owner pool; take `pg_advisory_lock(lockKey)` on a dedicated conn of it; register the cleanup right after (truncate on owner if `cleaned`, unlock, close lock conn, close owner, close api if opened).
3. Owner pool: `current_database()` must end in `_test` (existing message); `rolsuper or rolbypassrls` must be false, message `test owner role is a superuser or has BYPASSRLS: row level security would not apply to the CLI tests; connect as role unicourse_owner`.
4. `pg.Migrate(owner)`, `truncate(owner)`, `cleaned = true`.
5. Open API pool; its `current_database()` must equal the owner's (message `UNICOURSE_TEST_DATABASE_URL and UNICOURSE_TEST_OWNER_DATABASE_URL point at different databases (%q, %q)`); `pg.CheckAPIRole(api)` must pass (`t.Fatal(err)`). This replaces today's `rolsuper or rolbypassrls` check on the test pool (it is a superset).
6. Return both.

`truncate` and `Seed` bodies unchanged (`truncate` now always receives the owner pool). Package doc: "gives integration tests a migrated, empty database, migrated by the owner role and used as the API role".

## 8. Rollout on the shared local Postgres

Every lane uses one local cluster and `unicourse_test`. Branches without this change run `pg.Migrate` as `unicourse` from testdb and fail (`permission denied for schema public`) once `unicourse_test` is owned by `unicourse_owner`. So:

- The **worker never touches** `unicourse`, `unicourse_test` or `unicourse_e2e`. As `postgres` it creates role `unicourse_owner` (§1.4 first line; harmless to other lanes) and two scratch databases `unicourse_roles_test` and `unicourse_roles_e2e` owned by `unicourse_owner`, runs the Go gates with `UNICOURSE_TEST_DATABASE_URL=postgres://unicourse:unicourse@localhost:5432/unicourse_roles_test?sslmode=disable` and `UNICOURSE_TEST_OWNER_DATABASE_URL=postgres://unicourse_owner:unicourse_owner@...unicourse_roles_test...`, and e2e with `UNICOURSE_E2E_DATABASE_URL`/`UNICOURSE_E2E_OWNER_DATABASE_URL` on `unicourse_roles_e2e`. It drops both scratch databases when done (the role stays; the cut-over needs it).
- The **orchestrator**, after the PR merges and while no lane runs DB tests, runs §1.4 on the three shared databases, then `unicourse-admin migrate` against each, and tells running lanes to rebase. Verification on the real stack: (1) API with `UNICOURSE_DATABASE_URL` on the owner role exits 1 with `database role "unicourse_owner" ...`; (2) API against a database with `0004`'s row deleted exits 1 with `database is missing migrations 0004_role_split.sql: run unicourse-admin migrate`; (3) normal start, `GET /readyz` 200; (4) `psql` as `unicourse`: `alter table memberships disable row level security` → `must be owner of table memberships`.
