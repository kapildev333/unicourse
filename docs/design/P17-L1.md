## 1. B1: rate limits in Postgres (P17-L2)

### 1.1 Migration `migrations/0008_rate_buckets.sql`

```sql
-- B1 (Spec 10): sign-in rate limits shared by every API process. One row per (bucket, client_key),
-- a fixed window that ends at expires_at. Platform table outside row level security, like
-- outbox_mails: no university, and no API route reads it. client_key is a client address or a
-- normalised email, kept at most two windows (auth.Limiter prunes expired rows).
-- unicourse gets DML through the default privileges of 0004.
create table rate_buckets (
  bucket text not null,
  client_key text not null,
  hits integer not null,
  expires_at timestamptz not null,
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now(),
  primary key (bucket, client_key)
);
create index on rate_buckets (expires_at);
```

No `set_updated_at` trigger: the upsert sets `updated_at` itself (the trigger would fire on every hit for nothing). The window is stored as its end (`expires_at`), not its start: pruning is then one predicate that is correct for limiters with different windows (with a start column, a 1-minute limiter's prune would delete a 1-hour limiter's live rows).

### 1.2 Go shape (`internal/auth/ratelimit.go`)

The in-memory map goes; the type name, the constructor and `cmd/api/main.go` stay unchanged (`auth.NewLimiter(5, time.Hour)`, `auth.NewLimiter(300, time.Hour)`), so L2 never touches `main.go`. The database comes from `Deps.DB` at the call site.

```go
// Limiter is a fixed-window limit kept in rate_buckets, so every API process shares one count per key.
// Ceiling: fixed window, so up to 2x max across a window edge.
type Limiter struct {
	max    int
	window time.Duration
	now    func() time.Time // tests move the clock

	mu     sync.Mutex
	pruned time.Time // last prune by this instance
}

func NewLimiter(max int, window time.Duration) *Limiter

// Check records one hit for (bucket, key) and returns nil while the window holds at most max hits,
// httpx.RateLimited() once it holds more, or the database error (fail closed: the caller returns it, a 500).
func (l *Limiter) Check(ctx context.Context, db *sql.DB, bucket, key string) error
```

`Check`, in order:

1. Prune: under `l.mu`, decide `due := now.Sub(l.pruned) >= l.window` and if so set `l.pruned = now`; unlock, then when `due` run `delete from rate_buckets where expires_at < $1` with `now` (no statement runs under the mutex). If it fails, return the error.
2. Increment and read in one statement (`now` is `l.now()`, `$3`; `$4` is `now.Add(l.window)`):

```sql
insert into rate_buckets (bucket, client_key, hits, expires_at, updated_at)
values ($1, $2, 1, $4, $3)
on conflict (bucket, client_key) do update set
  hits       = case when rate_buckets.expires_at <= $3 then 1 else rate_buckets.hits + 1 end,
  expires_at = case when rate_buckets.expires_at <= $3 then excluded.expires_at else rate_buckets.expires_at end,
  updated_at = $3
returning hits
```

3. `hits > l.max` returns `httpx.RateLimited()`, else nil.

Atomic: `INSERT ... ON CONFLICT DO UPDATE` takes the row lock, so concurrent hits on one key serialise and each sees the count including its own hit; both `CASE`s read the old row. Hits over the limit are still counted (the in-memory limiter did not count them); the allow or deny answer within a window is the same. Run it on `db` directly, outside any transaction.

### 1.4 Database unreachable: fail closed

`Check` returns the error and the handler answers 500 `internal`. Reason: failing open would turn a database outage into an unlimited sign-in mail cannon the moment the database returns, and nothing is lost by refusing. Both routes already document 500 in `openapi.json`; no contract change.

### 1.6 Simplifications and ceilings

- Fixed window, up to 2x max across an edge (as before). Sliding windows if abuse shows up.
- One extra statement per sign-in request; at 300/h per address the table holds one row per active address and email, pruned hourly per process. Fine to millions of sign-ins a day; a `pg_cron`-style job only if the delete ever shows in slow logs.
- Keys are stored in clear (address, email) for at most two windows. Hash them if the privacy notice ever says otherwise.
- The window clock is each process's clock (`l.now`), not the database's: NTP skew of milliseconds shifts windows by milliseconds.

## 2. B2: parallel outbox senders (P17-L3)

### 2.1 Go shape (`internal/outbox/outbox.go`)

```go
type Sender struct {
	// ...existing fields...
	Senders int // goroutines draining in parallel per process; below 1 means 1
}
```

`NewSender` sets `Senders: 1`. `Run` keeps its loop, its one wake channel and its housekeeping; only the drain call changes from `s.Drain(ctx)` to `s.drainAll(ctx)`:

```go
// drainAll runs Senders Drains at once and waits for all; each claims its own rows (FOR UPDATE SKIP LOCKED).
func (s *Sender) drainAll(ctx context.Context) error {
	n := max(s.Senders, 1)
	errs := make([]error, n)
	var wg sync.WaitGroup
	for i := range n {
		wg.Add(1)
		go func() { defer wg.Done(); errs[i] = s.Drain(ctx) }()
	}
	wg.Wait()
	return errors.Join(errs...)
}
```

`sendOne` is unchanged apart from deleting its `ponytail: one send at a time per process` line. Exactly-once per claim is already guaranteed by `FOR UPDATE SKIP LOCKED` (the row stays locked for its send and is deleted in the same transaction).

### 2.2 Configuration

`UNICOURSE_OUTBOX_SENDERS`: optional, default 1, a whole number from 1 to 10. `config.Config` gains `OutboxSenders int`. Anything else fails `Load` with `UNICOURSE_OUTBOX_SENDERS must be a whole number from 1 to 10, got "<value>"`. Upper bound 10 because each sender holds one connection for the length of an SMTP send and `pg.Open` caps the pool at 20; 10 leaves half for requests. `main.go`: `sender.Senders = cfg.OutboxSenders` right after `outbox.NewSender`. README env row: `UNICOURSE_OUTBOX_SENDERS | no | mail sender goroutines per API process, 1 to 10, default 1; each holds a database connection while it talks to SMTP`.

## 4. B4: `unicourse_platform` role for `create-university` (P17-L7)

### 4.1 Why the migration does not create the role

Migrations run as `unicourse_owner`, which is `NOCREATEROLE` (D48, `docker/initdb.sql`), so `create role` inside `0009` would fail everywhere. Giving the owner `CREATEROLE` would widen D48. So the role is created by whoever creates the other roles (`docker/initdb.sql` locally and in CI, the database administrator in production), and `0009` checks it exists and fails with the exact statement to run, like `0004` fails on purpose for the wrong role. The local cluster needs the role created once before 0009 runs there (escalated).

### 4.2 `migrations/0009_platform_role.sql`

```sql
-- D133: unicourse_platform runs unicourse-admin create-university and nothing else. It owns nothing,
-- is subject to row level security, and has exactly the grants create-university needs; no grant on
-- schema_migrations and no CREATE on schema public, so it cannot run migrate. When a migration changes
-- what create-university touches, it updates these grants.
do $$
begin
  if not exists (select 1 from pg_roles where rolname = 'unicourse_platform') then
    raise exception 'role unicourse_platform is missing: as a superuser run  create role unicourse_platform login password ''<secret>'' nosuperuser nobypassrls nocreatedb;  then run unicourse-admin migrate again';
  end if;
end $$;
grant usage on schema public to unicourse_platform;
grant select, insert on universities, invitations to unicourse_platform;
grant select on users, memberships to unicourse_platform;
grant insert on grade_scales, audit_log to unicourse_platform;
```

## 5. B5: `Forwarded` and IPv4-mapped prefixes (P17-L3)

### 5.1 Client addresses

Already unmapped: `parseIP` calls `Unmap()` on every connection address and hop. B5 keeps that and adds `Forwarded`.

### 5.2 Prefixes (`internal/config/config.go`, `parseProxies`)

After a CIDR is parsed and masked: if `p.Addr().Is4In6() && p.Bits() >= 96`, replace it with `netip.PrefixFrom(p.Addr().Unmap(), p.Bits()-96)`. The existing `Bits() == 0` check then rejects `::ffff:0.0.0.0/96` as "trusts every address". Mapped prefixes shorter than /96 stay IPv6 (they cover more than the mapped range and never match an unmapped IPv4 address, as today). Bare addresses are already unmapped.

### 5.3 `Forwarded` parsing (`internal/httpx/clientip.go`)

```go
// forwardedFor returns the for= value of every element of the Forwarded header lines (RFC 7239), in order.
// A blank element yields "" (skipped, like an empty X-Forwarded-For entry). An element with no for=, a
// for= that is not a valid token or quoted string, or a quoted string with a backslash yields "unknown"
// (not an address, so the walk stops there with the connection address).
func forwardedFor(lines []string) []string
```

Rules:

1. Join the lines with `,`, split on `,` (elements), then each element on `;` (pairs). Commas or semicolons inside quoted strings are not honoured (see 5.6).
2. Pair: split on the first `=`; trim spaces around name and value; the name compares case-insensitively with `for`.
3. Value: if it starts with `"`, it must end with `"` and contain no other `"` or `\`; strip the quotes. Otherwise use it as is.
4. The value goes through `parseIP`, so these all work: `for=192.0.2.60`, `for="192.0.2.60:4711"`, `for="[2001:db8:cafe::17]"`, `for="[2001:db8:cafe::17]:4711"`, `for="::ffff:192.0.2.60"`, `for="[::ffff:192.0.2.60]:1"`. `unknown`, obfuscated identifiers (`_hidden`, `_SEVKISEK`) and obfuscated ports (`"192.0.2.60:_p"`) do not parse: same as a malformed X-Forwarded-For hop.

### 5.4 One trust walk, two headers

Extract the existing loop:

```go
// walk returns the rightmost hop that is not trusted, the leftmost hop when all are trusted, remote when
// there are no hops, and remote when a malformed hop is reached first. Blank hops are skipped.
func walk(remote netip.Addr, hops []string, trusted []netip.Prefix) netip.Addr

func clientIP(remoteAddr string, xff, fwd []string, trusted []netip.Prefix) string
```

`clientIP`:

1. Unparseable `remoteAddr`: return it (as today). Remote not trusted: return the remote address (headers ignored, as today).
2. A header is present when its joined values contain anything but spaces and commas.
3. Only X-Forwarded-For present (or neither): `walk(remote, split(xff))`, as today.
4. Only `Forwarded` present: `walk(remote, forwardedFor(fwd))`.
5. Both present: walk both; if they give the same address, that address; otherwise the connection address.

Why rule 5 instead of "one header wins": a proxy chain sets one of the two. If X-Forwarded-For always won, a client behind a `Forwarded`-only proxy could add its own X-Forwarded-For and pick its rate-limit key; if `Forwarded` always won, the same hole opens for today's X-Forwarded-For deployments. With rule 5 a client that adds the other header lands in the trusted proxy's own bucket, which only such clients share, so it cannot escape its limit and cannot touch anyone else's. `ClientIPMiddleware` passes `r.Header.Values("Forwarded")` as `fwd`. Update the function's `ponytail:` comment: `only X-Forwarded-For and Forwarded (not CF-Connecting-IP, X-Real-IP); IPv6 keyed per address, not per /64; ...`. README `UNICOURSE_TRUSTED_PROXIES` row: "X-Forwarded-For and Forwarded (for=) are read only on connections from these ... a request carrying both is keyed on the proxy address unless they agree".

### 5.6 Ceiling

Naive comma and semicolon splitting: a quoted value containing `,` or `;` splits wrongly. Only the client can write such a value, and only to the left of the trusted proxy's element; the walk stops at the first untrusted hop, so the misparse can at worst make that client's own request fall back to the proxy address. Clients behind proxies that send `for=unknown` or obfuscated identifiers share the proxy's bucket.
