# P7-L1 design: grading API (scale, assessments, scores, gradebook, final grades, GPA)

Source: spec `docs/specs/2026-10-07-grading.md` §3, §4, §5, §7, §8 (binding); plan `docs/plans/2026-10-07-grading.md` Task 1 and Review Focus 1-5; PLAN.md D16, D19, D20, D22, D27, D30, D41, D45, D46, D48, D61-D64. Builds on `docs/design/P0-L4.md` (contract conventions), `docs/design/P2-L2.md` (course package, imports) and `docs/design/P5-L1.md` (sub-lane pattern). Where this document and existing code disagree on a convention, the code wins; on behaviour, this document wins.

## 0. Decisions taken here

| # | Decision | Why |
|---|---|---|
| 1 | The US preset lives once, in SQL: migration `0005` defines `seed_us_grade_scale(u uuid)`; the migration calls it for every existing university **before** enabling RLS on `grade_scales`; `create-university` calls it inside its tenant-scoped tx. No Go copy. The Canadian preset is client-side only (spec §6). | Migrations are plain SQL and cannot call Go; one source of truth. Inserting before `enable row level security` avoids setting `app.university_id` per university in the migration (the owner is subject to forced RLS). |
| 2 | Every grade number (`points`, `maxPoints`, `weight`, `minPercent`, scale `points`, `percent`, `credits`, `gpa`) is a decimal **string** in Go, typed `json.Number`: read from Postgres as `x::text`, written as `$n::numeric`, marshalled as a JSON number literal (`87.50`). No `float64` anywhere. | `json.Number` already encodes as a number and decodes from one; no custom type. |
| 3 | Inputs are validated by one exact helper `tenant.Decimal` (regexp + `math/big.Rat`): decimal places, range, canonical formatting. | Exact comparisons (`points ≤ 2 × maxPoints`, `weights = 100.00`) without floats. |
| 4 | Running percent, final percent, letter and stats are computed in **Go with `math/big.Rat`** (exact rationals); GPA is computed in **SQL `numeric`** (`round(sum(points*credits)/sum(credits), 2)`). | The letter is decided on the *unrounded* percent; Σ(w·p/m) has non-terminating terms (1/3) that `numeric` division truncates, so a mathematically exact 93 could land on 92.999…; `big.Rat` is exact. `big.Rat.FloatString(2)` rounds halves away from zero = half up for non-negatives. GPA is one aggregate whose exact half-way values always terminate, so `numeric` + `round` is exact and keeps it one SQL statement (brief). |
| 5 | No new `authz` predicates: "grade" = `authz.CanReadRoster` (manager or any staff of the section); "teach" = `authz.CanManageTAs` (manager or instructor of the section); enrolled-student read = `authz.CanReadSection` minus staff. | Existing predicates are exactly the spec §4 sets; adding aliases is code without behaviour. Call sites carry a one-line comment. |
| 6 | Gradebook CSV export: `tenant.Wrap` learns one body type `tenant.Raw{ContentType, Filename, Body}` written verbatim. Negotiation: `strings.Contains(Accept, "text/csv")`. The contract lists `text/csv` as a second `200` content type of `getGradebook` (orchestrator ruling R4). | `Wrap` always JSON-encodes today; a handler has no `ResponseWriter`. The generated TS `data` type becomes `Gradebook \| string`; the web narrows it (P7-L2 note in the lane log). |
| 7 | Scores import has its own contract schemas `ScoreImportRow` / `ScoreImportCounts` / `ScoreImportPreview` (actions `add`, `update`, `exists`, `error`); `ImportRow` / `ImportCounts` are **not** widened (ruling R3). Upload bodies reuse `ImportUpload` / `ImportCommit` unchanged. In Go, `csvimport` gains `Update = "update"` and `Spec.Actions` (the action set counted and accepted; nil = today's four), so existing imports' JSON stays byte-identical. | Phase 6's import dialog and badges type against `ImportRow.action`; widening it would break them. |
| 8 | `PATCH` fields of non-string type use a new generic `tenant.Opt[T]` (absent vs explicit `null`, D27), next to `tenant.OptStr`. | Needed for `credits`, `maxPoints`, `weight`, `published`, `position`, `status`, `letter`. |
| 9 | Audit `score.set` carries the values, not only the user ids: `after = {assessmentId, scores:[{userId, points}]}`, `before = {scores:[...]}` for the rows that already had a value (omitted when none). | A grade trail without values cannot answer "what was it before". One extra select. Superset of spec §4. |
| 10 | Audit entities: `assessment.*` and `score.set` → `entityType assessment`, id = assessment id; `final_grade.finalize` / `.reopen` → `entityType section`, id = section id; `final_grade.override` → `entityType final_grade`, id = the `final_grades` row id; `grade_scale.update` → `entityType grade_scale`, id = university id. | `entity_id` is a uuid of a real thing; section-level actions sit on the section. |
| 11 | `GET /me/grades` lists sections the caller is enrolled in **or** has a final grade in (one `union`). Within a section, `running` is omitted when `final` is present. | Unenrolling after finalization must not drop a course from the GPA. One grade per section card. |
| 12 | The contract test's pending set carries the L1b and L1c routes while L1a lands the whole contract; each later sub-lane deletes its entries. | `diff()` in `contract_test.go` already supports a pending set; L1a must give the web lane every type (plan). |
| 13 | Finalization does not lock the section. Two concurrent finalizes: the second hits the unique `(university_id, section_id, user_id)` → 409. A score written concurrently may or may not be in the snapshot. | Unique constraint is the lock. |
| 14 | Students are ordered by `email` everywhere (gradebook, final-grades list, CSV). | Stable, unique. |
| 15 | D65: admin and dept_admin (own departments) hold every instructor power on grading (assessments, scores, import, finalize, override, reopen); TAs read the gradebook and final grades and enter/import scores; students read published only. This is exactly decision 5's predicates; no extra rule. | Ruling D65. |
| 16 | `PUT …/scores` row `points: null` deletes that score (ruling R2); absent `points` stays `is required`. `PATCH` assessment `dueOn: null` clears the date (ruling R8; the one D27 exception), `""` is a 400. Responses never carry `null` (D16): `dueOn`, `overrideReason`, `percent`, `letter`, `points` are omitted when unset (ruling R5's "nullable" read as "optional", per R8/D16). | Rulings R2, R5, R8. |

## 1. Migration `apps/api/migrations/0005_grading.sql` (L1a)

Plain SQL, no `begin`/`commit` (`pg.Migrate` wraps each file). Run as `unicourse_owner`; the four new tables are covered by `0004`'s `alter default privileges for role unicourse_owner in schema public grant select, insert, update, delete on tables to unicourse` (confirmed: `assertGrants` in `TestMigrate` walks every table and will fail if not). The function needs no grant (EXECUTE is granted to PUBLIC by default; it is `security invoker`, so RLS applies to the caller).

```sql
-- Spec 4 §3: grading. Percent and points are numeric; the API never converts them through floats.
alter table courses add column credits numeric(3,1) not null default 3.0 check (credits between 0 and 20);

-- One row per letter; the letter of a percent is the row with the greatest min_percent <= percent.
create table grade_scales (
  id uuid primary key default gen_random_uuid(),
  university_id uuid not null references universities(id) on delete cascade,
  letter text not null check (char_length(letter) between 1 and 10),
  min_percent numeric(5,2) not null check (min_percent between 0 and 100),
  points numeric(3,2) not null check (points >= 0),
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now(),
  unique (university_id, letter),
  unique (university_id, min_percent)
);

-- The US plus/minus 4.0 preset (spec §1). Called by this migration and by unicourse-admin create-university.
create function seed_us_grade_scale(u uuid) returns void language sql as $$
  insert into grade_scales (university_id, letter, min_percent, points)
  select u, v.letter, v.min_percent, v.points from (values
    ('A', 93.00, 4.00), ('A-', 90.00, 3.70), ('B+', 87.00, 3.30), ('B', 83.00, 3.00), ('B-', 80.00, 2.70),
    ('C+', 77.00, 2.30), ('C', 73.00, 2.00), ('C-', 70.00, 1.70), ('D+', 67.00, 1.30), ('D', 63.00, 1.00),
    ('D-', 60.00, 0.70), ('F', 0.00, 0.00)) as v(letter, min_percent, points)
$$;

-- Existing universities get the preset now, before row level security is switched on for the table
-- (the owner is subject to forced RLS and has no app.university_id here).
select seed_us_grade_scale(id) from universities;

create table assessments (
  id uuid primary key default gen_random_uuid(),
  university_id uuid not null references universities(id) on delete cascade,
  section_id uuid not null,
  name text not null check (char_length(name) between 1 and 100),
  max_points numeric(7,2) not null check (max_points > 0 and max_points <= 10000),
  weight numeric(5,2) not null check (weight between 0 and 100),
  due_on date,
  published boolean not null default false,
  position integer not null default 0 check (position >= 0),
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now(),
  unique (university_id, section_id, name),
  unique (university_id, id),
  foreign key (university_id, section_id) references sections (university_id, id) on delete cascade
);

-- user_id must be enrolled in the assessment's section: checked by the handler (spec §3), not here,
-- so removing an enrollment keeps the scores (hidden from the gradebook until re-enrolled).
create table scores (
  id uuid primary key default gen_random_uuid(),
  university_id uuid not null references universities(id) on delete cascade,
  assessment_id uuid not null,
  user_id uuid not null references users(id) on delete cascade,
  points numeric(7,2) not null check (points >= 0),
  graded_by uuid not null references users(id),
  graded_at timestamptz not null default now(),
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now(),
  unique (university_id, assessment_id, user_id),
  foreign key (university_id, assessment_id) references assessments (university_id, id) on delete cascade
);
create index on scores (user_id);

-- A snapshot: letter and points are copied from the scale at finalization; scale edits never touch it.
create table final_grades (
  id uuid primary key default gen_random_uuid(),
  university_id uuid not null references universities(id) on delete cascade,
  section_id uuid not null,
  user_id uuid not null references users(id) on delete cascade,
  status text not null check (status in ('graded', 'incomplete', 'withdrawn')),
  percent numeric(5,2) check (percent >= 0),
  letter text check (char_length(letter) between 1 and 10),
  points numeric(3,2) check (points >= 0),
  override_reason text check (char_length(override_reason) between 1 and 500),
  finalized_by uuid not null references users(id),
  finalized_at timestamptz not null default now(),
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now(),
  check (case when status = 'graded' then percent is not null and letter is not null and points is not null
              else percent is null and letter is null and points is null end),
  unique (university_id, section_id, user_id),
  foreign key (university_id, section_id) references sections (university_id, id) on delete cascade
);
create index on final_grades (user_id);

alter table grade_scales enable row level security;
alter table grade_scales force row level security;
create policy tenant_isolation on grade_scales
  using (university_id = nullif(current_setting('app.university_id', true), '')::uuid)
  with check (university_id = nullif(current_setting('app.university_id', true), '')::uuid);

alter table assessments enable row level security;
alter table assessments force row level security;
create policy tenant_isolation on assessments
  using (university_id = nullif(current_setting('app.university_id', true), '')::uuid)
  with check (university_id = nullif(current_setting('app.university_id', true), '')::uuid);

alter table scores enable row level security;
alter table scores force row level security;
create policy tenant_isolation on scores
  using (university_id = nullif(current_setting('app.university_id', true), '')::uuid)
  with check (university_id = nullif(current_setting('app.university_id', true), '')::uuid);

alter table final_grades enable row level security;
alter table final_grades force row level security;
create policy tenant_isolation on final_grades
  using (university_id = nullif(current_setting('app.university_id', true), '')::uuid)
  with check (university_id = nullif(current_setting('app.university_id', true), '')::uuid);

create trigger grade_scales_set_updated_at before update on grade_scales for each row execute function set_updated_at();
create trigger assessments_set_updated_at before update on assessments for each row execute function set_updated_at();
create trigger scores_set_updated_at before update on scores for each row execute function set_updated_at();
create trigger final_grades_set_updated_at before update on final_grades for each row execute function set_updated_at();
```

Indexes: section/assessment lookups use the tenant uniques (RLS adds `university_id = …`, so `(university_id, section_id, …)` and `(university_id, assessment_id, …)` serve `where section_id = $1`), as `section_staff` does. `(user_id)` on `scores` and `final_grades` serves `/me/grades`. Nothing is paged, so no `(university_id, created_at, id)` index.

Counts after `0005`: **22 tables** besides `schema_migrations` (18 + 4), **17 tenant tables** (13 + 4).

## 2. Contract `apps/api/openapi.json` (all of it in L1a; regenerate `apps/web/src/api/types.ts` with `npm run generate` in `apps/web`)

Conventions per P0-L4 §2: request schemas set `"additionalProperties": false`, response schemas do not; every property has an `example`; optional = not in `required`; arrays always present. Number fields are `"type": "number"`.

### 2.1 Widenings of existing schemas

- `Course.properties.credits`: `{ "type": "number", "minimum": 0, "maximum": 20, "example": 3, "description": "Credit hours, at most one decimal." }`; append `"credits"` to `Course.required`.
- `CourseCreate.properties.credits`: `{ "type": "number", "minimum": 0, "maximum": 20, "example": 3, "description": "At most one decimal. Omitted means 3.0." }` (not required).
- `CourseUpdate.properties.credits`: `{ "type": "number", "minimum": 0, "maximum": 20, "example": 4, "description": "At most one decimal." }`.
- `ImportRow` and `ImportCounts` are unchanged (decision 7).
- `AuditEntry.properties.action.pattern`: `"^[a-z_]+\\.[a-z_]+$"`.
- `AuditEntry.properties.entityType.enum` and `components.parameters.entityType.schema.enum`: append `"assessment", "final_grade", "grade_scale"`.
- Descriptions of `previewCourseImport` and `importCourses`: in the column list replace `required departmentCode, code, title` (whatever the current wording of the required list is) by appending `; optional credits (0 to 20, one decimal; empty means 3.0; ignored for existing courses)`, and append to the row messages `"credits must be a number", "credits must have at most 1 decimal", "credits must be between 0 and 20"`.

New parameter in `components.parameters`:

```json
"assessmentId": { "name": "assessmentId", "in": "path", "required": true, "schema": { "type": "string", "format": "uuid" } }
```

| `auth.NormalizeEmail` fails | `error`, `invalid email` |
| email not enrolled and not a member | `error`, `unknown email` |
| member but not enrolled | `error`, `not enrolled in this section` |
| `tenant.Decimal("points", json.Number(cell), 2, "0", maxScore(a))` error | `error`, `"points " + fe.Message` |
| no current score | `add`, Ref `scoreRef` |
| current score equal (`rat(old).Cmp(rat(new)) == 0`) | `exists` |
| current score differs | `update`, message `"<old> → <new>"` (both 2-decimal strings), Ref `scoreRef` |

Applier: `setScores(ctx, tx, s, a, refs as []scoreIn)` (same upsert and the same single `score.set` audit row as `PUT`). All-or-nothing comes from `csvimport.Apply` (any `error` row fails the commit with `line:<n>` details, nothing written).

## 8. Simplifications and their ceilings

| Simplification | Ceiling | Upgrade |
|---|---|---|
| Gradebook, final grades and `/me/grades` unpaginated, 4 statements each, computed per request | ~2,000 students × 50 assessments (100k cells, a few MB) per gradebook response | page students; cache running percent |
| Course credits are read live in GPA, not snapshotted in `final_grades` (spec §3 has no column) | editing a course's credits changes every past GPA that includes it | `final_grades.credits` copied at finalization |
| Section delete cascades its assessments, scores and final grades | an admin deleting a section erases transcript rows (audited as `section.delete` only) | `on delete restrict` on `final_grades` + 409 in `deleteSection` |
| No score deletion (spec §5 has none) | a mistaken score can only be changed, and it counts in the running percent | `DELETE …/scores/{userId}` |
| Scores of unenrolled students are kept and hidden | re-enrolling brings them back | `on delete cascade` from enrollments via `scores.section_id` |
| `Accept` negotiated by substring | no q-values (`text/csv;q=0` still gets CSV) | `mime.ParseMediaType` per entry |
| `json.Number` also accepts a JSON string holding a number (`"87.5"`) | lenient input | strict number type with its own `UnmarshalJSON` |
| No section lock in finalize | a score written during finalization may miss the snapshot | `select … for update` on the section |
| `finalized_by` keeps the finalizer after an override; the overrider is in the audit only | the row alone does not say who overrode | `overridden_by` column |
| `maxPoints` edits do not re-check existing scores against 2 × max | a score may exceed 2 × the new max | validate on PATCH |
| Scale letters compared byte-exact, case-sensitive | `a` and `A` are different letters | normalise on PUT |
| "At least one scale row" is enforced by PUT validation and the seeds, not the database | a manual SQL delete can empty a scale; finalize then answers 409 | constraint trigger |
| CSV formula escape prefixes `'` | the cell shows a leading quote in non-spreadsheet tools | none needed |
