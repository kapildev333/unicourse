# P1-L1 design: Authentication (`apps/api/internal/auth`)

Spec: `docs/specs/2026-10-05-platform-core-and-staffing.md` §4, §5, §6, §9, §10. Plan: Task 5. Builds on Task 1 (`config`, `httpx`, `httpx.Router` from Task 4) and Task 2 (`pg`, schema, `testdb`).

Workers: every choice is made here. If something below does not compile against the real `httpx`/`pg`, stop and report; do not redesign.

## 0. Deviations from the plan's Task 5 interface (all deliberate)

| Plan says | This design | Why |
|---|---|---|
| `SignIn(ctx, tx, email, displayName)` | `SignIn(ctx, db *sql.DB, email, displayName string) (userID string, err error)` | SignIn must open a `pg.WithUserTx` (needs `app.email` set) and switch universities inside it; a caller-supplied tx cannot have the right settings. One tx, all-or-nothing. |
| `SessionStore{db, secret}` | `SessionStore{DB *sql.DB}` | Tokens are 256-bit random; SHA-256 needs no secret. |
| Redirect reasons, `/me` shape, `next` | As fixed by the P0-L4 contract (`docs/design/P0-L4.md`, contract wins): failures redirect with `?error=<Error.code>`, `/me` items are `{ university: {id, slug, name}, role, departmentIds }`, `next` accepted on start and magic-link | `next` is validated by `safeNext` (§2) so it cannot become an open redirect. |
| Spec §10 "OIDC state lives in Postgres" | HMAC-signed cookie | Equally stateless for the API (any process can verify it), no table, no cleanup. Orchestrator to note in PLAN.md. |
| Domain rule "for this university" | Evaluated globally (any university's domain, or any pending invitation) | See §2. |
| Plan's `MagicLinks.Send` lowercases | All normalisation is `auth.NormalizeEmail`, called at every entry (Send, SignIn); tenant/csvimport import it | Review Focus 1: one place. |
| — | New `pending_section_staff` table, `pg.WithUserTx`, `pg.SetUniversity`, three SELECT policies | §3; requested from P0-L2 in `.claude/lanes/P1-L1.md`. |

`x/crypto` is not used: SHA-256 (`crypto/sha256`), HMAC (`crypto/hmac`), randomness (`crypto/rand`) are stdlib and there is no password hashing.

## 2. University selection and the allow rule

**Rule (one function, `allowed`), evaluated after the email is verified (OIDC callback, magic-link consume) and before mailing (magic-link send):**

```sql
select exists (select 1 from universities where $1 = any(allowed_email_domains))
    or exists (select 1 from invitations where email = $2 and accepted_at is null and expires_at > now())
-- $1 = domain (text after the last '@'), $2 = normalised email; tx = WithUserTx(email) so invitations_by_email applies
```

False → `ErrNotAllowed` (403 `forbidden`, "your email is not allowed for this university").

**Why global, not per chosen university.** A session grants nothing by itself: every tenant route goes through tenant middleware, which requires an active membership in that slug's university. So "which university is the sign-in for" only matters for where the browser lands. Evaluating globally removes every ambiguity the brief lists:
- several universities share a domain → irrelevant, the user simply has whatever memberships they have;
- invited adjunct whose domain matches no university and who gives no slug → allowed by the invitation clause;
- slug given that does not match → still signs in, lands on another membership or `/sign-in?error=no_membership`.

Domain match does **not** create a membership (spec has no auto-join; students arrive via invitations from roster import). Ceiling: a university that wants "anyone at @x.edu joins as member" needs an auto-join flag on `universities`; add when a customer asks.

**`safeNext(s string) string`** (handler.go): returns `s` if it starts with `/`, does not start with `//` or `/\`, has no `\r`, `\n` or `\t`, and is at most 512 bytes; else `""`. Applied wherever `next` enters (start body, magic-link body, magic-link GET query).

**Landing page** (`landing(ctx, userID, slug, next)`, in handler.go): if `next != ""` and the user has at least one active membership → `{WebBase}{next}` (the web route itself enforces membership). Otherwise memberships from `/me` query (active only, ordered by `universities.name`). If `slug` matches one → `{WebBase}/{slug}/me`; else first → `{WebBase}/{first.slug}/me`; none → `{WebBase}/sign-in?error=no_membership`.

## 3. RLS and cross-university reads (decided; requested from P0-L2)

**Problem.** `invitations`, `memberships`, `department_admins` are tenant tables under FORCE RLS. SignIn must find invitations for an email in any university; `GET /me` must list a user's memberships in every university. A platform tx (no `app.university_id`) sees none of them.

**Options weighed.**
1. *Loop universities, `WithTx` each.* No schema change, but O(universities) queries per sign-in and per `/me` (100 universities → 100 round trips on every page load of `/me`), and SignIn would not be one transaction.
2. *SECURITY DEFINER function.* Does not work here: the API role owns the tables (it runs migrations) and FORCE RLS applies to owners; only a separate BYPASSRLS owner role would help, which means a second role in compose, CI and production. More moving parts and a function that bypasses all tenancy.
3. *Extra permissive SELECT-only policies keyed on `app.user_id` / `app.email`.* O(1), one transaction, no new role. **Chosen.**

**Why 3 keeps the spec's guarantee.** Permissive policies are OR-ed, so the guarantee holds only if the extra keys are never set in a tenant transaction. Enforced structurally:
- `pg.WithTx` sets only `app.university_id`; `pg.WithUserTx` sets only `app.user_id`/`app.email`. Both use `set_config(..., true)` (transaction-local), so nothing survives on a pooled connection.
- The extra policies are `for select` only. Every write (accept invitation, insert membership, `department_admins`, `section_staff`) still needs `tenant_isolation`'s `with check`, which SignIn satisfies by `pg.SetUniversity(tx, invitation.university_id)` per invitation.
- What a `WithUserTx` can see across universities: the caller's own memberships and department-admin rows, and invitations addressed to the email the server itself verified. Nothing else (sections, enrollments, other users' memberships) has a non-tenant policy. A missed predicate inside domain packages cannot reach this path: domain packages only get `WithTx`.

**`nullif` gotcha.** After a custom setting has been set once in a session, `current_setting(name, true)` returns `''` rather than NULL in later transactions, and `''::uuid` raises 22P02. Every policy (including the plan's `tenant_isolation`) uses `nullif(current_setting(..., true), '')`.

**Exact P0-L2 requirements** (also in the lane log, Requests):


## 4. Tokens, expiry, single use

All three token kinds: `newToken()` = 32 bytes from `crypto/rand`, `base64.RawURLEncoding` (43 chars) to the client, `sha256.Sum256([]byte(token))` stored as `bytea`. Lookups are by hash (`where token_hash = $1`); the plaintext never reaches the database or logs. Malformed input (not 43 chars of the URL alphabet) is treated as unknown, without querying.

| Token | Lifetime | Single use / race safety | Failure → result |
|---|---|---|---|
| session | 30 days; sliding: if `last_seen_at < now() - 1 day`, `update sessions set last_seen_at = now(), expires_at = now() + interval '30 days' where id = $1`, and the cookie is re-set with `Max-Age` 30 d | n/a; `Revoke` = `delete ... where token_hash = $1` | missing, unknown, expired → `httpx.Unauthenticated()` (401 `unauthenticated`). Expired rows are deleted on lookup (`delete ... where token_hash=$1 and expires_at <= now()`) — no sweeper. |
| magic link | 15 minutes | `update magic_links set used_at = now(), updated_at = now() where token_hash = $1 and used_at is null and expires_at > now() returning email` — atomic, exactly one concurrent consumer wins. On 0 rows: `select used_at, expires_at from magic_links where token_hash = $1` to classify. | unknown → 400 `validation_failed` "invalid link"; `used_at` not null → "link already used"; expired → "link expired". Used takes precedence over expired. |
| invitation | 14 days (set by Task 6) | Accepted by verified email, not by token (§5): per invitation `update invitations set accepted_at = now(), updated_at = now() where id = $1 and accepted_at is null and expires_at > now() returning role, department_ids` — 0 rows (concurrent sign-in won, or expired) → skip it. | expired invitation: silently not accepted; if it was the only reason the email was allowed, SignIn returns `ErrNotAllowed` (403). |

Browser-facing GETs (magic-link consume, OIDC callback) never render JSON for expected failures: they 302 to `{WebBase}/sign-in?error=<code>` with the closed set fixed by the P0-L4 contract: any link failure → `validation_failed`; not allowed → `forbidden`; any OIDC failure → `unauthenticated`; signed in but no active membership → `no_membership`. No free-text message travels in the URL (avoids content spoofing); the web shows fixed copy per code ("This link is invalid, used or expired. Request a new one." for `validation_failed`). Unexpected errors (DB down) still go through `httpx.WriteError` (500 envelope). `Consume` itself returns the distinct `*httpx.Error` messages above (pinned by `magic_test`, and logged at Info by the handler), so Review Focus 5 is asserted at the function level; at the HTTP level all three are `error=validation_failed`. Ceiling: the browser cannot tell "used" from "expired"; both need the same action (request a new link).

## 5. Email normalisation (Review Focus 1)

```go
func NormalizeEmail(s string) (string, error) {
    e := strings.ToLower(strings.TrimSpace(s))
    a, err := mail.ParseAddress(e)            // net/mail
    if err != nil || a.Address != e || strings.Count(e, "@") != 1 || strings.HasPrefix(e, "@") || strings.HasSuffix(e, "@") {
        return "", httpx.Validation(httpx.FieldError{Field: "email", Message: "must be a valid email address"})
    }
    return e, nil
}
```

Called by `MagicLinks.Send`, `SignIn` (so OIDC emails pass through it too) and, outside this lane, by `tenant.CreateInvitation` and `csvimport`. Nothing else lowercases emails. The DB `check (email = lower(email))` catches any caller that forgets.

## 6. Flows

Cookies (all set via `http.SetCookie`):

| Cookie | Value | Path | Max-Age | Flags |
|---|---|---|---|---|
| `unicourse_session` | session token | `/` | 30 d (2592000) | HttpOnly, Secure, SameSite=Lax |
| `unicourse_oidc` | signed state (provider, slug, next, nonce, PKCE verifier, exp) | `/api/v1/auth/oidc` | 600 | HttpOnly, Secure, SameSite=Lax |

Clearing = same name/path, `MaxAge: -1`. `Secure` is always on, also in dev and e2e: Chromium and Firefox treat `http://localhost` as a secure context and store Secure cookies there, and Playwright runs Chromium; Go's `net/http/cookiejar` does drop Secure cookies on http, so handler tests use `httptest.NewRecorder` and copy `Set-Cookie` into the next request by hand (never a jar). Ceiling: Safari on `http://localhost` drops them — develop in Chrome/Firefox, or behind https. No `__Host-` prefix (avoids browser variance on localhost). Lax is required (not Strict) because the callback and the magic-link GET are top-level navigations from another site.

**OIDC start** — `POST /api/v1/auth/oidc/{provider}/start`, body `{ "slug"?: string, "email"?: string, "next"?: string }` (`httpx.DecodeJSON`).
1. Unknown provider (not in `Providers`) → `httpx.NotFound("provider")`. Exactly one of `slug`/`email` (contract): neither or both → 400 `validation_failed` field `slug`, message "give exactly one of slug or email". `email` goes through `NormalizeEmail` (400 field `email`). `slug` is not looked up (unknown slug just does not match a membership at landing). `next = safeNext(next)`.
2. `nonce` = 32 random bytes base64url; `verifier = oauth2.GenerateVerifier()`.
3. Set `unicourse_oidc` = `signState(secret, {provider, slug, next, nonce, verifier, exp: now+10min})`.
4. `url = p.OAuth.AuthCodeURL(nonce, oidc.Nonce(nonce), oauth2.S256ChallengeOption(verifier))`, plus `oauth2.SetAuthURLParam("login_hint", email)` when given and `("prompt","select_account")`.
5. 200 `{ "url": url }`. The web does `window.location = url`.

Nonce and PKCE are both included: each is one option call. PKCE binds the code to this browser's cookie (code injection), nonce binds the ID token to it (token replay); the same random value serves as OAuth `state` and OIDC nonce.

**State format.** `base64url(json(state)) + "." + base64url(hmac_sha256(secret, payloadPart))`. `parseState` splits on the last `.`, verifies with `hmac.Equal`, decodes, rejects `exp < now`. Secret = `[]byte(cfg.SessionSecret)`.

**OIDC callback** — `GET /api/v1/auth/oidc/{provider}/callback?code&state` (or `?error=` from the IdP).
1. Read and immediately clear `unicourse_oidc`. Any of these → 302 `sign-in?error=unauthenticated` (log the cause at Info): cookie missing/invalid/expired; `st.Provider != {provider}`; `query state != st.Nonce`; IdP `error` param; `Exchange(ctx, code, oauth2.VerifierOption(st.Verifier))` fails; no `id_token` in the token response; `Verifier.Verify` fails; `idToken.Nonce != st.Nonce`; email claims fail the provider rule below.
2. Claims `{ email, email_verified, name, tid, xms_edov }`.
   - google: require `email_verified == true`.
   - microsoft: require `email != ""` and `xms_edov == true` (email domain owner verified). Microsoft's `email` claim is otherwise user-editable in some tenants (the "nOAuth" takeover); the app registration must emit the `email` and `xms_edov` optional claims (ops task, see risks). Also require `iss == "https://login.microsoftonline.com/" + tid + "/v2.0"` (issuer check is skipped in the verifier, see below).
3. `userID, err := SignIn(ctx, db, email, name)`; `ErrNotAllowed` → 302 `sign-in?error=forbidden`.
4. `Sessions.Create`, set cookie, 302 `landing(userID, st.Slug, st.Next)`.

**Providers.** `NewProviders` builds only those whose client id is set (both may be absent in dev/test; then the route returns 404 for them). Redirect URL `{BaseURL}/api/v1/auth/oidc/{name}/callback`. Scopes `openid email profile`.
- google: issuer `https://accounts.google.com`.
- microsoft: `ctx = oidc.InsecureIssuerURLContext(ctx, "https://login.microsoftonline.com/{tenantid}/v2.0")`, `oidc.NewProvider(ctx, "https://login.microsoftonline.com/common/v2.0")` (the common discovery document advertises the templated issuer, which otherwise fails go-oidc's check), verifier `&oidc.Config{ClientID: id, SkipIssuerCheck: true}`; issuer checked manually in step 2.
- `newProvider(ctx, name, issuer, ...)` is the shared constructor; tests call it with the fake issuer URL and name `"google"` so the google claim rule applies.

**Magic-link send** — `POST /api/v1/auth/magic-link`, body `{ "email": string, "next"?: string }`.
1. `NormalizeEmail` → 400 on invalid; `next = safeNext(next)`.
2. Rate limit: `IPLimit.Allow("ip:"+host)` then `EmailLimit.Allow("email:"+email)`; either false → `httpx.RateLimited()` (429). Host = `net.SplitHostPort(r.RemoteAddr)`. No forwarded header is trusted; ceiling: behind a load balancer every request shares one IP — then trust exactly one configured header (new env var, PLAN decision).
3. `MagicLinks.Send`: in one `WithUserTx("", email)`: if `!allowed` → return nil (no row, no mail). Else insert `magic_links(email, token_hash, expires_at = now() + interval '15 minutes')`, commit, then `Mailer.Send(email, "Your UniCourse sign-in link", text)`; text contains the line `{BaseURL}/api/v1/auth/magic-link/{token}`, plus `?next={url.QueryEscape(next)}` when `next != ""`. `next` is not stored: it is validated again on the GET, so editing it in the link gains nothing. Signature becomes `Send(ctx, email, next string) error`. A mailer error is returned (500): the user must know the mail did not go out.
4. 202, empty body — identical for allowed and not-allowed emails (no enumeration).

**Magic-link consume** — `GET /api/v1/auth/magic-link/{token}`: `Consume` (failures → 302 reasons, §4) → `SignIn(ctx, db, email, "")` (`ErrNotAllowed` → `error=forbidden`; the invitation may have been revoked between send and click) → session cookie → 302 `landing(userID, "", safeNext(r.URL.Query().Get("next")))`.

**Sign-out** — `POST /api/v1/auth/sign-out`: if cookie present, `Revoke`; always clear cookie; 204. Not behind `RequireSession` (idempotent; a stale cookie must still be clearable).

**`GET /api/v1/me`** — behind `RequireSession`. `WithUserTx(actor.UserID, "")`:
```sql
select u.id, u.slug, u.name, m.role,
       coalesce(array(select da.department_id::text from department_admins da
                      where da.user_id = m.user_id and da.university_id = m.university_id
                      order by da.department_id), '{}')
from memberships m join universities u on u.id = m.university_id
where m.user_id = $1 and m.status = 'active'
order by u.name
```
plus `select id, email, display_name from users where id = $1`. Response (Go struct tags; JSON exactly):
`{ "user": { "id", "email", "displayName" }, "memberships": [ { "university": { "id", "slug", "name" }, "role", "departmentIds": [] } ] }` (P0-L4 contract) — `memberships` and `departmentIds` are `[]`, never null.

**`RequireSession`** — read cookie; absent → `httpx.WriteError(w, r, httpx.Unauthenticated())`; `Lookup` error → same (unexpected DB errors → 500); `slid` → `setSessionCookie(w, token)`; `httpx.WithUserID(ctx, a.UserID)` (P0-L1: mutates the log record, returns nothing); `next.ServeHTTP(w, r.WithContext(withActor(ctx, a)))`. Exported for `tenant.Middleware` (Task 6), which runs after it. Lookup runs in `WithPlatformTx`: `select s.id, s.user_id, u.email, s.last_seen_at from sessions s join users u on u.id = s.user_id where s.token_hash = $1 and s.expires_at > now()`.

## 7. `SignIn` semantics

One `pg.WithUserTx(ctx, db, "", email)`; any error rolls everything back.
1. `email = NormalizeEmail(email)`; `allowed` false → `ErrNotAllowed`.
2. Upsert user:
   ```sql
   insert into users (email, display_name) values ($1, $2)
   on conflict (email) do update
     set display_name = case when users.display_name = '' then excluded.display_name else users.display_name end,
         updated_at = now()
   returning id
   ```
   (OIDC fills an empty name; never overwrites one; magic link passes `''`.)
3. `select id, university_id from invitations where email = $1 and accepted_at is null and expires_at > now() order by created_at` (visible via `invitations_by_email`). Collect into a slice first, close rows.
4. For each: `pg.SetUniversity(tx, uni)`; claim it with the UPDATE in §4 (0 rows → continue); then
   ```sql
   insert into memberships (university_id, user_id, role, status) values ($1, $2, $3, 'active')
   on conflict (university_id, user_id) do update set status = 'active', updated_at = now(),
     role = case when array_position(array['member','dept_admin','admin'], excluded.role)
                    > array_position(array['member','dept_admin','admin'], memberships.role)
            then excluded.role else memberships.role end;
   insert into department_admins (university_id, department_id, user_id)
     select $1, d, $2 from unnest($3::uuid[]) d on conflict (department_id, user_id) do nothing;   -- only when role = dept_admin
   insert into section_staff (university_id, section_id, user_id, role)
     select university_id, section_id, $2, role from pending_section_staff where invitation_id = $1
     on conflict (section_id, user_id) do nothing;
   ```
   A role only ever goes up on acceptance (an admin who is also invited as member stays admin). `department_ids` pointing at a since-deleted department fails the FK → whole sign-in fails (500). Ceiling, accepted: Task 6 should delete/trim invitations when a department is deleted; noted for P1-L2.
5. Return user id. Idempotent: a second call finds no pending invitations and the upsert is a no-op.

Exported because P1-L2's invitation test signs in through it and Task 10's staff tests rely on it.

## 8. Mailer

- `LogMailer.Send` logs one line at Info: `l.Info("mail", "to", to, "subject", subject, "text", text)`. Under the JSON handler this is one JSON object with keys `msg:"mail"`, `to`, `subject`, `text`. **Contract for tests and e2e:** find the line with `"msg":"mail"` and `"to":"<email>"`; the URL is the first match of `https?://\S+` in `text` (magic: `.../api/v1/auth/magic-link/<43 chars>`; invitation: `.../invite/<43 chars>?email=...`). Each URL is on its own line of `text`.
- `NewSMTPMailer(url)`: `smtp://user:pass@host:port?from=noreply@x.edu` (`smtps` not supported; STARTTLS is negotiated by `net/smtp.SendMail` when the server offers it). Parse with `net/url`; `from` query param required, else error at startup. `PlainAuth` when userinfo present. Message: `From`, `To`, `Subject`, `MIME-Version: 1.0`, `Content-Type: text/plain; charset=utf-8`, blank line, text, CRLF line endings. Wiring: `cfg.SMTPURL == ""` → `LogMailer{L: logger}`.
- Ceiling: `net/smtp` is frozen and sends synchronously in the request; move to a queue/provider API when mail volume or latency matters.

**Invitation link** (`InvitationURL`): `{BaseURL}/invite/{token}?email={url.QueryEscape(email)}`. The web `/invite/{token}` page redirects to `/sign-in?email=...` (prefilled), per plan Task 8. The token is stored hashed (spec) but acceptance is by verified email on sign-in, which is stronger proof than holding the link. Ceiling: an invitee whose IdP email differs from the invited address (alias) cannot accept; then add a token-claim endpoint. `tenant.CreateInvitation` (Task 6) and the CLI (Task 7) generate the token with their own `crypto/rand` + `sha256` (or P1-L2 may call an exported `auth.NewToken` — export `newToken` as `NewToken` if they ask).

## 9. Rate limiter

Fixed window per key (simpler than a token bucket, same guarantee for "N per hour"): `bucket{start time.Time; n int}`. `Allow`: lock; if absent or `now - start >= window` → reset to `{now, 0}`; if `n >= max` → false; `n++` → true. When `len(hits) > 10000`, delete expired buckets in the same call. Header comment: `// ponytail: in-memory limiter, move to Postgres if more than one API process`. `now` is a field so tests advance time. Wiring: `NewLimiter(5, time.Hour)` for email, `NewLimiter(20, time.Hour)` for IP. Only `POST /auth/magic-link` is limited (OIDC start costs us nothing; the IdP limits itself; consume tokens are 256-bit).

## 10. Routes and wiring

Registered by `auth.Register(r, d)` through `httpx.Router.Handle` (Task 4); handlers are `httpx.Handler` (return error). Session-guarded routes wrap with `RequireSession`; if `Router.Handle` takes only `httpx.Handler`, do the cookie lookup at the top of the `/me` handler with the same helper `RequireSession` uses (`actorFromRequest(w, r, store) (Actor, error)`) — the worker picks whichever compiles against the real `Router`, behaviour is identical.

## 14. Simplifications and their ceilings

| Simplification | Ceiling | Upgrade |
|---|---|---|
| Signed state cookie instead of a Postgres table (spec §10 deviation) | none for correctness; a stolen cookie is replayable for 10 min only together with the IdP code | table only if state must be revocable |
| Allow rule evaluated globally, no auto-join by domain | universities wanting self-service join | `universities.auto_join_role` |
| Invitations accepted by verified email, token unused for acceptance | invitee whose IdP email ≠ invited address cannot accept | token-claim endpoint |
| In-memory fixed-window limiter, `RemoteAddr` only | one API process; behind a proxy/NAT all clients share a key (campus NAT may hit 20/h) | Postgres counter table; trusted-proxy header env var |
| Synchronous `net/smtp` | mail latency in request; no retries | queue or provider API |
| Always-`Secure` cookies | Safari on `http://localhost` | https in dev |
| Invitations applied only at sign-in | an already signed-in user sees a new invitation only after their next sign-in | call acceptance from `CreateInvitation` when the user exists |
| Expired sessions/magic links deleted lazily (sessions) or never (magic links) | `magic_links` grows ~1 row per sign-in | nightly `delete where expires_at < now() - interval '1 day'` in the admin CLI |

## 15. Open risks (for the orchestrator)

1. **Link scanners burn magic links.** Outlook Safe Links and similar scanners GET every URL in an email; with consume-on-GET (contract) the user's click then lands on `error=validation_failed`. Common at universities on Microsoft 365. Fix: the email link points to a web page (`/sign-in/magic?token=`) that POSTs the token; needs a contract change. Recommend deciding before P1-L4 builds the page.
2. **Microsoft email claim.** Accepting Microsoft sign-ins safely requires the `email` and `xms_edov` optional claims in the app registration; without them every Microsoft sign-in fails closed (`error=unauthenticated`). Personal Microsoft accounts may not carry `xms_edov` and are then rejected. Ops checklist item for the README.
3. **P0-L2 must land §3 exactly** (policies with `nullif`, `pending_section_staff`, `WithUserTx`, `SetUniversity`). If P0-L2 has already merged without them, P1-L1a starts with a `0002_auth.sql` migration plus the two `pg` functions (owner: P0-L2 files, so the orchestrator assigns it).
4. **`SESSION_SECRET` length** is not validated by `config.Load`; a short secret weakens the state HMAC. One-line check (≥ 32 bytes) in P0-L1's `config`.

## 16. Orchestrator amendments (2026-10-06, binding; they override the sections above)

1. **D11 magic link.** `GET /api/v1/auth/magic-link/{token}` does not consume the token: it answers `200 text/html` with a minimal page (no scripts, no external assets) containing one form `method="post"` to the same URL and a "Continue signing in" button; an unknown/expired/used token still renders the page (the POST reports the failure). `POST /api/v1/auth/magic-link/{token}` consumes and redirects exactly as §6 described for the GET. Both are in `openapi.json` (`confirmMagicLink`, `consumeMagicLink`).
2. **Self policies are off once a university is set.** `memberships_self`, `department_admins_self` and `invitations_by_email` apply only while `app.university_id` is unset. Inside one `pg.WithUserTx`, read everything that needs them (pending invitations by email, own memberships) BEFORE the first `pg.SetUniversity`; after it, only that university's rows are visible.
3. **Pending enrollments.** `SignIn` also applies `pending_enrollments (invitation_id, section_id)` on acceptance: `insert into enrollments (university_id, section_id, user_id) select … on conflict do nothing`, in the same place it applies `pending_section_staff`. Pinned by a test in P1-L1b.
4. **D13 rate limit.** Magic-link: 5 per email per hour, 300 per IP per hour.
5. **Exports requested by P1-L2:** `auth.Authenticate(w http.ResponseWriter, r *http.Request, s *SessionStore) (Actor, error)` (reads the session cookie, slides expiry, returns `httpx.Unauthenticated()` when absent or expired, calls `httpx.WithUserID`) and `auth.NewToken() (token string, hash []byte, err error)`. Built in P1-L1a.
6. **Route wiring** is `internal/app.NewRouter(deps)` (not `httpx.RegisterAll`); P1-L1c adds the auth fields to `app.Deps`, calls `auth.Register`, mounts the router in `cmd/api/main.go` under `/api/v1/`, and removes its seven routes from `internal/app/pending_routes.txt`.
7. **`updated_at`** is maintained by a database trigger; never set it in SQL.
8. **Config:** `config.Load` already rejects a `UNICOURSE_SESSION_SECRET` shorter than 32 bytes.
9. **Audit rows on acceptance (P1-L5).** For each invitation `SignIn` actually claims, it writes, in the same transaction and under that invitation's university, with the signing-in user as actor: `invitation.accept` (entity `invitation`, id = invitation id, `after` = `{email, role, departmentIds}`); `membership.create` (membership inserted) or `membership.update` (role raised and/or `invited` to `active`; `before` = `{role, status}`), entity `membership`, `after` = `{role, status, departmentIds}` with the department ids actually inserted into `department_admins`; one `staff.create` per `section_staff` row inserted from `pending_section_staff` (entity `staff`, id = section id, `after` = `{userId, role}`); one `enrollment.create` per enrollment inserted from `pending_enrollments` (entity `enrollment`, id = section id, `after` = `{userId}`). Nothing is written for conflicts that changed nothing, for an already-accepted invitation, or for a failed sign-in.
