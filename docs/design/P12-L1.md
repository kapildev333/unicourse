# P12-L1 design: Postman collection generated from the OpenAPI spec

Designer, 2026-10-07. The owner asked for "OpenAPI with Postman", with a full collection committed and kept in sync with the spec (owner, in session). No spec number yet: the orchestrator records the decisions in §9 (proposed D109 to D111) and a short Spec 8 (or a Spec 7 amendment) before briefing a worker. The lane number P12-L1 is provisional; renumber freely.

Worker scope: `apps/web/package.json`, `apps/web/package-lock.json`, `apps/web/scripts/postman.mjs` (new), `docs/postman/**` (new), `.github/workflows/ci.yml` (two lines in the `web` job), `README.md` (one new section). Nothing under `apps/api`: the spec does not change.

## 1. What exists

- `apps/api/openapi.json` is OpenAPI 3.1.0 and has all 49 paths. `internal/app/contract_test.go` checks it against the real routes in CI. It is the single source of the API description, and this lane adds no second hand-written one.
- The `web` job already runs `npm run generate` (types from the spec) followed by `git diff --exit-code src/api/types.ts`. The Postman collection uses the same pattern: a generated file is committed, and CI regenerates it and fails on any difference.

## 2. Facts checked in a scratch run (openapi-to-postmanv2 6.4.0 on the current spec)

| Finding | Consequence |
|---|---|
| Output contains random `id`, `_postman_id` and faked uuid path or query values on every run | the generator must normalise them (§4), otherwise the CI diff always fails |
| The library API with the options below gives byte-identical normalised output on repeated runs (checked twice) | the `git diff --exit-code` gate works |
| Raw output is 1.8 MB (3 MB with `parametersResolution=Example`), mostly generated example responses | normalisation drops `response` arrays: about 238 KB |
| The spec's `session` scheme (`apiKey` in cookie `unicourse_session`) becomes a **header** named `unicourse_session`, which the API ignores | remove every `auth` and send the cookie with a collection script (§5) |
| `servers: [{url: "/api/v1"}]` becomes collection variable `baseUrl = /api/v1`, which is unusable in Postman | remove the collection variable; `baseUrl` comes from the environment file |
| Request bodies are the spec's own `example` values and are deterministic | they stay as they are, except the magic-link request (§4 step 6) |
| The session cookie is set `Secure` and `HttpOnly`, and consume answers `302` | I can't confirm that Postman's cookie jar replays a `Secure` cookie over `http://localhost`, so the session is captured into a variable instead (§5) |

## 4. `scripts/postman.mjs` (exact behaviour)

1. Read the spec path and the output path from `process.argv`. With fewer than two arguments, print `usage: postman.mjs <openapi.json> <out.json>` and exit 2.
2. `import converter from 'openapi-to-postmanv2'` (CommonJS default import). Call `converter.convert({ type: 'string', data: <spec text> }, { folderStrategy: 'Paths', parametersResolution: 'Example', schemaFaker: false, includeAuthInfoInExample: false }, cb)`, wrapped in a Promise. If there is an error or `!res.result`, print `postman: <err or res.reason>` and exit 1. Take `res.output[0].data`.
3. Walk the collection recursively and delete every key named `id`, `_postman_id` or `auth` at any depth.
4. For every object that has a `request`:
   - set `response` to `[]`;
   - for each `request.url.variable[]`, set `value` to `{{slug}}` for key `slug`, `{{token}}` for key `token`, `""` otherwise;
   - for each `request.url.query[]`, set `value: ""` and `disabled: true`, so optional filters start off.
5. Set `collection.variable = []`.
6. On the item whose request is `POST` with `url.path` equal to `["auth","magic-link"]`, set `request.body.raw` to `{\n  "email": "{{email}}"\n}`.
7. On the item whose request is `POST` with `url.path` equal to `["auth","magic-link",":token"]`:
   - set `protocolProfileBehavior = { followRedirects: false }`;
   - add `event = [{ listen: "test", script: { type: "text/javascript", exec: CAPTURE } }]`.
8. Set `collection.event = [{ listen: "prerequest", script: { type: "text/javascript", exec: SEND } }]`.
9. If step 6 or step 7 finds no matching item, exit 1 with `postman: request <path> not found in the spec`, so a renamed route fails loudly.
10. Write `JSON.stringify(collection, null, 2) + "\n"`.

The two scripts, as string arrays (one line per element):

```js
const CAPTURE = [
  "const c = pm.response.headers.all().filter(h => h.key.toLowerCase() === 'set-cookie').map(h => h.value).find(v => v.startsWith('unicourse_session=') && !v.startsWith('unicourse_session=;'));",
  "pm.test('signed in (302 with a session cookie)', () => { pm.expect(pm.response.code).to.equal(302); pm.expect(c, 'no session cookie: token used, expired or wrong').to.be.a('string'); });",
  "if (c) pm.environment.set('session', c.split(';')[0].slice('unicourse_session='.length));",
]
const SEND = [
  "const s = pm.environment.get('session');",
  "if (s) pm.request.headers.upsert({ key: 'Cookie', value: 'unicourse_session=' + s });",
]
```

`Sec-Fetch-Site` is not sent by Postman, and that is what the server's sign-in check expects from non-browser clients (`internal/auth/handler.go`, `consumeMagicLink`). No route needs an Origin header.

The defaults match the `seed-demo` dataset. Any persona from the `seed-demo` report works as `email`.

## 6. CI

In the `web` job, directly after the existing types check:

```
          npm run postman
          git diff --exit-code ../../docs/postman/unicourse.postman_collection.json
```

A spec change without a regenerated collection fails `web`, as a stale `types.ts` does today. When Dependabot bumps `openapi-to-postmanv2` and the output changes, the Dependabot PR fails until someone runs `npm run postman` on it. That is the intended signal.

## 7. Root README section (after "Demo personas")

```
## Explore the API with Postman

The API is described by `apps/api/openapi.json` (OpenAPI 3.1, checked against the routes in CI). A Postman
collection generated from it lives in `docs/postman/` (`npm run postman` in `apps/web` regenerates it; CI fails
when it is stale).

1. In Postman, import `docs/postman/unicourse.postman_collection.json` and `docs/postman/unicourse.postman_environment.json`, and select the "UniCourse local" environment.
2. With the API running and the demo seeded, send **auth / magic-link / Request a magic link** (it uses `{{email}}`, Elena Marsh by default).
3. Copy the token from the link in the API log (`.../auth/magic-link/<token>`) into the environment variable `token`.
4. Send **auth / magic-link / {token} / Consume a magic link**. Its test stores the session in `session`, and every later request sends it.
5. Try **universities/{slug} / me / My sections** or any other request. Path ids are blank: paste an id from a previous response.
```

The folder and request names in steps 2, 4 and 5 were checked against the scratch output (library API, options of §4). If the committed file differs, the worker uses its names.

## 8. Tests and verification

There is no unit test for the script. The CI regenerate-and-diff check is its test, and a run against the real API is the proof.

1. **Gates:** `npm run lint`, `npm run typecheck` (the script is `.mjs` and only linted), and `npm run postman` twice with `git diff --exit-code` clean after the second run.
2. **Real run.** The worker records the transcript in the lane log, using Newman through `npx --yes newman@6`, which is verification only and not a dependency:
   - local API with `seed-demo` loaded;
   - run the magic-link request with the environment;
   - `grep` the token from the API log;
   - run the consume request and `My sections` with `--env-var token=<t>` and the session carried over (`--export-environment`).

   Expected: the consume test passes, and `My sections` returns 200 with three items for Elena.
3. **Postman app:** the owner imports both files once and repeats §7 by hand. The orchestrator records the result.

## 9. Decisions for PLAN.md (proposed numbers; the orchestrator assigns them)

- **D109:** the Postman collection is generated from `apps/api/openapi.json` by `openapi-to-postmanv2` (dev dependency of `apps/web`) and committed under `docs/postman/` with a hand-written environment. CI regenerates it and fails on a difference. The spec stays the single source.
- **D110:** the collection authenticates by capturing `unicourse_session` from the magic-link confirm response into an environment variable and sending it as a `Cookie` header from a collection script. It does not use Postman's cookie jar, which may not replay the `Secure` cookie over `http://localhost`.

## 10. Ceilings

- Path ids are blank and must be pasted by hand. There is no chaining, such as storing the created section id. Add it when someone scripts a flow in Postman.
- One environment (local). Add a staging environment when one exists.
- Multipart requests (imports, uploads) come out as form-data with an empty file. Postman users pick the file by hand.
