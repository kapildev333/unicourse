# P5-L2 design: schedule grid, catalog, term picker, meetings editor (web)

Spec: `docs/specs/2026-10-06-student-schedule.md` §5 (contract), §6 (web), §7 (tests). Plan: `docs/plans/2026-10-06-student-schedule.md` Task 2, Review Focus 2 and 4. Decisions D23, D34-D40.
Builds on (binding): `docs/design/P1-L4.md` and `docs/design/P2-L3.md`: light theme only, no toasts (inline `StatusMessage`), UI error copy keyed on `code:field`, pages take `slug` and search params as props and route files wire `navigate`, no `fetch` outside `src/api/`, only existing colour roles. **No new dependency** (D40). Every path below is under `apps/web/`.

Contract assumed (P5-L1a, on `main` before the worker starts; `src/api/types.ts` comes from there, never hand-edit it):
`Section.meetings: Meeting[]` always present, ordered by weekday then startsAt; `Meeting = { id, weekday 1-7 (1 = Monday), startsAt "HH:MM", endsAt "HH:MM", location }`; `SectionCreate.meetings?` / `SectionUpdate.meetings?: MeetingInput[]` replace the whole list, `[]` clears, absent keeps; `GET /sections` and `GET /courses` readable by every member, with `q` and `departmentId`. Anything else is a request in `.claude/lanes/P5-L2.md` (§9).

## 0. Decisions, deviations and simplifications

| # | Decision | Why / ceiling |
|---|---|---|
| 1 | `currentTerm()` returns the term containing today, else the next starting, else `undefined` (brief). The **picker default** is `defaultTermId()` (existing, `courses/queries.ts`), rewritten on top of `currentTerm()` and keeping its last fallback "latest-starting term", so a student after the last term ends still sees the last term, with the note "No term is in session today." | A `<select>` must show something; an empty page with past terms present is worse. Existing `defaultTermId` tests stay green. |
| 2 | My sections default view is **list**; `?view=schedule` selects the schedule. | Spec 1 end-to-end asserts the list rows on sign-in; the success criterion's "opens the schedule" is one click. |
| 3 | Week grid: **one CSS grid row per minute** (`0.1rem`, so an hour is `6rem`), not 30-minute rows as the plan says. | `10:00-11:15` and `09:05-09:55` place exactly with no rounding; the 30-minute rhythm stays visible as hour lines plus labels. Hundreds of implicit-size rows are fine for CSS grid. |
| 4 | Grid always shows Mon-Sun (spec). Visible hours: `min(08:00, earliest start floored to the hour)` to `max(18:00, latest end ceiled to the hour)`. | Ceiling: weekend columns take space even when empty. |
| 5 | Overlapping blocks on one day sit side by side in **lanes** (greedy interval assignment); every block of that day gets width `1/lanes`. | Ceiling: one clash on Monday narrows every Monday block. Per-cluster widths when someone complains. |
| 6 | Times display as stored, 24-hour `HH:MM` (`10:00–11:15`); no `Intl` formatting. | Wall-clock, no conversion (D35). Ceiling: 12-hour locales; add `Intl.DateTimeFormat` with `hour: 'numeric'` on a fixed date when asked. |
| 7 | Blocks clip overflow (`overflow-hidden`); a 50-minute block (80px) shows code, time, clash line, title and instructors, location may clip. The full text is in the DOM for screen readers and the block links to the section page. | Ceiling: tiny blocks; no hover popover. |
| 8 | One DOM for sight and screen readers: each weekday is a `<section>` with an `<h3>` and an `<ol>` that is itself the CSS grid for that day (its `<li>` are the grid items). No duplicated sr-only copy, no `display: contents`. | Keeps list semantics in every browser and keeps blocks focusable links. |
| 9 | Catalog department filter is a **single native `<select>`** over `useAllDepartments` (exactly the course list's filter), **not** `admin/department-picker.tsx`. | `DepartmentPicker` is a multi-select checkbox fieldset for forms; the filter is one value (`departmentId`). Reused: the data hook and the course-list markup. |
| 10 | Catalog search is debounced 300 ms in the page (`setTimeout` in an effect), value lands in the URL as `q`. Changing a filter shows `Loading` for the list body (new query key); the filter row stays mounted so focus is not lost. | Ceiling: a short flash of `Loading` per search. `placeholderData: keepPreviousData` in `useCursorList` if it bothers anyone. Also: if `q` changes in the URL from outside (back button), the input keeps its text; acceptable with `replace: true` navigation. |
| 11 | Catalog clash notes use the viewer's `GET /me/sections` (same query key as My sections, so usually cached). If that query is pending or failed, rows show no clash note; the catalog never blocks on it. | Ceiling: silent absence of notes when `/me/sections` fails. |
| 12 | Editing meetings of an existing section: `SectionDialog` gains an **edit mode** (number + meetings) opened from a new **Edit** button on the section list rows (same pattern as the course list). Section detail shows meetings read-only, no edit button. | Spec: "Section dialog gains a meetings editor"; without an edit mode meetings could be set only at creation. Ceiling: a manager on the detail page goes back to the list to edit. |
| 13 | Meetings validation is server-only (the form is `noValidate`, like every dialog). | Ceiling: one round trip for an empty time. |
| 14 | Nav: **every** role sees My sections and Catalog; admin and dept_admin also Courses and Admin. Order: My sections, Catalog, Courses, Admin. | Spec names the member nav; the catalog is equally useful to staff. |
| 15 | Section detail's own-role badge comes from `/me/sections` (`myRole`), not from "member means student". | Once members may open any section from the catalog (request R1), the old heuristic labels a non-enrolled member "Student". |
| 16 | No `catalog/queries.ts` (plan lists it). The catalog list uses `useCursorList` inline exactly like `section-list.tsx`; `useMySections` lives in `my-sections.tsx`. | One fewer file. |
| 17 | Section list's term `<select>` is left as is (not switched to `TermPicker`). | Smallest diff; same markup. |

## 1. `src/lib/schedule.ts` (pure, no React)

```ts
import type { components } from '../api/types'
export type Meeting = components['schemas']['Meeting']
export type Slot = Pick<Meeting, 'weekday' | 'startsAt' | 'endsAt'>

export const dayShort = ['Mon', 'Tue', 'Wed', 'Thu', 'Fri', 'Sat', 'Sun'] as const   // index weekday - 1
export const dayLong = ['Monday', 'Tuesday', 'Wednesday', 'Thursday', 'Friday', 'Saturday', 'Sunday'] as const

/** Same weekday and the half-open intervals [start, end) intersect. "HH:MM" compares as a string. */
export function overlaps(a: Slot, b: Slot): boolean
//   a.weekday === b.weekday && a.startsAt < b.endsAt && b.startsAt < a.endsAt
//   10:00-11:00 vs 11:00-12:00 -> false (touching); 10:00-11:01 vs 11:00-12:00 -> true; identical -> true;
//   containment -> true; symmetric; different weekday -> false.

/** Every other section (id !== section.id) with at least one meeting overlapping one of section.meetings.
 *  Each returned once, in the order of `others`. No meetings on either side -> not a clash.
 *  Per-block use: clashesFor({ id: s.id, meetings: [m] }, others). */
export function clashesFor<S extends { id: string; meetings: Slot[] }>(
  section: { id: string; meetings: Slot[] }, others: S[]): S[]

type TermLike = { startsOn: string; endsOn: string }   // 'YYYY-MM-DD'
/** Term with startsOn <= today <= endsOn (both inclusive; earliest startsOn if several),
 *  else the one with the smallest startsOn > today, else undefined (also for []). today = todayIso(). */
export function currentTerm<T extends TermLike>(terms: T[], today: string): T | undefined

/** 'CS101-001' */
export function classCode(s: { course: { code: string }; number: string }): string

/** 'Mon 10:00–11:15 · Room 101' (long: 'Monday 10:00–11:15 · Room 101'); ' · location' omitted when location is ''. En dash U+2013. */
export function formatMeeting(m: Slot & { location: string }, long = false): string

/** 'HH:MM' -> minutes since midnight. */
export function toMinutes(t: string): number

/** Input sorted by startsAt then endsAt. Greedy: each slot takes the lowest lane whose last endsAt <= its startsAt,
 *  else a new lane. Returns the lane index per input slot and the lane count (>= 1, also for []). */
export function assignLanes(slots: Pick<Slot, 'startsAt' | 'endsAt'>[]): { lane: number[]; lanes: number }
```

`src/features/courses/queries.ts`: `defaultTermId(terms, today)` becomes `(currentTerm(sorted, today) ?? latestStarting)?.id`, same results as today (its tests in `section-list.test.tsx` stay unchanged). `todayIso()` stays there.

### 3.3 `schedule.tsx` — `export function Schedule(props: { slug: string; term: Term; sections: MySection[] })`

Derived data (inside the component, plain code, no memo needed):
- `timed = sections.filter(s => s.meetings.length > 0)`, `untimed = sections.filter(s => s.meetings.length === 0)`.
- `start = Math.min(480, floor60(min startsAt))`, `end = Math.max(1080, ceil60(max endsAt))` in minutes (`toMinutes`); `rows = end - start`.
