## 0. Conventions for every case

1. **Titles.** One `test()` per case, title `E-<AREA>-<nn> <short description>`. Multi-part flows use `test.step` inside the case. The ID is the diff key between this catalogue and the files.
2. **University per file.** `const slug = \`<prefix>-${runId}\``, `const P = personas(slug)` at module top (pure, no side effects), `test.beforeAll(() => { seedDemo(slug) })`. Never seed at module top: Playwright loads files in the runner process to list them. Prefixes: `e2e-demo`, `e2e-auth`, `e2e-adm`, `e2e-crs`, `e2e-grd`, `e2e-cat`, `e2e-cnt`, `e2e-a11y`. Persona emails are `<local>@<slug>.edu`.
3. **Signing in.** `pageAs(browser, email, slug)` (cached session per email per worker, §D) for every persona page; close it with `await page.context().close()` at the end of the case. Use `signIn` on a fresh context only where the sign-in itself is under test or the case signs out (signing out a cached session would revoke it for later cases). Budget: the API allows 5 sign-in links per email per hour per API process; no persona is signed in more than 3 times per file with this rule.
4. **Seeding.** `seed-demo` gives the world. Extra rows the case does not assert go through `api(page, ...)` as the persona whose role may write them. A DELETE precondition uses `page.request.delete(url)` directly (`api` has no `delete`, and Spec 9 §5 keeps it unchanged). The UI is used for a write only when that write is the assertion.
5. **Selectors.** `getByRole` with the accessible name, `getByLabel`, `getByText`. Use `{ exact: true }` where the name is a prefix of another (`'Add week'` button vs dialog button, `'Final'` column vs `'Final Exam'`). Scope to a dialog with `page.getByRole('dialog', { name: '<title>' })`, to a table row with `page.getByRole('row', { name: /<name>/ })`, to a card with `page.getByRole('listitem').filter({ hasText: '<code>' })`, to a week card with `page.getByRole('listitem').filter({ has: page.getByRole('heading', { name: '<week title>', level: 3 }) })`. No CSS, no test ids, no `waitForTimeout`.
6. **Banner copy.** `ErrorBanner` text may end with ` Reference: <request id>.`; assert banner copy with the default substring `getByText`/`toContainText`, never `exact`. Field errors (under an input) carry no reference and may be exact.
7. **Failure messages.** Every `expect` on product copy passes a message `'<role>, <page>: <expected>'`, for example `expect(dialog.getByText('Enter a valid email address.'), 'admin, Invitations dialog: email field error').toBeVisible()`.
8. **Status lines.** Success notices render in a `role="status"` paragraph (`StatusMessage`); assert with `page.getByRole('status').filter({ hasText: '<copy>' })`.
9. **Phone checks.** `await page.setViewportSize({ width: 390, height: 844 })` inside the case, wait for the page's heading, then `expectNoSideScroll(page, '<role>, <page>')` (S5-68). Restore nothing: the page closes at the end of the case.
10. **Defects.** A case whose assertion fails because of the product is committed as `test.fixme('E-xxx-nn: <finding>')` with the finding recorded in the lane log (Spec 9 §7). §F lists the ones known now.
11. **Year.** `year = new Date().getFullYear()`; demo terms are `demoTerm = \`Academic Year ${year}\`` (current, Jan 1 to Dec 31) and `springTerm = \`Spring ${year + 1}\`` (upcoming).
