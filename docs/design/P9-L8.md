# P9-L8 design: display names (Spec 5 §7 C1)

Source: spec `docs/specs/2026-10-07-ui-ux-benchmark.md` §7 row C1; plan `docs/plans/2026-10-07-ui-ux-benchmark.md` Task 8; PLAN.md D21 (roster rows without an account become invitations + `pending_enrollments`), D83 (the ruling), D74. Builds on `docs/design/P2-L2.md` (roster import) and `docs/design/P7-L1.md` §0 row 7 (`ImportRow`/`ImportCounts` are not widened). Where this document and the code disagree on a convention, the code wins; on behaviour, this document wins.

API only. No web source changes; `apps/web/src/api/types.ts` is regenerated and nothing else in `apps/web` moves.

## 0. Decisions taken here

| # | Decision | Why |
|---|---|---|
| 1 | One migration `0006_invitation_display_name.sql` adds `invitations.display_name text not null default '' check (char_length(display_name) <= 100)`. The name lives on the invitation (one per person per university), not on `pending_enrollments` (one per section). | D83 says "stored on the invitation". `''` means "no name", the same convention as `users.display_name`. |
| 2 | One rule everywhere: **fill only if empty**. A non-empty `users.display_name` is changed only by the user (`PATCH /me`). A non-empty `invitations.display_name` is never changed. | The rule `SignIn` already applies to the OIDC name. |
| 3 | The import writes names **only for rows it writes** (`add` and `invite`). A row classified `exists` (already enrolled, or already pending in this section) changes nothing, name included. The import response, counts and row messages stay as they are, apart from one new row error for an over-long name. | `csvimport.Apply` hands only `add`/`invite`/`update` rows to the applier, and the web dialog's Import button needs `add + invite > 0`. Treating a name fill as `update` would widen `ImportCounts` and need a web change, which C1 rules out (and P7-L1 §0 row 7 forbids). Ceiling in §7. |
| 4 | Sign-in precedence for an empty `users.display_name`: **existing non-empty name > OIDC `name` claim > oldest open invitation that has a name (by `created_at, id`) > `''`**. Magic link passes no name, so the invitation name applies. | The OIDC name is the person's own identity data; the CSV name is typed by an admin. "Oldest" is the order `SignIn` already reads invitations in, so the result is deterministic. |
| 5 | `PATCH /api/v1/me` lives in `internal/auth` beside `GET /me`, registered in `auth.Register` (`internal/httpx/routes.go` is the router type and is **not** touched). Same authentication (`Authenticate`, session cookie, `SameSite=Lax`) and body decoding (`httpx.DecodeJSON`, unknown keys rejected) as every other mutating route; there is no separate CSRF token in this codebase. | Follows the existing `me` handler. |
| 6 | Audit: a changed name writes **one `membership.update` entry per active membership** of the person, in that membership's university: `entityType "membership"`, `entityId` = the membership id, `before {"displayName": old}`, `after {"displayName": new}`, actor = whoever made the change. Used by `PATCH /me` (actor = the user) and by the import's user fill (actor = the importing admin; only the importing university, the one membership the row was classified against). Not audited: the invitation name, and the fill at sign-in (the OIDC fill is not audited today either). | `audit_log` is tenant-scoped (`university_id not null`, RLS) and `users` is not; a membership is the user's footprint in each university, so each university's admins see the change in their own log. A new entity type `user` would widen the `AuditEntry.entityType` enum, and `apps/web/src/features/admin/audit-log.tsx` types `entityLabels` as `Record<EntityType, string>`, so the regenerated `types.ts` would break the web typecheck. `membership` renders as "Membership updated" with a generic before/after diff, no web change. |
| 7 | Validation is the existing `tenant.TrimLen` rule with max 100: trimmed, non-empty, no NUL, at most 100 runes. `internal/auth` cannot import `internal/tenant` (tenant imports auth), so auth gets a 10-line copy with the same messages. The import needs only the length check (CSV cells are already trimmed and NUL-free, see §2.2). | One rule, one set of messages; the copy is smaller than moving `TrimLen` and its callers. |
| 8 | No `users.display_name` length constraint in the database. | OIDC names are unvalidated today and existing rows could violate it; the API paths that write names (import, `PATCH /me`) enforce 100. Ceiling in §7. |

## 1. Migration `apps/api/migrations/0006_invitation_display_name.sql`

Exact content:

```sql
-- Spec 5 C1 (D83): the roster CSV's displayName for a person without an account. auth.SignIn copies it
-- into an empty users.display_name; '' means no name, as on users. Never overwritten once set.
alter table invitations add column display_name text not null default '' check (char_length(display_name) <= 100);
```

RLS and grants: nothing to add. The column inherits the table's `tenant_isolation` and `invitations_by_email` policies; `0004_role_split.sql`'s `grant select, insert, update, delete on all tables` is table-level, so `unicourse` can read and write the new column. The default is a constant, so Postgres adds the column without rewriting the table.

## 2. Roster import (`apps/api/internal/course/import.go`)

### 2.1 Ref

```go
type enrollRef struct{ UserID, Email, InvitationID, Name string }
```

### 2.2 Classifier (`enrollmentClassifier`)

`csvimport.Parse` already trims every cell and rejects any file containing a NUL byte, so `rc.Data["displayname"]` is trimmed and NUL-free; an empty cell or a file without the column gives `""`.

- Add one case to the `switch`, directly after `case e == "":`

  ```go
  case utf8.RuneCountInString(recs[i].Data["displayname"]) > 100:
      out[i] = verr("displayName must be at most 100 characters")
  ```

  (before any state-dependent case, so a file's validity does not depend on who already exists; `unicode/utf8` is already imported).
- Every `Add` and `Invite` verdict sets `Name: recs[i].Data["displayname"]` in its `enrollRef`. `Exists` verdicts are unchanged (no `Ref`). No row message changes.

### 2.3 Applier (`enrollmentApplier`)

While walking `rows`, also collect:

- `fillIDs, fillNames []string`: rows with `ref.UserID != "" && ref.Name != ""`.
- `invFillIDs, invFillNames []string`: rows with `ref.InvitationID != "" && ref.Name != ""`.
- `nameOf map[string]string`: rows going to `newEmails` with `ref.Name != ""`, keyed by `ref.Email`.

Order of statements in the applier (steps 2 and 4 are new):

1. Existing: insert `enrollments` + `enrollment.create` audit (only when `len(users) > 0`).
2. New, when `len(fillIDs) > 0`: fill empty user names and audit them, in one statement plus one `audit.WriteMany`:

   ```sql
   with filled as (
     update users u set display_name = x.n
     from unnest($1::uuid[], $2::text[]) as x(id, n)
     where u.id = x.id and u.display_name = ''
     returning u.id, u.display_name)
   select m.id, f.display_name from filled f join memberships m on m.user_id = f.id
   ```

   `users` has no RLS; `memberships` is confined to the importing university by `tenant_isolation`, so each filled user yields exactly their membership here (they were classified `active` in this university). For each returned `(membershipID, name)`:
   `audit.Entry{ActorUserID: s.UserID, Action: "membership.update", EntityType: "membership", EntityID: membershipID, Before: map[string]string{"displayName": ""}, After: map[string]string{"displayName": name}}`, written with `audit.WriteMany(ctx, tx, s.UniversityID, es)`.
3. Existing: `tenant.CreateInvitations(...)`; then for each returned `v`, append `v.ID` to `invIDs` (existing) and, when `nameOf[v.Email] != ""`, append `v.ID`/`nameOf[v.Email]` to `invFillIDs`/`invFillNames` (new).
4. New, when `len(invFillIDs) > 0`, **before** the existing `if len(invIDs) == 0 { return nil }`:

   ```sql
   update invitations i set display_name = x.n
   from unnest($1::uuid[], $2::text[]) as x(id, n)
   where i.id = x.id and i.display_name = ''
   ```

   (RLS confines it to the importing university; the ids came from it anyway.)
5. Existing: insert `pending_enrollments`.

`tenant.CreateInvitations` is not changed; the name is set right after it in the same transaction, so the `invitation.create` audit `after` keeps its current shape (no name).

### 2.4 Behaviour table (what the worker's tests pin)

| Row | Before | After commit |
|---|---|---|
| active member, not enrolled, name empty, CSV `Ann` | `''` | `Ann`, one `membership.update` audit in this university |
| active member, not enrolled, name `Set`, CSV `Ann` | `Set` | `Set`, no name audit |
| already enrolled (`exists`), name empty, CSV `Ann` | `''` | `''` (row not applied; §0 row 3) |
| no account, no open invitation, CSV `Ann` | - | new invitation `display_name = 'Ann'` |
| no account, open invitation in this university with `''`, not pending in this section, CSV `Ann` | `''` | `Ann` |
| same, invitation already `Bea` | `Bea` | `Bea` |
| user row exists but no membership in this university (classified `invite`), CSV `Ann` | user `''` | user `''`, invitation `Ann`; the user gets it at their next sign-in (§3) |
| any row, CSV name empty or no `displayName` column | | nothing name-related changes |
| CSV name of 101 runes | | `error` row `displayName must be at most 100 characters`; 100 runes is fine |

Re-import with a different name: the same table applies; a set name (user or invitation) is never replaced. The import summary reports nothing new (counts and messages unchanged).

## 3. Sign-in (`apps/api/internal/auth/invite.go`, `SignIn`)

This one function serves OIDC (`oidc.go` passes `cl.Name`), magic link (`handler.go` passes `""`) and invitation links (they land on sign-in, which ends in one of the two). Changes:

1. `type inv struct{ id, uni, name string }`; the invitation query becomes
   `select id, university_id, display_name from invitations where email = $1 and accepted_at is null and expires_at > now() order by created_at, id` and scans the third column.
2. After the read loop's `rows.Close()`/`rows.Err()` checks and before the `for _, i := range invs` accept loop, insert:

   ```go
   for _, i := range invs { // decision 4: the oldest open invitation with a name, only into an empty name
       if i.name != "" {
           if _, err := tx.ExecContext(ctx, `update users set display_name = $2 where id = $1 and display_name = ''`, userID, i.name); err != nil {
               return pg.MapError(err)
           }
           break
       }
   }
   ```

   The users upsert above it already applied the OIDC name to an empty name, so the guard `display_name = ''` yields the precedence of §0 row 4 with no extra branching. Not audited (§0 row 6).
3. Update `SignIn`'s doc comment: "displayName (then the oldest open invitation's stored name) only fills an empty name."

## 4. `PATCH /api/v1/me` (`apps/api/internal/auth/handler.go`)

### 4.1 Wiring

- `Register`: add `r.Handle("PATCH", "/api/v1/me", d.updateMe)` after the `GET` line; the comment becomes "adds the eight auth routes".
- Split the body of `me` after `Authenticate` into `func (d Deps) writeMe(w http.ResponseWriter, r *http.Request, userID string) error` (the existing user read + `d.memberships` + `WriteJSON 200`). `me` becomes `Authenticate` then `return d.writeMe(w, r, a.UserID)`.

### 4.2 Validation helper (same file)

```go
// displayName applies tenant.TrimLen's rule with max 100 (auth cannot import tenant).
func displayName(s string) (string, error)
```

`strings.TrimSpace`; then, in this order, `httpx.Validation(httpx.FieldError{Field: "displayName", Message: m})` with `m` = `"is required"` when empty, `"must not contain NUL"` when it contains `\x00`, `"must be at most 100 characters"` when `utf8.RuneCountInString > 100`. Returns the trimmed value otherwise.

### 4.3 Handler

```go
func (d Deps) updateMe(w http.ResponseWriter, r *http.Request) error
```

1. `a, err := Authenticate(w, r, d.Sessions)` (401 `unauthenticated` without a valid session).
2. `var body struct{ DisplayName string `json:"displayName"` }`; `httpx.DecodeJSON(r, &body)` (400 on unknown keys such as `userId`, non-string, empty body). A missing or `null` `displayName` decodes to `""` and fails step 3 with `is required`.
3. `name, err := displayName(body.DisplayName)`.
4. `pg.WithUserTx(ctx, d.DB, a.UserID, "", fn)` where `fn`:
   - `select display_name from users where id = $1 for update` into `old`; if `old == name`, return nil (no write, no audit).
   - `update users set display_name = $2 where id = $1` (`$1` is always the session's user: the body has no id, so no one can set another person's name).
   - Read **all** active memberships first (the `memberships_self` policy only applies while `app.university_id` is unset):
     `select id, university_id from memberships where user_id = $1 and status = 'active' order by university_id`.
   - For each: `pg.SetUniversity(ctx, tx, uni)` then `audit.Write(ctx, tx, uni, audit.Entry{ActorUserID: a.UserID, Action: "membership.update", EntityType: "membership", EntityID: id, Before: map[string]string{"displayName": old}, After: map[string]string{"displayName": name}})`.
   - Errors from SQL go through `pg.MapError`, as in `SignIn`.
5. `return d.writeMe(w, r, a.UserID)`: 200 with exactly the `GET /me` body `{user, memberships}`.

A user with no active membership still gets the name; no audit row is written (there is no university to hold it).

## 5. Contract `apps/api/openapi.json`

1. `paths["/me"]` gains, beside `get`:

   ```json
   "patch": {
     "operationId": "updateMe",
     "summary": "Set the current user's display name",
     "description": "Who: signed in, for their own name only. displayName is trimmed; 1-100 characters. The name is the person's across every university. Audited as membership.update (before/after displayName) in each university where the user has an active membership; no change, no audit.",
     "requestBody": {"required": true, "content": {"application/json": {"schema": {"$ref": "#/components/schemas/MeUpdate"}}}},
     "responses": {
       "200": {"description": "Updated; same body as getMe", "content": {"application/json": {"schema": {"$ref": "#/components/schemas/Me"}}}},
       "400": {"$ref": "#/components/responses/ValidationFailed"},
       "401": {"$ref": "#/components/responses/Unauthenticated"},
       "500": {"$ref": "#/components/responses/Internal"}
     }
   }
   ```

2. `components.schemas.MeUpdate`, placed right after `Me`:

   ```json
   "MeUpdate": {"type": "object", "properties": {"displayName": {"type": "string", "example": "Alice Doe", "minLength": 1, "maxLength": 100}}, "required": ["displayName"], "additionalProperties": false}
   ```

3. In both `importEnrollments` and its `/preview` operation's `description`, replace `displayName is accepted and ignored.` with:
   `displayName (optional, at most 100 characters) fills an empty name and never replaces a set one: on commit an added member's own name, or the invitation's name for an invited person, applied when they first sign in. Rows that already exist change nothing.`
   and extend the row-message list with `"displayName must be at most 100 characters"`.

`AuditEntry.entityType` and the `entityType` query parameter enums are **not** changed. Then in `apps/web`: `npm run generate` (rewrites `src/api/types.ts` only), and the web gates (`lint`, `typecheck`, `test`, `build`) must pass unchanged.

## 8. Simplifications and their ceilings

| Simplification | Ceiling | Upgrade path |
|---|---|---|
| Names fill only on `add`/`invite` rows (§0 row 3) | People enrolled or invited **before** this lane are not named by re-importing the same roster; they get a name from an OIDC sign-in or `PATCH /me` (whose UI waits for B2). Nothing is deployed yet, so this hits dev and seed data only | Classify a name fill on an `exists` row as `update` and widen `ImportCounts` with `update` plus a 3-line change in `csv-import-dialog.tsx` (Import enabled on `update`, summary "N names set") |
| Name fill on sign-in and invitation names not audited | No audit trail of the name a person got at first sign-in or of the name typed on an invitation | Add `displayName` to the `invitation.create` / `membership.create` `after` payloads |
| Audit as `membership.update` instead of a `user` entity | A rename shows as "Membership updated"; a user without memberships leaves no trace | Add `user` to the `entityType` enums and a label in `audit-log.tsx` |
| Import fills a global name (any university sees it) from one university's CSV | An admin in A names a person who is also in B; B's log does not show it | Fill-only-if-empty caps it to unnamed people; the person can overwrite with `PATCH /me` |
| No DB length constraint on `users.display_name`; OIDC names not validated | A long or odd OIDC name is stored as today | Validate/truncate the OIDC name in `SignIn` and add the check after a data audit |
| No control/bidi character filtering beyond NUL | A name can contain e.g. RTL overrides (same as every other text field today) | A shared text sanitiser for all user-facing names |
| Invitation names are not returned by any endpoint | Pending invitees still show as emails in invitation and pending-staff lists until they sign in | Add `displayName` to `Invitation` / `PendingStaff` |
