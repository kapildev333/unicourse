# P0-L4 design: `apps/api/openapi.json` (Spec 1 contract)

Source: spec `docs/specs/2026-10-05-platform-core-and-staffing.md` §4-§7; plan Tasks 2, 4, 5, 6, 9, 10.
Audience: the P0-L4 worker transcribes this into `apps/api/openapi.json` (OpenAPI 3.1, hand-written JSON) with no design choices left. Every later API and web lane builds against it. Later lanes may **widen** (add optional fields, routes, enum values) but never rename or remove.

## 1. Document shell

```json
{
  "openapi": "3.1.0",
  "info": { "title": "UniCourse API", "version": "1.0.0" },
  "servers": [ { "url": "/api/v1" } ],
  "paths": { ... },
  "components": { "schemas": {...}, "parameters": {...}, "responses": {...}, "securitySchemes": {...} },
  "security": [ { "session": [] } ]
}
```

- **Path keys are relative to the server `/api/v1`**: the JSON key is `/universities/{slug}/terms`, the Go route is `GET /api/v1/universities/{slug}/terms`. Reason: the web client is `openapi-fetch` with `baseUrl: '/api/v1'` (Task 3), which concatenates `baseUrl + pathKey`; full keys would yield `/api/v1/api/v1/...`. The contract test prefixes `/api/v1` to every key before comparing with `Router.Routes()`.
- `securitySchemes.session`: `{ "type": "apiKey", "in": "cookie", "name": "unicourse_session" }`. Root `security` applies it to everything; the operations marked **public** below set `"security": []`. (Cookie name is a P1-L1 choice; if it differs, P1-L1 widens/edits only this string — it does not affect generated types.)
- `/healthz` and `/readyz` are **not in the contract**. They are mounted by `httpx.Health` on the outer mux, outside `/api/v1` and outside `httpx.Router`, so the contract test never sees them; ops endpoints are not part of the web client. Rule: the contract is exactly the set of routes registered through `httpx.Router`, all under `/api/v1`.
- Every schema sets `"additionalProperties": false` on request bodies (matches `DecodeJSON`'s `DisallowUnknownFields`); response schemas do not set it (so widening responses never breaks clients).

## 2. Conventions (apply everywhere)

| Topic | Rule |
|---|---|
| Field names | camelCase, identical to the Go `json` tag and the generated TS type. |
| IDs | `{"type":"string","format":"uuid"}`, lowercase hex, example `"0b6f1c2e-5d4a-4f3b-9a51-7c2d8e9f0a11"`. |
| Timestamps | `{"type":"string","format":"date-time"}`, RFC 3339 in UTC with `Z` (Go `time.Time` marshalled after `.UTC()`), example `"2026-10-05T14:03:22Z"`. Fractional seconds allowed. |
| Dates | `{"type":"string","format":"date"}`, `YYYY-MM-DD`, example `"2026-09-01"`. Only `startsOn`, `endsOn`. |
| Enums | lowercase strings, snake_case if multi-word (`dept_admin`). |
| Emails | `{"type":"string","format":"email"}`; responses always lowercase. Requests accept any case and surrounding spaces; the server normalises. |
| **Nullability** | **Nothing is ever `null`.** An optional field that has no value is **omitted** (Go `omitempty` / nil pointer + `omitempty`). Optional fields are simply not in the schema's `required` list; no schema uses `"type": [..., "null"]`. |
| Arrays | Array fields are always **present** and are `[]` when empty, never omitted and never null (Go: initialise slices, no `omitempty` on slices). Applies to `items`, `details`, `departmentIds`, `staff`, `rows`, `terms`, `sections`, `memberships`. |
| Lists | `List<T>` = `{ "items": T[] (required), "nextCursor": string (optional) }`. `nextCursor` is omitted on the last page (Go `omitempty`). Cursor is opaque to clients. One named wrapper schema per T: `DepartmentList`, `TermList`, `MembershipList`, `InvitationList`, `CourseList`, `SectionList`, `SectionStaffList`, `EnrollmentList`, `AuditEntryList`. |
| Pagination params | Every collection `GET` takes `limit` and `cursor`. Order: ascending `(createdAt, id)`, except `audit-log`: newest first `(at desc, id desc)`. |
| Status codes | create `201` + resource body; update (`PATCH`) `200` + full updated resource; delete `204` no body; read `200`. Exceptions named per route (`202`, `302`). |
| PATCH | Partial merge: omitted fields are unchanged. Body with no recognised field → `400 validation_failed`, field `""`, message `"no fields to update"`. |
| Errors | Every non-2xx body is `Error`. Every operation lists `500`. Every non-public operation lists `401`. Every `/universities/{slug}/...` operation also lists `403` (no active membership / role) and `404` (unknown slug or id). |

Examples: put an `example` on every schema property (values below). For enum properties the first enum value is fine.

### 3.5 CSV import

**`ImportRow`**
| Field | Type | R/O | Example |
|---|---|---|---|
| line | integer, minimum 2 (line 1 is the header) | R | `3` |
| action | enum `add`, `exists`, `invite`, `error` | R | `"error"` |
| message | string | O (present for `error`, optional otherwise) | `"unknown department code MATH"` |
| data | object, `additionalProperties: {"type":"string"}` | R | `{"email":"erin@a.edu","displayname":"Erin Moe"}` |

`data` keys are the **lowercased** header names (Task 9 `Parse`), so `departmentCode` arrives as `departmentcode`.

**`ImportCounts`**: `add`, `exists`, `invite`, `error`: integer minimum 0, **all four required** (Go must initialise every key, the `map[Action]int` would otherwise drop zeros).

**`ImportPreview`**: `checksum` string R (sha256 hex, 64 chars, example `"9f86d081884c7d659a2feaa0c55ad015a3bf4f1b2b0b822cd15d6c15b0f00a08"`); `rows` `ImportRow[]` R; `counts` `ImportCounts` R.

**`ImportUpload`** (multipart `multipart/form-data`, preview): `file` string `format: binary` R. Max 5 MiB.
**`ImportCommit`** (multipart, import): `file` binary R; `checksum` string R. Must be the same bytes as previewed.

Import columns (header row required; case-insensitive; documented in each operation's `description`):
| Endpoint | Required | Optional |
|---|---|---|
| enrollments | `email` | `displayName` |
| courses | `departmentCode`, `code`, `title` | |
| sections | `courseCode`, `termName`, `number` | `instructorEmails`, `taEmails` (semicolon-separated) |

Import failure (`400 validation_failed`): `details` has one entry per bad row, `field: "line:<n>"`, `message` = the row's message; checksum mismatch → one entry `field: "checksum"`, `message: "file changed since preview"`; missing column / too large / no header → `field: "file"`.

### 3.6 Auth request/response bodies

**`OidcStart`** (request): `slug` string O; `email` email O; `next` string O, pattern `^/` (relative path only; the server ignores anything else). Exactly one of `slug`, `email` must be sent (server: 400 field `slug` if neither or both). Do not model this with `oneOf`; plain optional fields keep the generated TS simple.
**`OidcStartResult`**: `url` string `format: uri` R (provider authorize URL).
**`MagicLinkCreate`**: `email` email R; `next` string O, pattern `^/`.

### 4.2 `components/responses` (one per error code, each `application/json` → `Error`)
`ValidationFailed` (400), `Unauthenticated` (401), `Forbidden` (403), `NotFound` (404), `Conflict` (409), `RateLimited` (429), `Internal` (500). Each description states the code, e.g. `"validation_failed"`. `Internal` also declares header `X-Request-Id` (string).

## 6. Decisions (gaps and conflicts resolved)

1. **Path keys relative to `servers[0].url = /api/v1`** (§1). Required by `openapi-fetch` `baseUrl: '/api/v1'`; the contract test prefixes `/api/v1`.
2. **Health endpoints out of the contract** (§1): not registered through `httpx.Router`, not under `/api/v1`.
3. **Never null; optional = omitted; arrays always present** (§2). Consequences for Go: `audit.Row.ActorUserID`, `Before`, `After` need `omitempty` (RawMessage from SQL NULL is nil → omitted); `Invitation.AcceptedAt *time.Time` with `omitempty`; slices initialised to non-nil.
4. **`Section` always embeds `course`, `term`, `staff`** (all required). The plan's Go struct has them as `omitempty` pointers/slice; `staff` with `omitempty` would vanish for an unstaffed section, so P2-L2 drops `omitempty` on these three and fills them on every Section response. One shape for the web, no "maybe embedded" type.
5. **`Me.memberships[]` is `MyMembership { university: {id, slug, name}, role, departmentIds }`**, not the plan's flat `{ universityId, slug, name, role, departmentIds }`. A flat `name` inside a membership is ambiguous and the brief asks for a `University` schema; embedding gives it one use. Only `active` memberships are listed, so no `status`.
6. **Two membership schemas**: `Membership` (admin list: user email/name, status) and `MyMembership` (caller's view). They answer different questions; merging would force optional fields on both.
7. **`createdAt` only where shown**: `Enrollment.createdAt` (plan) and `AuditEntry.at`. Dropped the plan's `Department.createdAt` (unused by any §7 screen; adding back later is a widening). `Invitation.expiresAt`/`acceptedAt` kept (plan).
8. **Staff add takes `email`, not `userId`**, because spec §6 allows an invited email. 202 body is `{ invited: true, invitation: Invitation }` — the plan's `{ invited: true }` widened with the invitation so the web can show who/when without refetching.
9. **No single-enrollment POST**: spec §6 lists enrollments only via import; kept out.
10. **Import commit success = 200 `ImportPreview`** of the applied rows (the plan left the body unspecified). Reuses one schema; the web shows counts after import.
11. **`ImportCounts` has all four keys always**; `data` keys are lowercased headers.
12. **`SectionUpdate` has only `number`**; course/term moves are delete + create. Smallest; widening later is allowed.
13. **`OidcStart { slug?, email?, next? }` returning `{ url }`**, and the OIDC callback and `POST /auth/magic-link/{token}` always answer 302 (failures redirect to `/sign-in?error=<code>`), never a JSON error — they are browser navigations. Plan Task 5 says the not-allowed case is "403 forbidden"; the contract carries it as `?error=forbidden` on the redirect. P1-L1 may widen.
14a. **Magic-link scanners (D11, amended by orchestrator):** `GET /auth/magic-link/{token}` only shows a confirm page; `POST` consumes the token, so mail scanners that prefetch links cannot burn it.
14. **`POST /auth/sign-out` is public and idempotent** (204 even without a session), so a stale tab can always sign out.
15. **Every collection GET is a paginated `List<T>`**, including `/sections/{id}/staff`; `/me` and `/me/sections` are not lists.
16. **Audit-log order newest first**; `from` inclusive, `to` exclusive; `entityType` enum uses domain words (`staff`, not `section_staff`); `action` = `<entityType>.<create|update|delete>`.
17. **`DELETE` of a still-referenced parent returns 409**, not 404 (see risks).
18. Validation constraints in the contract are limited to what the plan already fixes (department `code` pattern, `minLength: 1` on names/codes/titles/number, `limit` bounds). Other limits (max lengths) are left to the owning designer; adding `maxLength` later is a narrowing of requests, so owners should decide them before their lane lands and amend here in the same PR.

## 9. Risks (for owning lanes, not the P0-L4 worker)

- **FK violation on DELETE maps to 404.** `pg.MapError` (P0-L2) maps 23503 to `ErrNotFound`, which is right for an insert referencing a missing row but wrong for deleting a still-referenced parent (department with courses, term with sections). The contract promises 409 there; P1-L2/P2-L2 must map 23503 on DELETE to `conflict` (or P0-L2 distinguishes by statement), or the contract's 409 is a lie.
- **Audit newest-first vs ascending keyset helper.** `httpx.Page`/`audit.List` (P0-L2) are written for ascending `(created_at, id) >`. Audit-log needs `(at, id) <` with `ORDER BY at DESC, id DESC`; the cursor stays opaque so the contract is unaffected, but `audit.List` must implement the descending variant.
- **Go struct drift.** Decisions 3, 4, 5, 7, 8 differ from Go structs printed in the plan (Tasks 2, 5, 6, 10). The contract wins; owning lanes must follow it, and the reviewer should diff JSON tags against this document.
