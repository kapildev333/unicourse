# P18-L1 design: quizzes and assignments API and data

Source: spec `docs/specs/2026-10-08-quizzes-and-assignments.md` (Spec 11) §3, §4, §5, §7, §10 (binding); plan `docs/plans/2026-10-08-quizzes-and-assignments.md` Tasks 3-5 and Review Focus 1-5; PLAN.md D16, D19, D20, D30, D46, D68, D74, D96, D137-D146. Builds on `docs/design/P7-L1.md` (grading) and `docs/design/P10-L1.md` (files, `tenant.After`, two-transaction upload). Where this document and the code disagree on a convention, the code wins; on behaviour, this document wins. "routes.go" in the plan is `internal/app/app.go` (there is no other route file).

## 0. Decisions taken here

| # | Decision | Why |
|---|---|---|
| 1 | Role predicate on `POST/PATCH/DELETE /assessments` depends on kind: `manual` keeps Spec 4's `teach` (admin, dept_admin, instructor); `quiz`/`assignment` use `authz.CanEditContent` (TA parity, Spec 11 §4). `POST` order: section 404 → `CanEditContent` 403 → decode → if `kind` is `manual` (or omitted) `teach` 403 → validation 400. An invalid `kind` skips the `teach` check and is a 400. PATCH/DELETE take the kind from the stored row. | Spec 4 §4/D74 vs Spec 11 §4; the kind is only known from the body on create |
| 2 | `kind` immutability = D46: the PATCH struct has no `kind` field, so `{"kind": …}` is 400 `validation_failed`, field `kind`, "unknown field". No trigger. | Smallest; already enforced by `httpx.DecodeJSON` |
| 3 | `dueOn` for quiz/assignment is computed **in SQL** in the same insert/update: `(closes_at at time zone (select timezone from universities where id = <university>))::date`. No `time.LoadLocation` in the handler. `dueOn` in the body of a quiz/assignment is 400 "derived from closesAt". | One statement; the timezone is already IANA-validated by `unicourse-admin` (`time.LoadLocation`) and Postgres reads the same tzdata; verified: close `2026-10-21T03:30:00Z` in New York → `2026-10-20` |
| 4 | Quiz `max_points` is `1` on create and Σ points after every `PUT questions` (`1` when the list is empty). Σ points > 10000 is 400 on `items` "total points must be at most 10000" (the existing `max_points <= 10000` check; 100 × 1000 would break it). | Spec gap (§3 lets 100 × 1000 = 100000) |
| 5 | Audit rows of this spec use `entity_type = 'assessment'`, `entity_id` = the assessment id, and carry `userId` in `after`. No new entity type, so the audit filter enum (`tenant/handler.go`, `openapi.json`, web `audit-log.tsx`) does not change. `score.set` already does this. | Avoids a web/contract change outside every lane's scope |
| 6 | Per-question `points` in `grading` (jsonb and API) and every score are **JSON numbers** backed by `json.Number` with 2 decimals (D68), not the string `"2.00"` of §3's example. `math/big` only, never floats. | Spec 4 contract convention |
| 7 | Students see answer keys (`correct`, `answers`) only when the quiz is published **and** their own attempt is submitted (spec says "published"; a quiz published before or during its window would otherwise leak keys mid-attempt). Escalated as E3. | Review Focus 2 |
| 8 | `grading`, `score`, `feedback` (attempt) and `score`, `feedback`, `gradedAt` (submission) are hidden from students until `published`. Hidden = omitted (pointer/omitempty fields), never `null`. | Spec §5, D16 |
| 9 | `UpsertScore` lives in `grade/score.go` and is written by **Task 3** (not 4b): Tasks 4 and 5 run in parallel from Task 3's head and both call it. Escalated as E5 (scope). | Avoid two lanes adding the same function |
| 10 | Submission-file upload/download reuse: **export two helpers from `content`** (`content.ReceiveFile`, `content.ServeFile`), refactoring `receive` and `downloadMaterial` onto them. Not moved into `blob`: the allowlist (`fileTypes`) is shared with `uploadPolicy` and the errors are `httpx` errors; moving would make `blob` import `httpx` and drag `uploadPolicy` along. Files: `content/material.go`, `content/download.go`. | Smallest diff; material tests are the regression |
| 11 | Blobs of cascaded `submission_files` are removed after commit on assessment delete (`grade/assessment.go deleteAssessment(files)`) and section delete (`course/section.go`, the existing material-id query gains a `union all`). `prune-files` catches anything else. | Spec §7 "cascade removes blobs" |
| 12 | Removing the last file of a submission whose body is empty deletes the submission row in the same statement sequence (the "body or file" rule holds); the `scores` row, if any, stays. A student's replace after grading keeps the grade (staff see `submittedAt > gradedAt`). | Spec §3 invariant; no un-grade surprise |
| 13 | Review sets `correct = (points == question points)` for each edited entry. | The results view shows accepted spellings as correct |
| 14 | `PUT …/questions` accepts 0..100 items. | "a quiz with no questions keeps max_points 1" |
| 15 | Quiz package helpers (`sectionExists`, `allow`, `enrolled`, `loadWork`) are small private copies in `quiz` and `assignment` (grade's and content's are unexported). No new `authz` predicate: "enrolled student" is the SQL in §7. | Each package self-contained, no shared-file edits |
| 16 | 409 texts not given by the spec: "the quiz has no questions", "already submitted", "the attempt is not submitted", "not open yet"/"closed" for questions GET and submission writes. | Spec gaps |

## 1. Migration `apps/api/migrations/0010_quizzes_and_assignments.sql` (Task 3)

```sql
-- Spec 11 §3: quizzes and assignments are assessments with a kind (D138). Their answers live in jsonb
-- on the attempt row; files of submissions are blobs at UNICOURSE_FILES_DIR/<university_id>/<file_id>.
alter table assessments
  add column kind text not null default 'manual' check (kind in ('manual', 'quiz', 'assignment')),
  add column description text not null default '' check (char_length(description) <= 10000),
  add column opens_at timestamptz,
  add column closes_at timestamptz,
  add constraint assessments_window_check check (case when kind = 'manual' then opens_at is null and closes_at is null
    else opens_at is not null and closes_at is not null and opens_at < closes_at end);

-- choices: [{"text": "...", "correct": true}], answers: ["accepted", ...]; shapes validated by the handler (D139).
create table questions (
  id uuid primary key default gen_random_uuid(),
  university_id uuid not null references universities(id) on delete cascade,
  assessment_id uuid not null,
  kind text not null check (kind in ('choice', 'blank')),
  prompt text not null check (char_length(prompt) between 1 and 2000),
  points numeric(7,2) not null check (points > 0 and points <= 1000),
  position integer not null check (position >= 1),
  choices jsonb not null default '[]',
  answers jsonb not null default '[]',
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now(),
  foreign key (university_id, assessment_id) references assessments (university_id, id) on delete cascade
);
create index on questions (assessment_id, position);

-- One attempt per student (D140). score is set exactly when submitted.
create table attempts (
  id uuid primary key default gen_random_uuid(),
  university_id uuid not null references universities(id) on delete cascade,
  assessment_id uuid not null,
  user_id uuid not null references users(id) on delete cascade,
  started_at timestamptz not null default now(),
  submitted_at timestamptz,
  auto_submitted boolean not null default false,
  answers jsonb not null default '{}',
  grading jsonb not null default '{}',
  score numeric(7,2) check (score >= 0),
  feedback text not null default '' check (char_length(feedback) <= 5000),
  reviewed_by uuid references users(id),
  reviewed_at timestamptz,
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now(),
  check ((submitted_at is null) = (score is null)),
  unique (university_id, assessment_id, user_id),
  foreign key (university_id, assessment_id) references assessments (university_id, id) on delete cascade
);
create index on attempts (assessment_id, submitted_at);
create index on attempts (user_id);

create table submissions (
  id uuid primary key default gen_random_uuid(),
  university_id uuid not null references universities(id) on delete cascade,
  assessment_id uuid not null,
  user_id uuid not null references users(id) on delete cascade,
  body text not null default '' check (char_length(body) <= 20000),
  submitted_at timestamptz not null default now(),
  score numeric(7,2) check (score >= 0),
  feedback text not null default '' check (char_length(feedback) <= 5000),
  graded_by uuid references users(id),
  graded_at timestamptz,
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now(),
  unique (university_id, assessment_id, user_id),
  unique (university_id, id),
  foreign key (university_id, assessment_id) references assessments (university_id, id) on delete cascade
);
create index on submissions (user_id);

-- size_bytes has no upper bound here: the limit is UNICOURSE_MAX_UPLOAD_BYTES (blob.Dir.Limit).
create table submission_files (
  id uuid primary key default gen_random_uuid(),
  university_id uuid not null references universities(id) on delete cascade,
  submission_id uuid not null,
  file_name text not null check (char_length(file_name) between 1 and 255),
  content_type text not null check (content_type <> ''),
  size_bytes bigint not null check (size_bytes >= 1),
  sha256 text not null check (sha256 ~ '^[0-9a-f]{64}$'),
  position integer not null check (position >= 1),
  uploaded_at timestamptz not null default now(),
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now(),
  foreign key (university_id, submission_id) references submissions (university_id, id) on delete cascade
);
create index on submission_files (submission_id, position);
```
Then, for each of `questions`, `attempts`, `submissions`, `submission_files`: the three RLS lines of `0007` (`enable`, `force`, `create policy tenant_isolation … using (…) with check (…)` verbatim) and `create trigger <t>_set_updated_at before update on <t> for each row execute function set_updated_at();`. ## 2. `grade` changes (Task 3)

```go
type Assessment struct {
	ID            string      `json:"id"`
	SectionID     string      `json:"sectionId"`
	Kind          string      `json:"kind"`
	Name          string      `json:"name"`
	Description   string      `json:"description"`
	MaxPoints     json.Number `json:"maxPoints"`

	OpensAt       *time.Time  `json:"opensAt,omitempty"`  // UTC

	Position      int         `json:"position"`
	QuestionCount *int        `json:"questionCount,omitempty"` // quizzes only
}
const assessmentCols = `id, section_id, kind, name, description, max_points::text, weight::text,
  coalesce(to_char(due_on, 'YYYY-MM-DD'), ''), opens_at, closes_at, published, position,
  case when kind = 'quiz' then (select count(*)::int from questions q where q.assessment_id = assessments.id) end`
```
`scanAssessment` scans `opens_at`/`closes_at` into `sql.NullTime` (→ pointer, `.UTC()`) and the count into `sql.NullInt32`. Every user of `assessmentCols` selects `from assessments` without an alias (insert/update `returning` too; verified).

**Create** body (D46 tags): `kind string`, `name`, `description string`, `maxPoints json.Number`, `weight`, `dueOn string`, `opensAt string`, `closesAt string`, `published bool`, `position *int`. **PATCH** gains `description tenant.Opt[string]`, `opensAt tenant.Opt[string]`, `closesAt tenant.Opt[string]` (null → "must not be null"), merged over the row as today.

| Field | Rule (errors collected in body order, all at once) | Message |
|---|---|---|
| `kind` | omitted = `manual`; else one of the three | "must be manual, quiz or assignment" |
| `description` | trimmed, inner line breaks kept, no NUL, ≤ 10000 runes (copy `content.optText`'s rules) | "must not contain NUL" / "must be at most 10000 characters" |
| `maxPoints` | quiz: given (create or PATCH) → error; else Spec 4 rule | "derived from the questions" |
| `dueOn` | quiz/assignment: given → error; manual: Spec 4 rule | "derived from closesAt" |
| `opensAt`, `closesAt` | manual: given → error. quiz/assignment: required, `time.Parse(time.RFC3339, v)` | "only for quizzes and assignments" / "is required" / "must be an RFC 3339 time" |
| `closesAt` | after `opensAt` (Go comparison of the two parsed values, not the clock) | "must be after opensAt" |

No rule against a window in the past. Insert (quiz `max_points` = `'1'`):
```sql
insert into assessments (university_id, section_id, kind, name, description, max_points, weight, opens_at, closes_at, due_on, published, position)
values ($1, $2, $3, $4, $5, $6::numeric, $7::numeric, $8::timestamptz, $9::timestamptz,
  case when $3 = 'manual' then nullif($10, '')::date
       else ($9::timestamptz at time zone (select timezone from universities where id = $1))::date end,
  $11, coalesce($12::int, (select coalesce(max(position) + 1, 0) from assessments where section_id = $2)))
returning <assessmentCols>
```
Update sets `description`, `opens_at`, `closes_at` and `due_on = case when kind = 'manual' then nullif($5, '')::date else ($10::timestamptz at time zone (select u.timezone from universities u where u.id = assessments.university_id))::date end`; it never writes `kind`, and writes `max_points` only for non-quiz rows. Audit `assessment.create/update/delete` carries the widened struct unchanged.

**Student listing** (`listSectionAssessments`): `where section_id = $1 and (published or kind <> 'manual' or not $2)`. `GET /me/grades` (`gpa.go`) keeps its published-only rule; see E1 for `kind` there.

**`UpsertScore`** (`grade/score.go`, Task 3, with a test in `score_test.go`):
```go
// UpsertScore sets the scores row of (assessmentID, userID) to points, a canonical 2-decimal string,
```

## 4. `internal/quiz` (Task 4)

### 4.1 Types
```go
type Choice struct {
	Text    string `json:"text"`
	Correct *bool  `json:"correct,omitempty"` // stored and shown to staff; nil = hidden
}
type Question struct {
	ID       string      `json:"id"`
	Kind     string      `json:"kind"` // choice | blank
	Prompt   string      `json:"prompt"`
	Points   json.Number `json:"points"`

	Choices  []Choice    `json:"choices"`           // [] for blank
	Answers  *[]string   `json:"answers,omitempty"` // nil = hidden; &[]string{} for choice
}

	Choices []int  `json:"choices,omitempty"`

}
type Mark struct {

	Answers       map[string]Answer `json:"answers"`           // never nil
	Grading       *map[string]Mark  `json:"grading,omitempty"` // nil = hidden
```

### 4.2 Pure grading (`grading.go`, 4a, tests first, `-race` gate)
```go
// autoGrade marks every question of qs (one Mark per question id, unanswered = 0, correct false) and
// returns the total as a 2-decimal string. Pure: no clock, no database.
func autoGrade(qs []Question, answers map[string]Answer) (marks map[string]Mark, total string)
func normalize(s string) string { return strings.Join(strings.Fields(strings.ToLower(s)), " ") }
```
choice: set of chosen indexes (duplicates collapse) equals the set of `i` with `*Choices[i].Correct`; blank: `normalize(a.Text) != ""` and equals `normalize` of one accepted answer. Points from `big.Rat.SetString(q.Points)`, total `Σ.FloatString(2)`, mark points `FloatString(2)`. Answers whose key is not a question are ignored. `// ponytail: no Unicode normalisation (NFC) — "é" typed two ways differs; add golang.org/x/text when a course needs it` (not allowed today, D1).

`TestAutoGrade` table; questions: `c1` choice 2.00 `[A✓, B, C]`; `c2` choice 1.50 `[A✓, B✓, C]`; `b1` blank 3.25 `["Paris", "  New   York "]`.

### 4.3 Routes, check order, errors
Order everywhere: section 404 → `loadWork(kind='quiz')` 404 → role 403 → entity 404 (attempt) → state 409 → body 400.

| Route | Role (403 otherwise) | State 409 | Body / behaviour |
|---|---|---|---|
| `GET …/questions` | editor; or enrolled | student without a submitted attempt: `Upcoming` "not open yet", `Closed` "closed" | `{items: Question[]}` by position; student: `hideKeys()` unless `published` and own attempt submitted |
| `PUT …/questions` | editor | `loadWork(…, "for update")`; any attempt exists → "questions are locked once a student has started" | §4.4; replaces rows, `max_points`, audit `question.update`; returns `{items}` |
| `GET …/attempts` | editor | – | `AttemptRow` list: `from attempts a join enrollments e on e.section_id = $2 and e.user_id = a.user_id join users u on u.id = a.user_id where a.assessment_id = $1 order by coalesce(nullif(u.display_name, ''), u.email), u.email` |
| `POST …/attempts` | enrolled | `Upcoming` "not open yet"; `Closed` "closed"; no questions "the quiz has no questions" | `insert … on conflict (university_id, assessment_id, user_id) do nothing returning …`: inserted → 201 + audit `attempt.start` (`after {userId}`); else read existing → 200, no audit |
| `GET …/attempts/{userId}` | `target` | – | 404 "attempt" when none; student: `hideResults()` unless published |
| `PUT …/attempts/me` | enrolled | attempt `for update` (404 "attempt" when none); submitted → "already submitted"; `Closed` → "closed; your answers as of the closing time were submitted" | §4.5 |
| `PATCH …/attempts/{userId}` | editor | attempt `for update`; not submitted → "the attempt is not submitted" | §4.6 |

### 4.4 Questions `PUT` (4a)
Body `{ "items": [ { "kind", "prompt", "points": json.Number, "choices": [{ "text", "correct": bool }], "answers": [string] } ] }` (item struct with explicit tags; `choices`/`answers` optional). `validation_failed` lists every error:

| Field | Rule | Message |
|---|---|---|
| `items` | 0..100 | "must have at most 100 questions" |
| `items[i].kind` | `choice`/`blank` | "must be choice or blank" |
| `items[i].prompt` | trimmed, line breaks kept, no NUL, 1..2000 runes | "is required" / "must be at most 2000 characters" / "must not contain NUL" |
| `items[i].points` | `tenant.Decimal(…, 2, "0.01", "1000")` | its messages |
| `items[i].choices` | choice: 2..10, ≥ 1 correct; blank: absent or empty | "must have 2 to 10 choices" / "must have at least one correct choice" / "only for multiple choice" |
| `items[i].choices[j].text` | trimmed 1..500, no control characters | "is required" / "must be at most 500 characters" |
| `items[i].answers` | blank: 1..20; choice: absent or empty | "must have 1 to 20 accepted answers" / "only for fill in the blank" |
| `items[i].answers[j]` | trimmed 1..200 | "is required" / "must be at most 200 characters" |
| `items` | Σ points ≤ 10000 (only when every item is valid) | "total points must be at most 10000" |

Write: `delete from questions where assessment_id = $1`; one `insert … select … from unnest($kinds::text[], $prompts::text[], $points::text[], $choices::text[], $answers::text[]) with ordinality as x(k, p, pts, c, a, n)` with `position = n`, `pts::numeric`, `c::jsonb`, `a::jsonb` (Go-marshalled, choices stored as `{text, correct}`); `update assessments set max_points = $2::numeric where id = $1` (Σ or `1`). Audit `question.update`, `before`/`after` `{questionCount, totalPoints}`.

### 4.5 Save and submit (4b)
Body `{ "answers": map[string]Answer, "submit": bool }`; `answers` required ("is required"). Per key, against the quiz's questions:

| Field | Rule | Message |
|---|---|---|
| `answers.<id>` | a question of this quiz | "is not a question of this quiz" |
| `answers.<id>.choices` | choice: distinct, each 0..n-1; blank: empty | "must be distinct indexes from 0 to <n-1>" / "only for multiple choice" |
| `answers.<id>.text` | blank: ≤ 1000 runes, no NUL; choice: empty | "must be at most 1000 characters" / "only for fill in the blank" |

Stored as given minus empty entries (`update attempts set answers = $3::jsonb`). With `submit: true` the same transaction calls `submit(…, false)`. Returns the `Attempt` (student projection).

```go
// submit grades the stored answers of (assessmentID, userID), sets grading, score, submitted_at
// (now() for a student, the quiz's closes_at when auto), auto_submitted; upserts scores (graded_by =
// the student) and writes audit attempt.submit (actor: the student, or none when auto; after
// {userId, score, auto}). The caller holds the attempt row lock. errAlreadySubmitted when the
// guarded update touched no row.
func submit(ctx context.Context, tx *sql.Tx, universityID, assessmentID, userID string, auto bool) error
```
SQL core: questions `select id, kind, points::text, choices, answers from questions where assessment_id = $1 order by position`; `update attempts set grading = $3::jsonb, score = $4::numeric, auto_submitted = $5, submitted_at = case when $5 then (select closes_at from assessments where id = $1) else now() end where assessment_id = $1 and user_id = $2 and submitted_at is null`; then `grade.UpsertScore(ctx, tx, universityID, assessmentID, userID, total, userID)`.

Race reasoning (Review Focus 1): the student path locks the attempt `for update` and reads `Closed` in the same transaction; the sweeper claims `skip locked`. A row the student holds is swept on the next pass; a row the sweeper holds makes the student wait, then read `submitted_at` → 409. A sweeper whose snapshot predates another's commit re-checks `submitted_at is null` on lock (EvalPlanQual), and `submit`'s guarded update is the last line of defence.

### 4.6 Review (4c)
Body `{ "grading"?: { "<questionId>": { "points": json.Number, "feedback"?: string } }, "feedback"?: string }` (top-level `tenant.Opt`; neither → `tenant.NoFields()`). Errors: `grading.<id>` "is not a question of this quiz"; `grading.<id>.points` `tenant.Decimal(…, 2, "0", <question points>)`; `grading.<id>.feedback` ≤ 2000 runes; `feedback` ≤ 5000 runes (trimmed, line breaks kept, no NUL). Apply: replace `points`, set `correct = points == question points` (big.Rat `Cmp`), `feedback` only when given; score = Σ marks; `update attempts set grading, score, feedback, reviewed_by = $actor, reviewed_at = now()`; `grade.UpsertScore(…, score, s.UserID)`; audit `attempt.review` `before {userId, score}` `after {userId, score}`. Returns the staff `Attempt`.

### 4.7 Sweeper (`sweeper.go`, 4b)
```go
// Sweeper submits the open attempts of closed quizzes (D140). Any number of processes may run one:
// rows are claimed with FOR UPDATE SKIP LOCKED in per-university tenant transactions.
type Sweeper struct {
	DB    *sql.DB
	Log   *slog.Logger
	Poll  time.Duration // 10s
	Batch int           // attempts per transaction, 100
}
func NewSweeper(db *sql.DB, log *slog.Logger) *Sweeper
// Run sweeps, then waits for the poll tick, until ctx is done; errors are logged, never fatal.
func (s *Sweeper) Run(ctx context.Context)
// Sweep is one pass over every university; it returns how many attempts it submitted.
func (s *Sweeper) Sweep(ctx context.Context) (int, error)
```
`Sweep`: `pg.WithPlatformTx` → `select id::text from universities order by id`; per university `sweepUniversity` loops transactions under `pg.WithTx(ctx, s.DB, uni, …)` until one claims fewer than `Batch`:
```sql
select a.assessment_id::text, a.user_id::text from attempts a join assessments q on q.id = a.assessment_id
where a.submitted_at is null and q.closes_at <= now()
order by q.closes_at, a.id limit $1 for update of a skip locked
```
(rows read and closed, then `submit(ctx, tx, uni, aid, uid, true)` each; `errAlreadySubmitted` is skipped, not an error). One university's error is logged (`"quiz sweeper", "universityId", uni, "err", err`) and the pass continues; `Sweep` returns `errors.Join` of them. After a university with `n > 0`: `s.Log.Info("quiz attempts submitted", "universityId", uni, "count", n)`. `// ponytail: one bad row rolls back its whole batch every pass; a savepoint per attempt if that is ever seen`. `cmd/api/main.go`, after `go sender.Run(ctx)`: `go quiz.NewSweeper(db, logger).Run(ctx)`.

Tests fake time in SQL only (D30): create through the API with a future window, start attempts, then `update assessments set opens_at = now() - interval '2 hours', closes_at = now() - interval '1 hour' where id = $1` (one statement; the window check holds). Two-process test: 30 attempts, two `NewSweeper(db, …)` with `Batch: 4`, `Sweep` in two goroutines (shared pool, separate connections); assert the two counts sum to 30, every attempt `submitted_at = closes_at` and `auto_submitted`, exactly 30 `attempt.submit` audit rows and 30 `scores` rows. Run with `-race`.

## 9. Open risks

- Inline gradebook score entry (D144) can make `scores.points` differ from `attempts.score`; the next review or submit overwrites it. Documented, not prevented.
- The sweeper runs one transaction per university every 10 s even when nothing is due; fine at today's tens of universities, a platform-level "any closed open attempt" query needs a non-RLS view if that grows.
- Postgres and Go tzdata could disagree on a newly added zone name; the insert would fail 500 on such a university until Postgres' tzdata is updated.
- Autosave writes the whole `answers` map per change; at the §11 scale (300 × 50) this is fine.
