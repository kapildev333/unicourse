# P19-L1 design: quiz and assignment follow-ups (API, data, web)

Source: Spec 12 `docs/specs/2026-10-09-quiz-and-assignment-followups.md` §3-§7 (binding; D149-D152 ruled); plan `docs/plans/2026-10-09-quiz-and-assignment-followups.md` Tasks 2-5, 7 and Review Focus 1-3. Builds on `docs/design/P18-L1.md` (API) and `docs/design/P18-L2.md` (web); their conventions hold unless restated. Task 6 (timeouts) is P19-L6 and not designed here; its `content.ReceiveFile(files, timeout, …)` signature change is on Task 5's path (§5.4). Where this document and the code disagree on a convention, the code wins; on behaviour, this document wins.

## 0. Decisions taken here

| # | Decision | Why |
|---|---|---|
| 1 | The effective deadline is one Go constant `deadlineSQL` in a new `quiz/deadline.go`, written by **Task 2** together with the student `GET questions` gate. Tasks 3 and 4 then touch disjoint files (§6). | `listQuestions` (question.go) needs the deadline and question.go is Task 3's; one owner per file |
| 2 | `least()` ignores NULL in Postgres, so `least(a.started_at + make_interval(mins => q.time_limit_minutes), q.closes_at)` is `closes_at` without a limit and without an attempt; no `coalesce`. Verified on the local Postgres. | One expression for every case |
| 3 | A student without an attempt gets 409 "not started" from `GET questions` of a **timed** quiz while it is open. Untimed quizzes keep Spec 11's behaviour. | Otherwise a student reads every question before starting the clock. Escalated E2 |
| 4 | `manual: true` is set by a review only on an entry whose **points change** (compared with `big.Rat`), and stays once set. A feedback-only edit does not set it. A regrade recomputes points and `correct` of every non-manual entry and **keeps its feedback**. | "a reviewed question keeps its reviewed points" (§1) without freezing an entry whose points the reviewer only confirmed; feedback is never lost |
| 5 | The regrade updates questions **in place** (ids kept; attempts key answers and grading by question id). The no-attempt path still deletes and re-inserts, and ignores `id`. | Answers would otherwise point at deleted ids |
| 6 | `submissions.late` is set by every student write while `now() >= closes_at` (the `>=` of today's `Closed`; spec §3 says `>`). | One boundary for "closed" and "late" |
| 7 | `finalScore` is read from the `scores` row (what the gradebook holds); `penaltyPercent` is the assessment's current percent. Changing the percent touches no row until the grade is saved again. | No new column; "Recorded as" copy is literally the gradebook value. Escalated E3 |
| 8 | Half-up rounding = `big.Rat.FloatString(2)` (rounds halves away from zero; every value here is ≥ 0). | No hand-written rounding |
| 9 | Moving `closesAt` to or past a stored `lateUntil` is 400 on `closesAt` "must be before lateUntil" (message not in spec §5). If the request also names `lateUntil`, the error is on `lateUntil` "must be after closesAt" instead. | Spec §7 puts it on `closesAt`; the field the user touched carries it |
| 10 | Spec §6's "caution `StatusMessage`" is a warning `Badge` "Past due" plus a plain sentence: `StatusMessage` is success-only (green, `Check` icon, `role="status"`). | No component change; status colour still means caution. Escalated E4 |
| 11 | The "Late" badge on the grading table is neutral (D87: state badges are neutral, like "Auto"). | Existing rule |

## 1. Migration `apps/api/migrations/0011_quiz_and_assignment_followups.sql` (Task 2)

```sql
-- Spec 12 §3: per-attempt time limit for quizzes (D150), late window and penalty for assignments (D151).
-- The effective deadline of an attempt is computed in SQL (quiz/deadline.go), never stored.
alter table assessments
  add column time_limit_minutes integer,
  add column late_until timestamptz,
  add column late_penalty_percent numeric(5,2) not null default 0,
  add constraint assessments_time_limit_check
    check (time_limit_minutes is null or (kind = 'quiz' and time_limit_minutes between 1 and 1440)),
  add constraint assessments_late_until_check
    check (late_until is null or (kind = 'assignment' and late_until > closes_at)),
  add constraint assessments_late_penalty_check
    check (late_penalty_percent between 0 and 100 and (late_penalty_percent = 0 or kind = 'assignment'));

-- Set by any student write at or after closes_at; never cleared (D151).
alter table submissions add column late boolean not null default false;
```
No new table, trigger or policy: `migrate_test.go` counts are unchanged. **pg tests** (`tx_test.go`): new `TestAssessmentFollowupChecks`, same shape as `TestAssessmentWindowCheck` (section by SQL, each insert must fail 23514): assignment with `time_limit_minutes 5`; quiz with 0 and with 1441; quiz with `late_until`; assignment with `late_until = closes_at`; manual with `late_penalty_percent 5`; assignment with `100.01`. Then valid: quiz `time_limit_minutes 1440`; assignment `late_until = closes_at + 1 day, late_penalty_percent 100`. Insert columns: `(university_id, section_id, name, max_points, weight, kind, opens_at, closes_at, time_limit_minutes, late_until, late_penalty_percent)`.

## 2. `grade` (Task 2): fields and validation

`Assessment` gains (after `QuestionCount`):
```go
TimeLimitMinutes   *int        `json:"timeLimitMinutes,omitempty"`   // quizzes only, nil = no limit
LateUntil          *time.Time  `json:"lateUntil,omitempty"`          // assignments only, UTC
LatePenaltyPercent json.Number `json:"latePenaltyPercent,omitempty"` // assignments only, always present for them
```
`assessmentCols` appends `time_limit_minutes, late_until, case when kind = 'assignment' then late_penalty_percent::text end`; `scanAssessment` scans `sql.NullInt32`, `sql.NullTime` (`.UTC()`), `sql.NullString`.

Body fields. Create: `timeLimitMinutes json.Number`, `lateUntil string`, `latePenaltyPercent json.Number` (absent or `null` = not given). PATCH: `tenant.Opt[json.Number]`, `tenant.Opt[string]`, `tenant.Opt[json.Number]`; `null` **clears** `timeLimitMinutes` and `lateUntil`; `latePenaltyPercent: null` joins the existing "must not be null" loop. They count for the `NoFields` check. `fieldsIn` gains `TimeLimit json.Number`, `LateUntil string`, `Penalty json.Number` (merged values; PATCH starts from the row) and `SetTimeLimit`, `SetLateUntil`, `SetPenalty bool` (named in this request with a non-null value).

| Field | Rule (in `assessmentFields`, after `closesAt`, body order, all errors at once) | Message |
|---|---|---|
| `timeLimitMinutes` | kind ≠ quiz and `SetTimeLimit` | "only for quizzes" |
| | quiz, value ≠ "": `strconv.Atoi` succeeds and 1..1440 (so `10.5`, `1e1`, `"x"` fail) | "must be between 1 and 1440" |
| `lateUntil` | kind ≠ assignment and `SetLateUntil` | "only for assignments" |
| | assignment, value ≠ "": `time.Parse(time.RFC3339, v)` | "must be an RFC 3339 time" |
| | parsed, `closesAt` parsed, `!late.Round(µs).After(closes.Round(µs))`: if `SetLateUntil` the error goes on `lateUntil`, else on `closesAt` | "must be after closesAt" / "must be before lateUntil" |
| `latePenaltyPercent` | kind ≠ assignment and `SetPenalty` | "only for assignments" |
| | assignment: "" → "0"; else `tenant.Decimal("latePenaltyPercent", v, 2, "0", "100")` (its range text is the spec's) | "must be between 0 and 100" (and Decimal's others) |

Non-assignments always write `late_penalty_percent = 0`. A penalty without `lateUntil` is accepted and stored (it applies to submissions already `late`; §5.2). Insert adds `time_limit_minutes = nullif($13, '')::int, late_until = nullif($14, '')::timestamptz, late_penalty_percent = $15::numeric`; update sets the same three from the merged values. Audit rows carry the widened struct unchanged.

**Tests** (`assessment_test.go`, Task 2): `TestAssessmentTimeLimit` (quiz 10 → 201 and `timeLimitMinutes` 10; 0, 1441, 10.5 → "must be between 1 and 1440"; assignment and manual → "only for quizzes"; PATCH 30 then `null` clears, field absent in JSON); `TestAssessmentLateWindow` (assignment with `lateUntil` + 20 → both in JSON; `latePenaltyPercent` 0 present when omitted; `lateUntil = closesAt` → "must be after closesAt"; 100.01 and -1 → "must be between 0 and 100"; quiz/manual → "only for assignments" each field; PATCH `lateUntil: null` clears); `TestAssessmentCloseAfterLate` (PATCH `closesAt` past the stored `lateUntil` → 400 field `closesAt` "must be before lateUntil"; PATCH both wrong → field `lateUntil`; PATCH both right → 200).

## 3. Effective deadline (Task 2 file, Task 4 users)

`quiz/deadline.go` (Task 2):
```go
// deadlineSQL is the effective deadline of attempt a of quiz q (D150): started_at plus the limit, never after
// the close. least() ignores NULL, so it is q.closes_at without a limit (and for a missing left-joined attempt).
// Every query using it names attempts "a" and assessments "q".
const deadlineSQL = `least(a.started_at + make_interval(mins => q.time_limit_minutes), q.closes_at)`
```
**Student `GET questions`** (Task 2 edits only the student branch of `listQuestions`): replace the `exists(...)` query with
```sql
select a.user_id is not null, coalesce(a.submitted_at is not null, false), q.time_limit_minutes is not null, now() >= <deadlineSQL>
from assessments q left join attempts a on a.assessment_id = q.id and a.user_id = $2 where q.id = $1
```
then, in order: submitted → 200 (keys rule unchanged); `w.Upcoming` → 409 "not open yet"; past deadline → 409 "closed"; timed and no attempt → 409 "not started"; else 200 with keys hidden. Test file `deadline_test.go` (Task 2): `TestQuestionsStudentDeadline` (timed, no attempt → "not started"; attempt with `started_at = now() - 11 min` on a 10-minute limit → "closed" while the window is open; started 5 min ago → 200, keys hidden; untimed, no attempt, open → 200 as before).

Users (Task 4):
- `Attempt` gains `DeadlineAt time.Time \`json:"deadlineAt"\`` (after `StartedAt`, every projection). `loadAttempt` selects `from attempts a join assessments q on q.id = a.assessment_id where a.assessment_id = $1 and a.user_id = $2` plus `<deadlineSQL>`; a non-empty `lock` becomes `lock + " of a"` (callers keep passing "for update").
- `putAttempt`: the `w.Closed` check and the `clock_timestamp() >= closes_at` check become `pastDeadline(ctx, tx, w.ID, s.UserID, "now()")` and `(…, "clock_timestamp()")`, same 409 text "closed; your answers as of the closing time were submitted":
  ```go
  // pastDeadline: select <clock> >= deadlineSQL from attempts a join assessments q on q.id = a.assessment_id
  // where a.assessment_id = $1 and a.user_id = $2. clock is the constant "now()" or "clock_timestamp()".
  func pastDeadline(ctx context.Context, tx *sql.Tx, assessmentID, userID, clock string) (bool, error)
  ```
  `startAttempt` keeps `w.Closed` (the window); a start near the close simply gets a clamped deadline.
- `submit` (auto): `update attempts a set … submitted_at = case when $5::boolean then (select <deadlineSQL> from assessments q where q.id = a.assessment_id) else now() end where a.assessment_id = $1 and a.user_id = $2 and a.submitted_at is null`.
- Sweeper claim: `… where a.submitted_at is null and <deadlineSQL> <= now() order by <deadlineSQL>, a.id limit $1 for update of a skip locked`. Mixed deadlines: earliest first across timed and untimed attempts of every quiz in the university; ties by id. Batches and `skip locked` unchanged; race reasoning of P18-L1 §4.5 holds with "deadline" for "close". `// ponytail: the filter scans every unsubmitted attempt of the university each pass; an index on (submitted_at) where submitted_at is null if that grows`.

A changed limit or close applies to running attempts at once (the expression is live); see risks.

## 4. Regrade (Task 3)

**Request.** `questionIn` gains `ID string \`json:"id"\``; `checkQuestions` copies it into its output. Contract: `QuestionInput.id` (uuid, optional; "Required once a student has started; the id of the question at this position.").

**`putQuestions` flow** (the `started` 409 before decoding goes away):
1. section 404 → `loadWork(…, "for update")` 404 → editor 403 (unchanged). `started` read as today.
2. decode; `items` required; `checkQuestions` → 400 with every Spec 11 error (including the 10000 total).
3. Not started: today's delete + insert; `id` ignored.
4. Started: any item with `id == ""` → 400 `items[i].id` "is required once a student has started" (all at once). Then `existing := keyedQuestions(…)` (by position) and `sameStructure(existing, items)` false → 409 "questions are locked once a student has started". **Same structure** means: `len(items) == len(existing)`, and for every `i`: `items[i].ID == existing[i].ID` (that is "order": the item at index *i* names the question now at position *i*+1; an unknown, foreign or malformed id fails the same way), `items[i].Kind == existing[i].Kind`, and for `choice` `len(items[i].Choices) == len(existing[i].Choices)`. Prompt, points, choice texts, `correct` flags and `answers` may differ (a choice question may go from one correct choice to several).
5. Started, same structure, in `regrade.go`:
   ```go
   // regrade applies items to the quiz's questions in place and regrades every submitted attempt (D149).
   // The caller holds the assessment row lock and has checked sameStructure.
   func regrade(ctx context.Context, tx *sql.Tx, s authz.Scope, assessmentID string, items []questionIn) error
   ```
   a. `select 1 from attempts where assessment_id = $1 order by id for update` (all attempts: an in-flight student submit or sweeper claim finishes first; a later submit grades against the new keys because its `keyedQuestions` runs after this commit).
   b. `update questions q set prompt = x.v->>'prompt', points = (x.v->>'points')::numeric, choices = x.v->'choices', answers = x.v->'answers' from jsonb_array_elements($2::jsonb) as x(v) where q.assessment_id = $1 and q.id = (x.v->>'id')::uuid` (the same marshalled rows as the insert path, plus `id`).
   c. For each `select user_id::text, answers, grading, score::text from attempts where assessment_id = $1 and submitted_at is not null order by user_id`: `marks, total := regradeMarks(qs, answers, old)`; if `json.Marshal(marks)` equals `json.Marshal(old)` (map keys sort, so bytes compare) skip; else `update attempts set grading = $3::jsonb, score = $4::numeric where assessment_id = $1 and user_id = $2`, `grade.UpsertScore(…, total, s.UserID)`, audit `attempt.regrade` (`entity_type 'assessment'`, actor the editor, `before {userId, score}`, `after {userId, score}`). `reviewed_by`/`reviewed_at`/`feedback` untouched.
6. Both paths: `max_points` = new Σ (or 1), audit `question.update` as today, response `{items}` unchanged. Unsubmitted attempts: locked, never written. `final_grades`: never read or written.

`grading.go` (Task 3): `Mark` gains `Manual bool \`json:"manual,omitempty"\``, and
```go
// regradeMarks recomputes old against the current keys: a Manual entry is kept as is; every other question takes
// autoGrade's points and correct and keeps the old entry's feedback. total is Σ of the returned points (2 decimals).
func regradeMarks(qs []Question, answers map[string]Answer, old map[string]Mark) (map[string]Mark, string)
```
**Review** (`review.go`, Task 3): when an entry's points validate, `if got.Cmp(old points) != 0 { mark.Manual = true }` (old points from the stored mark; an absent mark counts as 0); `Manual` is never cleared. Contract: `Mark.manual` (boolean, optional, "Set when a review changed the points; a regrade keeps such an entry.").

**Tests** (Task 3): `grading_test.go` `TestRegradeMarks` (manual kept with its points and feedback; non-manual recomputed with feedback kept; total exact over 0.10 steps; a question missing from `old` gets its automatic mark). `regrade_test.go`: `TestRegradeKeyFlip` (two submitted attempts right/wrong on q2 and one in progress; flip q2's key → points swap, `attempts.score` = `scores.points` for both, `graded_by` = editor, in-progress attempt's `grading '{}'` and `score null` unchanged, exactly two `attempt.regrade` rows with before/after, one `question.update`); `TestRegradeKeepsManual` (review sets q2 to 1.5 and only feedback on q1; flip both keys → q2 keeps 1.5 and its feedback, q1 recomputed and keeps feedback); `TestRegradeNoChangeNoAudit` (same items with ids → 200, no `attempt.regrade`); `TestRegradePoints` (q1 2 → 4: `max_points` and the right answers' scores move); `TestRegradeIDsKept` (response ids equal the previous ones); `TestRegradeStructureLocked` (subtests, each 409 with the text: one more item, one fewer, two ids swapped, kind changed, a choice added, a choice removed, a random uuid, another quiz's id); `TestRegradeMissingID` (400 `items[1].id`); `TestRegradeValidationFirst` (bad points and a swapped order → 400). `review_test.go` `TestReviewSetsManual` (changed points → `manual`; same points with feedback → none; manual stays after a second review).

## 5. Late submissions (Task 5)

### 5.1 Window and the `late` write
`work` gains `Late bool` and `Penalty string`; `loadWork` selects `now() < opens_at, now() >= coalesce(late_until, closes_at), now() >= closes_at, late_penalty_percent::text` into `Upcoming, Closed, Late, Penalty`. `window()` is unchanged (its `Closed` now means "after the late window"; without one it is the due date as before, so writes after it stay 409 "closed"). Every student write passes `w.Late`:
- `putSubmission`: `insert into submissions (university_id, assessment_id, user_id, body, late) values ($1, $2, $3, $4, $5) on conflict (…) do update set body = excluded.body, submitted_at = now(), late = submissions.late or excluded.late`.
- `receive` (phase 2, re-checked `wk`): the same `late` column and `late = submissions.late or excluded.late` in its upsert.
- `deleteFile`: `update submissions set submitted_at = now(), late = late or $2 where id = $1`.

### 5.2 Penalty and the `scores` write
`grade.go`:
```go
// penalise returns score × (100 − percent) / 100 rounded half up to 2 decimals; score and percent are canonical
// non-negative decimals. big.Rat.FloatString rounds halves away from zero, which is half up for these values.
func penalise(score, percent string) string
```
`gradeSubmission`: validation unchanged (raw `score` ≤ 2 × max); `submissions.score` = raw; `points := score; if before.Late { points = penalise(score, w.Penalty) }`; `grade.UpsertScore(…, points, s.UserID)`; `gradeAudit` gains `FinalScore json.Number \`json:"finalScore,omitempty"\`` (after only). A later change of `latePenaltyPercent`, or a submission turning late after it was graded, changes nothing until the grade is saved again (D151 "applies at grading time").

### 5.3 JSON
`Submission` gains `Late bool \`json:"late"\``, `PenaltyPercent json.Number \`json:"penaltyPercent"\``, `FinalScore json.Number \`json:"finalScore,omitempty"\``; `SubmissionRow` gains `Late` and `FinalScore` (the percent is on the `Assessment` the page already has). `loadSubmission` selects from `submissions s join assessments a on a.id = s.assessment_id`, adding `s.late, a.late_penalty_percent::text, case when s.score is not null then coalesce((select sc.points::text from scores sc where sc.assessment_id = s.assessment_id and sc.user_id = s.user_id), '') else '' end`; a non-empty lock becomes `lock + " of s"`. The list query adds `s.late` and the same `scores` subquery. `hideGrade` also empties `FinalScore`; `late` and `penaltyPercent` are always visible to the student. `finalScore` is absent when a gradebook edit deleted the `scores` cell.

### 5.4 Tests and the P19-L6 overlap
`grade_test.go`: `TestPenalise` table: (15, 20) → 12.00; (12.50, 11) → **11.13** (11.125: half up; half-even or float printing gives 11.12); (0.01, 50) → 0.01; (17.35, 0) → 17.35; (20, 100) → 0.00; (40, 25) → 30.00. `TestGradeLate` (late, 20% → `scores.points` 12.00, response `score` 15 and `finalScore` 12.00, audit `finalScore`); `TestGradeLatePenaltyZero` (equal); `TestGradeOnTime` (late false, 20% → unpenalised); `TestGradePercentChangedLater` (PATCH the percent → `scores` unchanged until the grade is saved again). `submission_test.go`: `TestSubmissionLateWindow` (closes 1 h ago, late until in 1 h: PUT 200 and `late`; replace keeps `late`; file upload and file delete mark `late`); `TestSubmissionAfterLateUntil` (409 "closed" for PUT, upload, delete); `TestSubmissionNoLateWindow` (409 after due, as before); `TestSubmissionOnTimeNotLate`; `TestSubmissionStudentView` (`late` and `penaltyPercent` always, `finalScore` only when published); `TestSubmissionsListLate` (row `late`, `finalScore`). Fake time: `update assessments set opens_at = now() - interval '3 hours', closes_at = now() - interval '1 hour', late_until = now() + interval '1 hour'` (one statement satisfies every check).

## 9. Risks

- A shorter limit or earlier close saved while attempts run makes past deadlines at once: the sweeper submits them with `submitted_at` in the past, possibly before the last autosave it still grades (the answers stored at sweep time count). Not prevented.
- A regrade holds the quiz and all its attempt rows locked for one transaction: at 300 attempts × 100 questions that is a few hundred updates, well under a second; students saving meanwhile wait, not fail.
- The browser countdown trusts `deadlineAt` and the browser clock (P18-L2 risk 1 unchanged); the server's deadline decides.
- `regrade` reuses `keyedQuestions` (submit.go, Task 4's file) read-only; a signature change there in Task 4 breaks Task 3 at rebase, so Task 4 must not change it.
