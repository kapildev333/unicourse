Source: Spec 11 `docs/specs/2026-10-08-quizzes-and-assignments.md` §4-§7 (binding); plan Tasks 2, 6, 7, Review Focus 2; D137-D146, D23 (no toasts, `code:field` copy), D57/D58 (look), D60, D78 (rubric), D87 (neutral state badges, quiet row deletes), D100, D101. Visual rules: Spec 3, `docs/design/P6-L1.md`, CLAUDE.md UI conventions. Patterns copied from `features/section/{announcements,materials}.tsx` and `features/grades/{gradebook,assessment-dialog}.tsx`. API shapes: spec §5 plus the additions requested in §12 (P18-L1 decides them; the worker adapts names, not behaviour). ## 0. Decisions taken here

| # | Decision | Why |
|---|---|---|
| 1 | Quiz and assignment lists are `<ul>` of `<article>` items (the Announcements item: `rounded border border-line bg-surface p-4 sm:p-6`), not tables, not `Card` | Student-facing, several actions per item, long titles wrap; `Card` is a section link card. Tables stay for staff review/grading (CLAUDE "tables for admin") |
| 2 | Every row action is an explicit button or `ButtonLink`; titles are plain `h3` | One obvious action per intent; no hidden link-on-title |
| 3 | Student row: exactly one action. Quiz: **Start** (open, questions > 0, no attempt, primary), **Continue** (open, attempt not submitted, primary), **View** (every other case, secondary). Assignment: **View** (§11 item 2), primary while open | Spec §6; the take page owns every state, so a direct URL works too |
| 4 | Starting is explicit: the take page shows an intro with **Start quiz** (`POST …/attempts`); the list's Start only navigates | Intent preload (`defaultPreload: 'intent'`) must never create an attempt; one POST call site |
| 5 | State badges are neutral (D87): Upcoming, Open, Closed, Submitted; staff also see neutral **Scores released** and a warning **No questions** (caution: students cannot start) | No colour-only state; status colours only for caution |
| 6 | Window text: `Opens {formatDateTime(opensAt)} · Closes {formatDateTime(closesAt)}` (assignments `· Due`). `formatDateTime` prints the year ("Oct 12, 2026, 9:00 AM"); the spec example omits it (§11 item 5) | One date format app-wide; one middle dot per line (rubric 9.F) |
| 7 | Window state is computed from the browser clock (`now < opensAt` Upcoming, `< closesAt` Open, else Closed) and re-evaluated by `useNow(30_000)` (`window.ts`: `setInterval` state of `Date.now()`); display only, the server decides (D140) | A list left open across `opensAt` grows its Start button |
| 8 | One dialog for both kinds: `WindowDialog` in `features/quiz/quiz-dialog.tsx` with `kind: 'quiz' \| 'assignment'`; Task 7 imports it; no `assignment-dialog.tsx` | Same six fields; one copy map; plan file list changes (§11 item 7) |
| 9 | Routes are non-nested with trailing underscores (TanStack nests `quizzes.$assessmentId` under `quizzes.tsx` otherwise): `sections_.$id.quizzes.tsx`, `sections_.$id.quizzes_.$assessmentId.tsx`, `sections_.$id.quizzes_.$assessmentId_.questions.tsx`, `sections_.$id.quizzes_.$assessmentId_.attempts.tsx`; assignments the same with `submissions`. URLs are the spec's | Spec "non-nested"; the existing `sections_` convention |
| 10 | No route loaders (no existing section route has one); pages fetch through hooks inside `SectionFrame`; the router's `defaultPendingComponent` covers transitions | Existing pattern |
| 11 | Review and grading open one student in place through `?user=<id>` (validated search param), not `Disclosure` | A form inside a `<details>` inside a stacked table row breaks table semantics; one open form at a time; deep link and Back work; the panel fetches only its own attempt |
| 12 | The student learns radio vs checkbox from `Question.multiple` (API-derived, §12 R1). Hint inside the legend: "Choose one answer." / "Choose all that apply." | Spec "told one or more"; keys stay hidden |
| 13 | Countdown: visible line plus a separate `sr-only role="status"` announcer that speaks only at 10 min, 5 min, 1 min, 30 s and zero | A per-minute or per-second live region is noise for screen readers (§11 item 3) |
| 14 | Unsaved edits on the question editor, review panel and grading panel are guarded by a new shared `UnsavedChangesGuard` (router `useBlocker` + `beforeunload`, Dialog) | Up to 100 questions or long feedback lost by one tab click is data loss (§11 item 6, component scope) |
| 15 | "Release scores" asks for confirmation; "Hide scores" does not | Release shows keys to every student and cannot be unseen; hiding is harmless |
| 16 | Points and scores are JSON numbers, formatted with `fmtNum`, parsed with `parseDecimal` (`features/grades/grade.ts`), as Spec 4 | Existing contract (`Assessment.maxPoints: number`) |
| 17 | Student file removal has no confirm | Own file, window open, re-uploadable; status line confirms |
| 18 | Correct/incorrect in results and review: neutral `Badge` "Correct"/"Incorrect" with Lucide `Check`/`X` | A wrong answer is not an app error, so no danger colour (CLAUDE status colours) |

|---|---|

## 2. Tabs, routes, shared pieces

**Tabs** (`section-tabs.tsx`): Home, Announcements, Materials, **Quizzes**, **Assignments**, Participants, Grades. The two new links sit inside the existing `a.canRead` fragment after Materials (6a adds Quizzes, 7 adds Assignments). Phone: `TabNav` is `overflow-x-auto snap-x`; seven tabs scroll horizontally at 390 px (checked in the class list; no wrap). Risk §13.3: the current tab can start off-screen.

**Route files** (each `createFileRoute`, `component` reads `Route.useParams()` and renders the page, as `sections_.$id.materials.tsx`): the 8 files of decision 9. `…attempts.tsx` and `…submissions.tsx` add `validateSearch: (s) => ({ user: typeof s.user === 'string' ? s.user : undefined })`. Back links: take/editor/review pages start with `TextLink`-styled `ArrowLeft` link "All quizzes" (assignments: "All assignments") to the list, class `mb-3 inline-flex items-center gap-1 text-sm font-medium text-accent hover:underline` (the band's `backClass`).

**`window.ts`**: `windowState(a, now): 'upcoming' | 'open' | 'closed'`; `windowLine(a)` per decision 6; `toLocalInput(iso)` → `YYYY-MM-DDTHH:mm` in local time; `fromLocalInput(v)` → `new Date(v).toISOString()`, `undefined` for `''`/invalid; `timeZone()` = `Intl.DateTimeFormat().resolvedOptions().timeZone`; `useNow(ms)` = `Date.now()` re-read every `ms`.

**`UnsavedChangesGuard({ when })`**: `useBlocker({ shouldBlockFn: () => when, withResolver: true, enableBeforeUnload: () => when })`; while blocked renders `Dialog` title "Discard unsaved changes?", description "Your changes on this page haven't been saved.", `DialogFooter`: secondary "Keep editing" (`reset`), danger "Discard changes" (`proceed`).

**`ReleaseButton({ slug, sectionId, a, note?, onDone, onError })`**: `a.published` → ghost "Hide scores" (PATCH `{published:false}` immediately; status "{name}: scores hidden from students."). Else ghost (lists) or secondary (review pages, prop `variant`) "Release scores" → `Dialog` "Release scores for {name}?", description quiz "Students will see their scores, feedback and the correct answers." / assignment "Students will see their scores and feedback.", plus `note` ("2 submitted attempts aren't reviewed yet." / "3 submissions aren't graded yet.") when given; footer Cancel, primary "Release scores" (pending "Releasing…"). Status "{name}: scores released to students." `aria-label` "Release scores for {name}" / "Hide scores for {name}". Errors: `onError(\`Couldn't change ${name}: ${errorMessage(e)}\`)` shown as the page `ErrorBanner`.

## 5. Take quiz (`TakeQuizPage`, 6b)

**States** (from assessments list, `useAttempt(me)`, `useNow`): `upcoming` → intro without button, line "This quiz opens {time}."; `open` + no attempt + 0 questions → "This quiz isn't ready yet. Check back later."; `open` + no attempt → intro + primary "Start quiz"; attempt not submitted + open → **form**; attempt submitted → **results**; closed + no attempt → "This quiz closed on {time}. You didn't start it."; closed + attempt not submitted → results with "Submitting your answers…" and `refetchInterval: 3000` on the attempt until `submittedAt` arrives (the sweeper runs every 10 s).

Intro (above every state): back link, `h2` quiz name, window line, "3 questions, 10 points.", description `PlainText max-w-prose`, and for Start the line "You have one attempt. Your answers are saved as you go and submitted automatically when the quiz closes."

```
1440 (max-w-3xl column)                                390
← All quizzes                                          ← All quizzes
Week 3 check (h2)                                      Week 3 check
Opens … · Closes …                                     Opens … · Closes …
┌ sticky: (Clock) Closes in 12 min        Saved ┐      ┌ sticky: Closes in 12 min  Saved ┐
1 ┌ fieldset ─────────────────────────────────┐        fieldsets full width,
  │ Question 1 of 3, 2 points                 │        choices one per line,
  │ Which layer routes packets?  (legend)     │        44 px rows
  │ Choose one answer.                        │
  │ ( ) Transport  ( ) Network  ( ) Link      │
  └───────────────────────────────────────────┘
3 ┌ Question 3 … Your answer [_____________] ┐
[Submit quiz]                                          [Submit quiz] full width
```

**Structure**: `ol` of `li > fieldset` (`rounded border border-line bg-surface p-4 sm:p-6`). `legend` holds three spans: muted "Question {i} of {n}, {points} points", bold prompt (`whitespace-pre-wrap`; no links inside a legend), muted hint ("Choose one answer." / "Choose all that apply." / none for blanks). Choices: `label` rows `flex min-h-11 items-center gap-3` with native `input type=radio name={qid}` or `checkbox` (`accent-accent`), value = index. Blank: `FormField label="Your answer"` `inputClass`, `maxLength 1000`, `autoComplete="off"`, `spellCheck={false}`.

**Questions fetch**: `useQuestions` is enabled only once the attempt exists (a student `GET …/questions` outside the window without a submitted attempt is 409). Keys (`correct`, `answers`) arrive only when published and the attempt is submitted (P18-L1 decision 7).

**Form model**: `answers: Record<questionId, { choices?: number[]; text?: string }>` initialised from `attempt.answers`; radio sets `[i]`, checkbox toggles and sorts; a cleared text or empty choice set deletes the key (unanswered = absent). `answeredCount` = keys present.

**Autosave** (`useAutosave(save, answers)`):
- every change sets `dirty` and restarts a 1,000 ms timer; at fire, if a request is in flight, set `again = true` and wait; else `PUT …/attempts/me {answers}` with the current map. On success: if `again` or changed since sent, send again; else `Saved`. On network/5xx error: `Not saved` and retry in 5 s while dirty. On 409: stop autosave, go to the closed path below. On 400: banner "Your answers couldn't be saved. Reload the page." (unknown question id means the quiz changed).
- Responses never overwrite local answers.
- Unmount with a pending timer: send immediately (fire and forget). `beforeunload` prompt while a timer or request is pending.
- Status (right side of the sticky bar, `role="status"` `aria-atomic`): initial "Answers save automatically." (muted); `Saving…` (rendered `aria-hidden`, visible only, so screen readers hear only results); "Saved" (muted, `Check` icon); "Not saved. Retrying…" (`text-danger`, `CircleAlert`).

**Countdown** (`countdown.ts`, pure + hook):
- Source of truth: `closesAt` from the assessments list (refetched every 60 s on this page, `refetchInterval: 60_000`) and `Date.now()`; one `setInterval(1000)` in `useNow(1000)`; text derived each tick.
- `countdownText(ms)`: ≥ 24 h → "Closes {formatDateTime}"; ≥ 1 h → "Closes in 3 h 12 min"; ≥ 60 s → "Closes in {ceil(min)} min"; > 0 → "Closes in 42 s"; ≤ 0 → "Time is up". Under 5 min the line is `text-warning font-bold` with `AlarmClock` instead of `Clock` (caution; the text carries it).
- `announcement(prevMs, ms)`: returns "10 minutes left.", "5 minutes left.", "1 minute left.", "30 seconds left." when a threshold is crossed between ticks, "Time is up. Submitting your answers." at zero; rendered in an `sr-only role="status"`. The visible line is a plain `<p>` (readable, not live).
- **At zero** (once, guarded by `finishing` ref): cancel the autosave timer; `await refetch()` the assessments list; if `closesAt` moved later, continue; else `PUT {answers, submit:true}`. 200 → results. 409 → refetch attempt → results (poll as above if not yet submitted). Network error → results-pending view polling the attempt.
- Double-submit: one `finishing` ref shared by the dialog submit and the zero submit; the Submit button and dialog confirm are `disabled` while pending; the zero path is skipped when `finishing` is set.

**Submit**: primary "Submit quiz" at the end of the form (DOM after the last fieldset; full width at 390). Opens `Dialog` "Submit quiz?" description "You answered {a} of {n} questions. You can't change your answers after submitting." (all: "You answered all {n} questions. …"); `DialogFooter` secondary "Cancel", primary "Submit quiz" (pending "Submitting…"). Errors inside the dialog via `FormErrors` (`conflict` → handled as 409 path, dialog closes).

**409 copy shown to students** (API messages per spec §5; the page maps by message, falling back to `errorMessage`):

| Call | API message | Page shows |
|---|---|---|
| POST start | "not open yet" | banner "This quiz isn't open yet. It opens {time}." |
| POST start | "closed" | switches to closed state ("This quiz closed on {time}. You didn't start it.") |
| POST start | "the quiz has no questions" | "This quiz isn't ready yet. Check back later." |
| PUT save/submit | "closed; your answers as of the closing time were submitted" | results view; if local changes were unsaved: `ErrorBanner title="Your last change wasn't saved"` "The quiz closed before it reached the server. Your answers as of the closing time were submitted." |
| PUT | already submitted | results view, no banner (another tab submitted) |

**Results** (`results.tsx`; focus moves to its `h3` "Your results" with `tabIndex -1` after a submit):
- Line: "Submitted {formatDateTime(submittedAt)}" or "Submitted automatically at {formatDateTime(submittedAt)}" (e2e substring "Submitted automatically").
- Unpublished: "Your score and the correct answers appear here once staff release the scores." Questions listed with "Your answer: …" only.
- Published: `text-xl font-bold` line "Score {s} / {max}"; staff feedback `h4` "Feedback from staff" + `PlainText` (omitted when empty). ## 13. Escalations, requests, risks

**Escalations (spec changes; design assumes my recommendation unless the orchestrator rules otherwise):**

1. **Submit at zero** (spec §6 Take quiz): the spec submits with `submit:true`. If the browser clock runs slightly early, the server records a student submit ("Submitted …") not an automatic one, and a stale `closesAt` could submit early. Recommendation: at zero send a save **without** `submit`, then poll the attempt until the sweeper submits ("Submitted automatically at …"); one boolean in §5. The design keeps the spec's `submit:true` plus the refetch guard until ruled.
2. **Assignment student button "Open"** → **"View"**: "Open" sits next to the "Open" state badge. Recommendation: "View" (designed).
3. **Countdown copy**: "Closes in 12 min" / "Closes in 42 s" instead of "12:34" (a per-minute update cannot show seconds), and the live region is a threshold announcer, not the visible line (designed).
4. **Route file names** gain trailing underscores (decision 9) to be non-nested.
5. **Window format** keeps the year (`formatDateTime`).
6. **`components/unsaved-changes.tsx`** is outside Task 6's listed scope; add it (+ test, + one line in `docs/design/P6-L1.md`) to 6a. Fallback: `features/quiz/unsaved-changes.tsx`.
7. **No `assignment-dialog.tsx`**: one `WindowDialog` (decision 8); the plan's file list changes.
8. **Gradebook dialog also hides Due date** for quiz and assignment (server-derived from the close; spec §6 names only Max points).

**Requests to P18-L1 (API design) and P18-L4/P18-L5 (builders):**

- R1 **open** (not in P18-L1's `Question`): `Question.multiple: boolean` (true when the key has ≥ 2 correct choices), present for students and staff, never revealing which; P18-L4a adds it to the struct, `openapi.json` and `types.ts`. Without it the take page cannot follow spec §6 (radio vs checkbox); interim fallback is checkboxes for every choice question with "Choose all that apply.", which tells students nothing.
- R2 (answered by P18-L1: no per-row state on `Assessment`) adopted: student lists run `useQueries` over the rows with the `useAttempt(…, 'me')` / `useSubmission(…, 'me')` keys (404 = none), so the take and assignment pages reuse the cache. Ceiling: one request per row (fine to ~30 rows); upgrade is a `mine` field on the list.
- R3 `MyAssessment.kind` (additive) for the My grades deep link; without it no link.
- R4 TAs (`CanEditContent`) may `PATCH published` and create/edit/delete `quiz`/`assignment` rows (spec §4), while `manual` keeps Spec 4's instructor rule.
- R5 answered by P18-L1 (409 texts fixed): start "not open yet" / "closed" / "the quiz has no questions"; PUT "already submitted" / "closed; your answers as of the closing time were submitted"; questions PUT "questions are locked once a student has started"; submissions "not open yet" / "closed".
- R6 answered: `dueOn` on quiz/assignment → 400 "derived from closesAt", `maxPoints` on quiz → 400; §9 never sends them.
- R7 answered: submission feedback ≤ 5,000; empty choice text → `items[i].choices[j].text` "is required" (collapses to the card's choices error, §4); all points and scores are JSON numbers; question total ≤ 10,000 → `items` banner.
- R8 answered: removing the last file of an empty-text submission deletes the submission; the page refetches `submissions/me`, gets 404 and shows "Not submitted yet."

**To P18-L8 (e2e):** selectors: buttons "Start quiz", "Submit quiz", "Save review", "Release scores", "Save grade", "Upload files", "Save"; dialogs "Submit quiz?", "Release scores for {name}?"; labels "Points for question 3", "Feedback for {name}", "Your answer", "Score". For the §1 "Submitted automatically" assertion, navigate the student away before the close (escalation 1).
