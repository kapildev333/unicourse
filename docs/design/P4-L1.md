# P4-L1 design: mail outbox

Mail is written to a Postgres table inside the caller's transaction and sent after commit by a loop that runs in every API process. This removes the backlog items "send invitation mail after commit through an outbox" and "magic-link send is synchronous (timing and failure oracle)".

Today (read on `main` at `e3e0776`):

| Caller | How it sends | Problem |
|---|---|---|
| `auth.MagicLinks.Send` (`auth/magic.go`) | `Mailer.Send` after its `WithUserTx` commits, inside the HTTP request | SMTP latency and SMTP failure (500) only happen for allowed emails: a timing and failure oracle on `POST /auth/magic-link` |
| `tenant.CreateInvitation` (invitation create, staff add in `course/staff.go`, CLI) | `Mailer.Send` inside the tenant transaction | an SMTP error rolls back the invitation; SMTP latency holds the transaction open |
| `tenant.CreateInvitations` (section and roster imports, `course/import.go`) | one `Mailer.Send` per row inside the import transaction | a 50,000-row roster makes 50,000 SMTP sessions inside one transaction |
| `unicourse-admin create-university` | `captureMailer`: nothing is sent, the URL is printed (D28) | none; must stay that way |

## 0. Decisions in this design

| # | Decision | Why |
|---|---|---|
| 1 | New package `internal/outbox`; `Mailer`, `LogMailer`, `NewSMTPMailer` move there from `auth` unchanged (file move) | After this change nothing in `auth` sends mail. `auth` must import the outbox (`MagicLinks.Send` enqueues), so the outbox cannot import `auth.Mailer` (import cycle). Delivery (queue, sender, SMTP) is one concern in one package; `tenant` and `course` stop importing `auth` for mail. The interface itself is unchanged, and so is the `LogMailer` line |
| 2 | Table `outbox_mails` is a platform table outside RLS, with no `university_id` column | Magic-link mail has no university; the sender reads every university's rows, which RLS would forbid without a bypass policy; no API route reads the table. Same class as `users`, `sessions`, `magic_links`. Inserting from a tenant transaction (`app.university_id` set) is unaffected, since RLS is off on this table. A nullable `university_id` would be read by nothing (YAGNI) |
| 3 | One row per transaction while sending: `select … for update skip locked limit 1`, `Mailer.Send`, then `delete` or `update`, commit | Several processes never pick the same row; a crash mid-send rolls back and the row is retried. Delivery is at least once: a crash after the SMTP server accepted and before commit sends the mail twice |
| 4 | Sent rows are deleted at once. A row that exhausts its attempts keeps `recipient`, `subject`, `last_error`, gets `failed_at`, has `body` set to `''`, and is deleted 30 days later | Bodies hold sign-in and invitation URLs in plain text (the rest of the database holds only token hashes). Deleting after send and clearing at give-up keeps a usable token in the table only while it waits to be sent |
| 5 | `urgent` column: magic-link mail is sent before invitation mail | Otherwise a sign-in link waits behind a 50k-invitation import backlog. FIFO within each class |
| 6 | Wake-up: `Sender.Wake()` (buffered channel of 1, non-blocking send) is called by `MagicLinks.Send` after its commit. Invitations are not nudged and wait for the poll (5 s) | The brief asks for wake-up on the sign-in path only. `tenant.Wrap` has no post-commit hook, and nudging on every tenant request is waste |
| 7 | `CreateInvitation` takes an `enqueue` function in place of the `Mailer` parameter. The API passes `outbox.Enqueue`; the CLI passes a capturing function | D28: the CLI never sends mail. If the CLI enqueued, any running API process would mail the admin. The function parameter keeps the CLI's atomicity test (a failing enqueuer leaves no university). `CreateInvitations` has API callers only, so it calls `outbox.Enqueue` directly and loses its mailer parameter |
| 8 | `Enqueue` is variadic and inserts with one `unnest` statement | A 50k roster import is one insert, not 50k round trips |
| 9 | `/readyz` is unchanged (database ping only). A stuck outbox shows in the log (§5) | Readiness is per process, but the outbox is shared. A dead SMTP provider would mark every process unready at once and take down sign-in for people who already have sessions, the admin UI and imports, all of which still work |
| 10 | No new environment variables. The knobs are `Sender` fields with defaults set in `NewSender`: poll 5 s, first retry 30 s doubling to at most 1 h, 8 attempts (about 64 min in total) | No operator has asked to change them. Tests set the fields directly. Add `UNICOURSE_MAIL_*` when one does |

## 1. Migration `apps/api/migrations/0003_mail_outbox.sql`

`0002` belongs to lane P5-L1 (section meetings). `pg.Migrate` applies every unapplied file in name order, so this file works whichever lane lands first: the two migrations share nothing.

```sql
-- Outgoing mail. Written inside the caller's transaction (outbox.Enqueue), sent after commit by
-- outbox.Sender in every API process. Platform table outside row level security, like users,
-- sessions and magic_links: sign-in mail has no university, the sender reads all rows, and no API
-- route reads it. body holds sign-in and invitation URLs in plain text, so a row is deleted once
-- sent and its body is cleared when the sender gives up (failed_at set).
create table outbox_mails (
  id uuid primary key default gen_random_uuid(),
  recipient text not null,
  subject text not null,
  body text not null,
  urgent boolean not null default false,
  attempts integer not null default 0,
  next_attempt_at timestamptz not null default now(),
  last_error text,
  failed_at timestamptz,
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now()
);
create index on outbox_mails (urgent desc, next_attempt_at, id) where failed_at is null;
create index on outbox_mails (failed_at) where failed_at is not null;
create trigger outbox_mails_set_updated_at before update on outbox_mails for each row execute function set_updated_at();
```

`testdb.truncate` already truncates every public table, so no test-helper change is needed.

```go
// Package outbox stores outgoing mail in the caller's transaction and sends it after commit.
package outbox

// Mail is one plain-text message. Urgent mail (sign-in links) is sent before other mail.
type Mail struct {
	To, Subject, Text string
	Urgent            bool
}

// Enqueue stores mails in tx with one statement; nothing is sent unless tx commits. No mails is a no-op.
func Enqueue(ctx context.Context, tx *sql.Tx, mails ...Mail) error

// Sender delivers outbox_mails through Mailer. Any number of Senders (processes) may run against one
// database: each row is claimed with FOR UPDATE SKIP LOCKED for the length of its send.
type Sender struct {
	DB          *sql.DB
	Mailer      Mailer
	Log         *slog.Logger
	Poll        time.Duration // fallback when no Wake arrives
	Backoff     time.Duration // delay after the first failure, doubled per attempt, capped at 1h; 0 retries at once (tests)
	MaxAttempts int           // the attempt that reaches this count gives up
	wake        chan struct{}
}

// NewSender sets the defaults: Poll 5s, Backoff 30s, MaxAttempts 8.
func NewSender(db *sql.DB, m Mailer, log *slog.Logger) *Sender

// Wake nudges Run to drain now. Non-blocking, safe from any goroutine; call it after commit.
func (s *Sender) Wake()

// Run drains, then waits for Wake, the poll tick or the hourly housekeeping tick, until ctx is done.
// It runs housekeeping once at start (processes restarted more often than hourly must still prune).
func (s *Sender) Run(ctx context.Context)

// Drain sends due mail, one transaction per mail, until none is due. It returns the first database
// error, or ctx.Err() when cancelled mid-send (that send is rolled back and is not counted as an attempt).
func (s *Sender) Drain(ctx context.Context) error

func (s *Sender) sendOne(ctx context.Context) (claimed bool, err error) // unexported
func (s *Sender) housekeep(ctx context.Context) error                   // unexported
```

### 2.1 SQL, exactly

Enqueue (pgx encodes `[]string` and `[]bool` as arrays; `CreateInvitations` already passes `[]string` this way):
```sql
insert into outbox_mails (recipient, subject, body, urgent)
select * from unnest($1::text[], $2::text[], $3::text[], $4::bool[])
```

`sendOne`, inside `pg.WithPlatformTx(ctx, s.DB, …)`:
```sql
-- claim
select id, recipient, subject, body, attempts from outbox_mails
where failed_at is null and next_attempt_at <= now()
order by urgent desc, next_attempt_at, id
limit 1 for update skip locked
```
- `sql.ErrNoRows`: return `(false, nil)`.
- `err := s.Mailer.Send(ctx, recipient, subject, body)`.
- If `ctx.Err() != nil`, return it. The closure's error rolls back, so the row is untouched and has no attempt counted.
- On success: `delete from outbox_mails where id = $1`.
- On failure:
```sql
update outbox_mails set
  attempts = attempts + 1,
  last_error = left($2, 1000),
  next_attempt_at = now() + least(make_interval(secs => $3::float8 * power(2::float8, attempts)), interval '1 hour'),
  failed_at = case when attempts + 1 >= $4 then now() end,
  body = case when attempts + 1 >= $4 then '' else body end
where id = $1
returning failed_at is not null
```
  `$3` is `s.Backoff.Seconds()` and `$4` is `s.MaxAttempts`. `attempts` on the right-hand side is the old value. Log the outcome:
  - `failed_at` set: `s.Log.Error("mail gave up", "id", id, "attempts", n, "err", err)`.
  - otherwise: `s.Log.Warn("mail send failed", "id", id, "attempt", n, "err", err)`.
- Commit and return `(true, nil)`.

The backoff is computed in SQL with the database clock (D30), so tests can check `next_attempt_at > now()` in SQL.

`housekeep`:
```sql
delete from outbox_mails where failed_at < now() - interval '30 days';
select count(*), coalesce(extract(epoch from now() - min(created_at)), 0)::bigint
from outbox_mails where failed_at is null and created_at < now() - interval '15 minutes';
```
If the count is greater than 0: `s.Log.Warn("mail outbox backlog", "pending", n, "oldestSeconds", age)`.

`Run`:
```go
s.housekeep → log Error("mail outbox", "err", err) on error (unless ctx done)
poll := time.NewTicker(s.Poll); hk := time.NewTicker(time.Hour) (both stopped on return)
for {
	if err := s.Drain(ctx); err != nil && ctx.Err() == nil { s.Log.Error("mail outbox", "err", err) }
	select { case <-ctx.Done(): return; case <-s.wake: ; case <-poll.C: ; case <-hk.C: housekeep (log as above) }
}
```

Logs never carry `body` (sign-in URLs). `LogMailer` is the deliberate exception: it is the dev mailer, and the e2e test reads that line.

## 4. Behaviour after the change

- `POST /auth/magic-link`: the allowed path does two inserts (`magic_links`, `outbox_mails`); the other path does none. No SMTP latency or failure reaches the response.
- Invitation create, staff add and imports: one more insert, or one `unnest` insert for an import. An SMTP outage no longer fails or rolls back an invitation. The mail goes out within about 5 s of commit, or later with retries.
- Two API processes: each runs a `Sender`. Rows are split by SKIP LOCKED, and each process wakes itself for its own magic links.

## 5. What an operator sees when mail is stuck

| Situation | Signal |
|---|---|
| SMTP rejects or times out | `WARN mail send failed id attempt err` per attempt. After 8 attempts (about 64 min): `ERROR mail gave up id attempts err`. The row stays with `failed_at` and `last_error` for 30 days |
| Database errors while claiming | `ERROR mail outbox err`, at most once per poll (5 s) per process |
| Backlog older than 15 min that has not given up (slow SMTP, huge import, retries) | hourly `WARN mail outbox backlog pending oldestSeconds` per process |
| `/readyz` | unchanged (decision 9) |

Diagnosis query (for the README or runbook, worker b's choice): `select recipient, subject, attempts, last_error, failed_at from outbox_mails order by created_at`.

## 8. Simplifications and their ceilings

| Simplification | Ceiling | Upgrade path |
|---|---|---|
| One send at a time per process, with a new SMTP session per mail (existing `smtpMailer`) | About 1-2 mails/s per process with real SMTP: a 50k import takes hours to deliver. Sign-in links are unaffected because they are urgent | Run k `Run` goroutines (safe by construction, decision 3), or switch to a provider HTTP API |
| At-least-once delivery | A crash between the SMTP accept and the commit duplicates one mail | Accept it; idempotency keys only exist with provider APIs |
| Only magic links wake the sender | Invitation mail waits up to `Poll` (5 s) | Call `Wake` after commit in `tenant.Wrap` |
| No expiry check before sending | A sign-in link retried after 15 min is already dead when it arrives | Add `expires_at` and skip expired rows |
| Fixed knobs, no env vars | Changing poll, backoff or attempts needs a code change | `UNICOURSE_MAIL_*` in `config` |
| Residual timing difference on `POST /auth/magic-link` | Two inserts versus none: sub-millisecond, but measurable in principle | Do equal dummy work on the not-allowed path |
| Each process runs housekeeping hourly | Redundant deletes across processes, which are harmless | Keep as is |
