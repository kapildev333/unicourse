# Platform Core and Course Staffing — Implementation Plan

> **For agentic workers:** This plan is executed by `/orchestrate` (orchestrator + `designer` → `worker` → `reviewer` lanes, one branch and worktree per lane). Each task below is one lane. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A department at one university can sign in, create terms, courses and sections, staff them with instructors and TAs, import rosters, and every assigned person sees their sections — with other universities' data provably invisible.

**Architecture:** Go `net/http` API over PostgreSQL with row-level security per university; React + Vite web app talking to it through a client generated from a hand-maintained `openapi.json`. The contract is written first so API and web lanes run in parallel.

**Tech Stack:** Go 1.27 standard library + `pgx/v5`, `x/oauth2`, `go-oidc/v3`, `x/crypto`; PostgreSQL 16; React 18, Vite, TypeScript strict, TanStack Router + Query, Tailwind, Vitest, Playwright.

**Spec:** `docs/specs/2026-10-05-platform-core-and-staffing.md` — every task cites the sections it implements; executors read both.

## Global Constraints

- Go: `net/http` + `http.ServeMux` method/wildcard patterns; no framework, router, ORM, DI container or code generator (spec §3).
- Allowed Go modules: `github.com/jackc/pgx/v5`, `golang.org/x/oauth2`, `github.com/coreos/go-oidc/v3`, `golang.org/x/crypto`. Anything else is a PLAN.md decision (§3).
- Tests: `testing` package only; no testify. Integration tests hit real Postgres at `UNICOURSE_TEST_DATABASE_URL` (§3, §12).
- IDs are UUID strings generated by Postgres `gen_random_uuid()`; Go holds them as `string` (stdlib has no uuid type). Handlers validate path ids with `^[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}$`.
- Naming: the table in `CLAUDE.md` is binding (kebab-case dirs, one-word Go packages, snake_case plural tables, `/api/v1/<plural-noun>`, camelCase JSON identical in Go tags and TS, `UNICOURSE_` env vars, one word per domain concept).
- Every tenant-scoped table has `university_id` and an RLS policy; all tenant queries run inside `pg.WithTx` (§4).
- Error envelope `{ "error": { "code", "message", "details": [{ "field", "message" }] } }` on every non-2xx; codes `unauthenticated`, `forbidden`, `not_found`, `conflict`, `validation_failed`, `rate_limited`, `internal` (§6).
- Lists paginate with `?limit=` (default 50, max 200) and `?cursor=`; response `{ "items", "nextCursor" }` (§6).
- Gates for every lane: `gofmt -l`, `go vet ./...`, `go test ./... -count=1`; web: `npm run lint`, `npm run typecheck`, `npm test -- --run`, `npm run build` (§12, `.github/workflows/ci.yml`).
- Git: lanes commit on `lane/<LANE-ID>-<slug>` in `.worktrees/<LANE-ID>`, never push; the orchestrator opens the PR (`CLAUDE.md`).

## Review Focus

Inputs the spec implies but no feature test would naturally cover; each has a pinned test in the owning task.

1. **Email case and whitespace** — `  Alice@CS.Example.EDU ` must match an invitation for `alice@cs.example.edu` and never create a second user. Pinned in Task 5 (auth) and Task 9 (csvimport).
2. **A user in two universities** — the same user with memberships in A and B must see only A's sections under `/universities/a/...` even when B has sections for them too. Pinned in Task 2 (RLS) and Task 6 (tenant middleware).
3. **Cursor pagination across deletes** — deleting the row a cursor points at must not skip or repeat items. Pinned in Task 1 (`httpx` pagination uses `(created_at, id)` keyset, not offsets).
4. **CSV with BOM, CRLF, quoted commas and a trailing blank line** — all must parse; a header-only file is a valid empty import. Pinned in Task 9.
5. **Expired or reused tokens** — a magic link used twice, an invitation accepted after 14 days, a session past 30 days: each must 401/400 with the right code and never partially apply. Pinned in Task 5.
