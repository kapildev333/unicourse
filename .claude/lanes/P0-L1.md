## Found
- `httpx.WithUserID(ctx, id)` / `WithUniversityID(ctx, id)` return nothing: they mutate a per-request struct that LogMiddleware puts in ctx (no-op if absent). Call them from auth / tenant middleware; do not reassign ctx.
- `WithRequestID` is now unexported; use `httpx.RequestID(ctx)` to read.
- `internal/pg/errors.go` holds only `ErrNotFound`, `ErrConflict`; P0-L2 extends it. `pg` must never import `httpx`.
- Middleware order is RequestID -> Log -> Recover (Recover innermost). A panic yields the 500 envelope with `X-Request-Id`, one request log line with status 500 and the same request id. `Recover` re-panics `http.ErrAbortHandler`.
- `main.go` has `newHandler(logger)`: `GET /healthz`, `GET /readyz` (503 `{"status":"unavailable"}` until P0-L2 wires db) and a catch-all `/` returning the JSON `not_found` envelope (so POST /healthz and unknown /api/v1 paths get the envelope). Later lanes register routes on this mux.
- Shutdown: main waits for `srv.Shutdown` (10 s) so in-flight requests drain.
- `DecodeJSON`: trailing data, empty body (`body is required`) and type errors (`invalid value`, field = JSON field) are validation_failed. Request ids from clients must match `^[A-Za-z0-9-]{1,64}$`. Cursor ids must be UUIDs; `limit<0` is a validation error.
- README.md in apps/api documents run steps and env vars.
- Validation of body-decoding failures that are not unknown-field use field `body`.
- Compose: superuser `postgres`/`postgres`; app role `unicourse`/`unicourse` (NOSUPERUSER NOBYPASSRLS); DBs `unicourse`, `unicourse_test`. initdb.sql only runs on a fresh volume.
