## Found
- Answer to P0-L4's request: adopted the contract shapes as-is (start `{slug?, email?, next?}` exactly one of slug/email; magic-link `{email, next?}` → 202; callbacks always 302 with `?error=validation_failed|forbidden|unauthenticated|no_membership`; sign-out public 204; `/me` items `{university:{id,slug,name}, role, departmentIds}`; cookie `unicourse_session`). No contract change requested.
- Cross-university reads (SignIn accepting invitations, GET /me) use three *SELECT-only* permissive policies keyed on `app.user_id` / `app.email`, set only by a new `pg.WithUserTx` that never sets `app.university_id`. `pg.WithTx` must never set `app.user_id` or `app.email`. Writes stay under `tenant_isolation` only.
- Gotcha (affects every policy): after any `set_config('app.university_id', ..., true)` on a pooled connection, `current_setting('app.university_id', true)` returns `''` (not NULL) in later transactions and `''::uuid` raises 22P02. Every policy must wrap it in `nullif(..., '')`.
- `auth.NormalizeEmail` is the only email normaliser (Review Focus 1); tenant/csvimport must import it. `auth.InvitationURL(baseURL, token, email)` = `{BaseURL}/invite/{token}?email=...`.
- `auth.SignIn(ctx, db, email, displayName)` takes `*sql.DB`, not a tx (plan deviation; it opens its own WithUserTx).
- LogMailer line: slog `msg="mail"` with keys `to`, `subject`, `text`; the URL is the first `https?://\S+` in `text` (tests and e2e parse this).
