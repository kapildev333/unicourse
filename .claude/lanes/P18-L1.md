  - Every points/score value (`grading[*].points`, `score`, attempt and submission) is a JSON number (json.Number, 2 decimals, D68), not the string "2.00" of spec §3's example.
  - Student answer keys (`choices[].correct`, `answers`) appear only when the quiz is published AND the student's own attempt is submitted (spec said "published"; tightened so keys never show mid-attempt). Results (`grading`, `score`, `feedback`) appear when published.
  - Hidden fields are omitted, never null. `Question.answers` is `[]` for a choice question (staff); `Question.choices` is `[]` for a blank.

  - No per-row "mine" state on Assessment: student lists read `GET …/attempts/me` / `GET …/submissions/me` per row (404 = not started).
  - 409 texts: start "not open yet" / "closed" / "the quiz has no questions"; PUT attempts/me "already submitted" / "closed; your answers as of the closing time were submitted"; questions PUT "questions are locked once a student has started"; review "the attempt is not submitted"; submissions "not open yet" / "closed"; students GET questions outside the window "not open yet" / "closed".
  - New 400s: quiz `maxPoints` given → `maxPoints` "derived from the questions"; `dueOn` on quiz/assignment → "derived from closesAt"; window on manual → "only for quizzes and assignments"; `kind` in PATCH → `kind` "unknown field"; questions total > 10000 → `items` "total points must be at most 10000"; 11th file → `file` "a submission holds at most 10 files"; empty submission → `body` "a submission needs text or a file".
  - The gradebook dialog must not send `maxPoints` or `dueOn` when PATCHing a quiz, and TAs can create/edit/delete quizzes and assignments but still not manual assessments.
